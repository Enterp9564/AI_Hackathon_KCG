## 유지할 사용자 결정

- 상황실장은 짧게 범위를 해석해 요원에게 먼저 배정한다. 요원 보고·정보요구를 모아 핵심 제안과 질문을 전달한다.
- 독립 임무는 실제 병렬 처리한다. 배정 이유·상태·보고·근거를 보여주고 내부 추론 원문·가짜 진행률을 만들지 않는다.
- 모델은 `gpt-6-luna`, 모든 역할 `medium`. 화면에서 모델·추론 수준을 숨기되 LIVE/DEMO는 구별한다.
- 핵심 제안·질문은 1~2개 중심이고 이유를 짧게 붙인다. 접기만으로 의미 기반 우선순위 선정 완료를 주장하지 않는다.
- 세션 기억·원문·정정 이력을 격리·보존한다. 삭제 확인과 진행 중 보호를 유지한다.
- 매뉴얼·사용자 제공 동해 세력을 사용하되 등록 목록을 실시간 가용성·출동 완료로 취급하지 않는다.
- Enter 전송·Shift+Enter 줄바꿈, 즉시 접수·상단 진행·고정 상황판·복귀 동선을 유지한다.

## 작업 경계

현재 스택은 Python HTTP·SQLite·HTML/CSS/JavaScript다. 관련 없는 재작성·새 프레임워크 도입을 피한다. 앱 내부 병렬 요원 요구를 개발 보조 에이전트 생성 요청으로 해석하지 않는다.

키·환경변수 값을 출력하거나 문서·커밋·배포물에 넣지 않는다. `prototype/.secrets/`, `prototype/runtime/`의 기존 사용자 자료를 임의로 삭제하지 않는다. 발표 설명 애니메이션과 실제 앱 실행 증거를 구별한다.

변경 위험에 맞춰 검증하고 단위/HTTP/브라우저/LIVE 결과를 나눠 보고한다. 실행하지 않은 시험은 통과로 기록하지 않는다. 명령은 README를 따른다. 과거 실패·수정·재실행 기록을 덮어쓰지 않는다.

변경 후 13과 PROGRESS 및 관련 요구 문서를 갱신한다. 승인된 범위는 불필요한 재확인 없이 진행하며 문서 현행화 요청을 앱 기능 변경으로 확장하지 않는다.
