# AI 종합상황실 발표자료 설계서

> 2026-09-26 현행화: 현재 구현·검증·남은 과제는 [13번 인수인계 문서](13_현재상태_요구사항_인수인계.md)를 기준으로 한다. 본문의 목표·수용 기준과 날짜별 기록을 구현 완료로 해석하지 않는다.

> 통합 개정본 v2 · 공식 10분 표기 대응 + 5분 압축본
> 이 문서는 발표 설계와 대본 초안이다. 실제 PPT·영상은 아직 제작하지 않았다.

## 1. 발표시간의 근거

제공 커리큘럼에는 10/1 13:30부터 15:30 최종 발표, 팀별 10분이라고 적혀 있다. 사용자 제공 약 30명·20팀과 시간표 사이의 차이는 미확인이다. 5분을 공식 시간으로 단정하지 않는다.

같은 사건과 자료로 10분 구성과 5분 압축본을 준비한다. 10분에 질의응답이 포함되는지는 현장 확인 사항이다. 포함된다면 설명을 줄여 질문 시간을 확보한다.

## 2. 첫 1분의 목표

첫 화면에서 ‘상황실장과 대화하면 요원들이 실제로 조사하고 보고한다’는 동작을 보여준다. 긴 기술 소개보다 짧은 사건 제시 후 채팅으로 바로 진입한다.

첫 문장 초안:
> 사고 대응에서는 신고를 정리하는 동안 명부를 확인하고, 기상을 조회하고, 대응지침도 찾아야 합니다. 저희는 이 업무를 상황실장과 전문요원이 나눠 처리하는 AI 종합상황실로 구성했습니다.

## 3. 공통 슬라이드 6장

| 장 | 화면 내용 | 증거 또는 메시지 |
|---|---|---|
| 1. 상황 접수 | 가상 사고 한 문장·채팅 진입 | 실제 업무문제 |
| 2. 움직이는 상황실 | 앱 또는 조직도·지시/보고 | 필요한 전문성에 추론 집중 · 선택 배정·병렬 검토·종합 |
| 3. 새로운 명부 | 5명/7명 불일치, 사용자 확인, 7=4+3 | 정보 변화에 따른 재지시 |
| 4. 근거 있는 대응 | RAG 구절·기상 출처·MCP·검증 | 교육기술의 실제 기여 |
| 5. 비교와 검증 | 동일 조건 모델 비교·오류 사례 | 측정된 결과만 기재 |
| 6. 효과와 한계 | 업무 적용·확장 조건·최종 메시지 | 인간 판단 지원 |

2·3은 앱 시연을 중심으로 진행하고 슬라이드는 장애 시 대체 화면으로 쓴다. 특정 기능이 미완성이면 표기와 대본을 실제 상태에 맞춘다.

### 3.1 왜 여러 AI 에이전트인가 — 필수 메시지

**필요한 순간, 필요한 전문성에 추론을 집중한다.**

사용자는 하나의 사건 대화에서 상황실장에게 요청한다. 내부에서는 역할별 작업 맥락을 분리하고, 상황실장이 해당 시점에 필요한 요원만 선택한다. 각 요원은 공통 상황 버전·필수 제약과 자신의 임무에 필요한 자료·지침·도구를 받아 집중적으로 검토한다. 독립 조사는 병렬로 처리하고 보고를 종합·검증해 하나의 답변으로 돌려준다.

| 설계 선택 | 줄이려는 낭비·기대효과 | 시연에서 보여줄 것 |
|---|---|---|
| 필요한 요원만 호출 | 단순 요청에 불필요한 전원 호출 방지 | 배정 이유와 미배정 요원 |
| 역할별 맥락·자료·도구 | 무관한 자료 처리와 중복 탐색을 줄이고 검토 범위에 집중 | 정보: 명부·기상 / 수색구조: 지침 / 자원지원: 가용표 |
| 독립 임무 병렬 실행 | 독립 조사들의 대기시간 중첩 | 실제 실행 구간과 먼저 도착한 보고 |
| 영향받는 임무만 재검토 | 변경과 무관한 작업의 반복 최소화 | 인원 정정의 영향 분석과 선택적 보완 지시 |
| 상황실장 종합·검증 | 관점별 결과와 누락·충돌을 모아 사용자 선택 지원 | 사용 보고·미확인사항·최종 답변 연결 |

**발표 대본 — 약 25초 목표, 리허설로 확인**
> 필요한 순간, 필요한 전문성에 추론을 집중하는 구조입니다. 사용자는 하나의 대화를 이어가고, 상황실장은 그때 필요한 요원만 선택합니다. 요원들은 각자의 지침·자료·도구로 집중 검토하고, 독립 작업은 동시에 수행합니다. 바뀐 정보에 영향받는 임무만 재검토해 불필요한 반복을 줄이는 것이 목표입니다. 보고는 상황실장이 종합해 사용자의 판단을 돕습니다.

**용어와 주장 범위:** ‘하나의 대화’는 사용자 경험과 공유 사건 기록을 뜻한다. 모든 요원이 하나의 LLM 세션·컨텍스트를 공유한다는 뜻은 아니다. ‘전문화’는 현재 설계의 역할 프롬프트·RAG 자료·전용 도구 구성이다. 별도 전문가 모델 학습·미세조정은 수행하지 않았으므로 ‘전문가 학습이 완료된 AI’라고 말하지 않는다.

추론 자원의 선택과 집중은 설계 원칙이며 총 토큰·비용 절감과 판단 품질 향상은 검증할 가설이다. 배정·보고·종합·검증 호출의 추가 비용도 포함해 단일 에이전트, 전원 호출, 선택 호출을 같은 사건·모델·자료·도구 접근·평가기준으로 비교한다. 총 입력/출력 토큰, 비용, 도구 호출, 최초/최종 보고 시간, 누락·모순·정정 정확도를 기록한다. API가 제공하는 경우에만 추론 토큰을 별도 기록하며 내부 연산량을 임의 추정하지 않는다. 단일 에이전트도 도구 병렬 호출이 가능하므로 병렬 속도를 다중 에이전트만의 고유 장점으로 주장하지 않는다.

외부 기술 참고: [Anthropic의 다중 에이전트 연구 시스템](https://www.anthropic.com/engineering/multi-agent-research-system)은 역할별 맥락·도구의 분리, 병렬 조사, 과제 복잡도에 맞춘 자원 배분과 함께 추가 토큰 비용을 설명한다. [Building effective agents](https://www.anthropic.com/engineering/building-effective-agents)는 라우팅·병렬화·조정자 구조의 적용 조건을 설명한다. 이는 설계 참고이며 우리 앱의 성능 증거가 아니다.

| 0:00부터 0:40 | 문제와 가상 사건 제시 |

| 5:00부터 6:30 | Agent·RAG·MCP·DB 책임 설명 |
| 6:30부터 7:30 | 모델 비교와 신뢰성 시험 |
| 7:30부터 8:30 | 업무효과·한계·다른 분야 확장 |
| 8:30부터 9:30 | 실제 지연 여유 또는 근거 상세 |

9분 30초까지 반드시 말로 채우려 하지 않는다. 질의응답 포함 시 앱 시연·설명을 압축하고 주최 측 시간 배분을 따른다.

## 5. 5분 압축 구성안

| 구간 | 내용 |
|---|---|
| 0:00부터 0:30 | 문제와 제품 한 문장 |
| 0:30부터 3:10 | 데모 2분 40초: 최초 분석과 명부 정정 |
| 3:10부터 4:00 | 근거 검색·기상·MCP 적용 |

구현을 자세히 설명하는 시간부터 줄인다. 사용자 확인과 재지시 장면은 유지한다. 응답이 늦으면 자동 성공 연출 대신 명시적인 녹화/재생으로 전환한다.

## 6. 공통 대본 초안

아래는 목표 기능이 실제로 작동할 때 사용하는 초안이다. 완료 전에는 ‘구현했다’는 표현을 대외 사용하지 않는다.

**사건 접수**
> 이 사건은 가상 훈련입니다. 최초 신고는 승선원 5명, 구조 보고 4명, 소재 미확인 1명입니다. 사용자는 별도 양식 대신 상황실장에게 채팅으로 전달합니다.

**임무와 조사**
> 상황실장이 필요한 임무를 나눕니다. 정보요원은 제공자료와 기상을 확인하고, 수색구조요원은 지침을 찾으며, 자원지원요원은 시연용 가용자원을 검토합니다. 화살표를 선택하면 실제 지시와 보고를 볼 수 있습니다.

**기상과 근거**
> 기상은 사건 위치로 조회한 자료이며 출처와 기준시각, 예측자료 여부를 함께 표시합니다. 검색한 지침은 어느 구절을 근거로 썼는지 연결합니다.

**새 자료**
> 이제 명부를 추가하겠습니다. 명부에는 7명이 있지만 최초 신고는 5명이었습니다. 시스템은 숫자를 조용히 덮어쓰지 않고 실제 탑승명부인지 확인합니다.

**사용자 정정과 재지시**
> 사용자가 7명이 맞다고 정정했습니다. 총원 7명, 구조 보고 4명, 소재 미확인 3명으로 갱신하고 관련 요원에게 보완 지시를 내립니다. 이전 보고와 계획, 바뀐 이유도 남습니다.

**검증**
> 인원 합계와 중복은 프로그램이 검사하고, 검증요원은 근거 누락과 보고 간 모순을 점검합니다. 검증을 통과해도 실제 조치의 최종 판단은 사람에게 있습니다.

**마무리**
> 저희가 보여드린 것은 상황 접수부터 조사, 보고, 정정, 계획 갱신까지 이어지는 AI 조직입니다. 사용자는 상황실장과 소통하고, 요원들의 작업과 근거를 확인하면서 판단할 수 있습니다.

## 7. 교육 기술 설명과 실제 증거

| 요소 | 한 문장 설명 | 제시할 증거 |
|---|---|---|
| NLP·Agent | 자연어에서 상황과 필요한 임무를 만든다 | 원문·임무·보고 연결 |
| 임베딩·벡터DB·RAG | 관련 문서 구절을 찾아 생성에 사용한다 | 질의·검색 구절·반영 조치 |
| MCP | 정해진 프로토콜로 기상 조회 도구를 호출한다 | 실제 요청·응답 |
| 멀티모델 비교 | 같은 입력과 기준으로 두 모델을 비교한다 | 모델명·조건·응답시간·오류 |
| 신뢰성 검증 | 규칙 검사와 검증요원으로 오류를 찾는다 | 잘못된 입력/초안과 지적 결과 |
| 상황 관리 | 이전 사실을 보존하며 최신 상황을 갱신한다 | 버전·변경 이유·복원 |

CNN·Word2Vec는 배운 기초 개념을 이해하고 설명한다. 구현하지 않은 알고리즘을 기술표에 사용 완료로 넣지 않는다. 같은 모델의 역할 분리는 멀티모델 비교가 아니다. 일반 함수 호출은 MCP 사용 증거가 아니다.

## 8. 효과와 한계 표현

‘업무시간 80% 절감’, ‘15초 처리’, ‘오류 0건’처럼 측정하지 않은 수치를 쓰지 않는다. 기대효과는 정보 재입력 감소, 역할별 조사 가시화, 정정 이력 추적으로 설명한다. 수치가 필요하면 같은 사건·자료·평가기준으로 비교하고 표본 수·조건을 붙인다.

현재 범위는 훈련용 개념검증이다. 실시간 선박 위치와 실제 구조자원은 연결하지 않는다. 다른 재난 적용에는 도메인 자료·도구·검증이 필요하다.

현재 앱은 모든 역할에 medium을 적용하고 모델 표기를 운영 화면에서 숨긴다. 여러 세션과 독립 기억·조건 비교 흐름은 부분 구현됐으며 13번 문서에서 검증 범위를 확인한다. 발표 HTML은 최신 앱의 실행 증거를 자동 반영하지 않는다.

## 9. 예상 질문

**MMSI나 내부 시스템을 연결했나요?**  
초기 범위에서 제외했습니다. 외부 데이터는 기상만 조회하며 선박정보와 사고 위치는 사용자 제공자료를 사용합니다.

**실시간 기상인가요?**  
현재 수동 Forecast 조회 코드가 있으며 실제 응답 성공의 추가 검증이 필요합니다. 표시 시 모델 기반 자료와 현장 관측을 구별하고 기준시각·조회시각을 함께 보여줍니다.

**왜 여러 요원인가요?**  
필요한 시점에 필요한 전문 역할만 선택하고, 역할별 자료·도구·작업 맥락으로 집중 검토하기 위해서입니다. 독립 작업은 병렬로 진행하고, 새 정보에 영향받는 임무만 재검토해 불필요한 반복을 줄이는 것이 목표입니다. 상황실장이 보고를 종합·검증해 사용자의 선택을 돕습니다. 전문화는 역할·자료·도구 구성이며 별도 학습 완료를 뜻하지 않습니다. 총비용·속도·품질 개선은 같은 조건의 단일/전원/선택 호출 비교로 검증합니다.

**MCP를 실제로 썼나요?**  
현재는 로컬 함수 경로이며 MCP는 미구현입니다. 구현 후 프로토콜 요청·응답 로그를 확보해야 완료라고 설명할 수 있습니다.

**명부를 벡터DB로 세나요?**  
아닙니다. 현재 CSV는 전체 행의 ID 중복과 구조 상태를 검사합니다. 문서 근거는 단어 기반으로 찾으며 벡터DB는 향후 지침 검색 계획입니다.

**검증요원도 틀리지 않나요?**  
그럴 수 있습니다. 명확한 합계·버전 규칙은 코드로 검사하고 AI 검증은 보조 검토로 둡니다.
