## 범위와 현재 결과

## 결과 검증과 해석

### 확인된 원인과 수정

진단만 추가한 동일 설정 재시험은59.017초에 다시 실패했다. 검증 호출의 응답은 status=incomplete, incomplete_reason=max_output_tokens, output_tokens=2400, reasoning_tokens=2400이었다. 즉 한도 전체를 추론에 사용해 검증 보고 생성 전에 중단됐다. 최초57.558초 실패는 상세 이유가 없어 직접 확정할 수 없지만 같은 설정에서 같은 실패를 재현해 원인을 확인했다.

OpenAI Responses의 max_output_tokens는 추론과 표시할 응답을 함께 제한한다. [OpenAI 공식 설명](https://developers.openai.com/api/docs/guides/reasoning#allocating-space-for-reasoning). 검증요원의 짧은 지침·medium 추론을 유지하고 OpenAI 어댑터에서만 상한을2400→6000으로 복구했다. 로컬 Qwen의 추론 비활성 요청·검증 상한2400은 유지한다. 최대 허용량을 늘린 것이며 매번6000토큰 생성을 지시하는 것은 아니다. 입력 축소 작업은 이번에 수행하지 않았다.

실패 진단에는 허용한 status·reason과 정수 토큰 집계만 남긴다. 부분 응답·추론 원문·키·임의 오류 내용은 기록하지 않는다. max_output_tokens일 때 화면에 표시되는 오류도 출력 한도 도달로 구별한다. 자동 재시도나 검증 우회는 추가하지 않았다.

한도만 바꾼 동일 검증 입력 단독 시험은32.791초 후 미제공 근거 ID 인용으로 서버 검증에서 실패했다. 이 단독 스크립트는 실패 시 응답/metadata를 보존하지 않아 잘못된 ID와 사용량은 회수할 수 없다. 다음 전체 시험은 한도 수정만으로82.577초에 완료했지만, 단독 시험에서 발견한 인용 오류를 방치하지 않도록 OpenAI 검증 출력에 strict JSON Schema를 적용했다. evidence_ids는 해당 호출에 제공한 근거 ID만 enum으로 허용하고, 근거가 없으면 빈 배열만 허용한다. findings/uncertainties는각3개, 질문2개, 출동안 빈 배열을 제한한다. 서버의 기존 의미·근거 검증도 유지한다.
