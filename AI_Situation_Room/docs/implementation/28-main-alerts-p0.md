# 28 · 주요 알림 P0: 상시 요약과 여러 환자 점검

> 후속 구현: [29 주요 알림 정렬·선체경사 경고](29-alert-sorting-vessel.md). 기본 목록 순서는 최신순으로 변경됐다. 아래는 P0 당시 기록이다.

2026-09-29 · [개선안](../improvements/04-main-alerts.md) · Python HTTP/SQLite와 기존 JavaScript 유지

## 구현 범위

- 새 알림 버튼에 은은한 붉은 강조와 `새 알림` 문구를 유지한다. 버튼을 눌러 패널이 정상적으로 열리면 그때까지 수신한 알림의 강조만 멈춘다.
- 미열람 건수는 그대로 남는다. 목록·검색·필터·버튼 클릭으로 읽음이나 AI 검토를 실행하지 않는다. 상세 열기는 기존 판본별 읽음 API를 사용한다.
- 현재 해온 사건의 최신 판정/즉시 확인/30분 분류/기타·분석 확인/미열람 요약을 공통 영역에 고정한다. 패널 안에도 요약을 표시한다. 링크온 원본 화면과 사건 선택이 자동으로 일치한다는 뜻은 아니다.
- 비모달 패널에서 여러 환자를 비교하고 옆에서 상세를 연다. 넓게 보기, 전체/미열람/즉시 확인/판정 후 기록 변경 필터, 이름·식별자·요약 검색을 제공한다.
- 수신 시각과 분석 기준/완료 시각을 구분한다. 위치·관리 상태는 현재 알림 API에 없으므로 확인 불가로 표시한다. OBSERVE를 정상 판정으로 바꾸지 않는다.
- 대형 화면은 고정된 해온 사건의 캐시만 조회하며 패널 열기·읽음·검토 기능을 제공하지 않는다.

## 코드와 상태

`prototype/static/patient-alerts.js`가 기존 캐시 GET과 단건 인용 흐름을 사용한다. `index.html`은 고정 요약·필터·목록/상세 영역을, `style.css`는 비모달 배치·폭·모바일 전환·강조 효과를 정의한다. 원격 DB의 3초 조회는 변경하지 않았다.

강조 상태는 `haeon:patient-notice:v1` sessionStorage에 세션별 `known`, `pending`, `initialized`로 저장한다. 로컬 판본 ID만 저장하며 원문은 넣지 않는다. 첫 진입에는 미열람 판본을 강조하고, 이후 새로운 ID는 읽음과 별개로 강조한다. 클릭 직후 도착한 판본은 강조 대기에 남는다. 같은 탭 새로고침에는 인지 상태를 유지하며 새 탭은 미열람 자료를 다시 강조할 수 있다. 저장소 실패 시 메모리로 동작한다. 20개 세션, 집합별 최근 5,000개 ID로 제한하며 오래된 기록 제거 시 재강조를 허용한다. 이는 담당자 인증이나 공동 확인 이력이 아니다.

목록의 행 순서와 포커스는 환자 ID로 유지한다. 새 판본에 변경 배지를 붙이고 현재 상세는 기존 원문으로 고정한다. 판본 교체 시 상세 DOM을 재작성하지 않아 펼침/키보드 포커스를 보존한다. 기존 판본의 인용은 막고 `최신 판정 보기`로 새 내용을 열게 한다. 서버의 최신성·사건 검사도 유지한다. 사건 전환에서는 상세·필터·목록 순서를 초기화한다.

## 검증과 수정 기록

1. 최초 신규 테스트: 기존 3개 PASS, 신규 5개 FAIL. 강조가 미열람 수에 묶여 있는 기존 동작, 요약 부재, 대형 화면 조회 차단을 재현했다.
2. 구현 후 8개 PASS. 패널 열기 실패·저장소 오류·판본 교체 검사를 보강했다. 미연결 목록 안내 누락 1 FAIL을 수정했다.
3. 별도 코드 리뷰에서 판본 교체 시 상세 DOM 재작성, 행 변경 배지/포커스 연속성 문제를 확인했다. 재작성 방지 회귀를 먼저 실패시킨 후 수정했다. 스크린리더 이름에도 `새 알림`을 포함했다.
4. Node 전체 테스트 파일 실행: 20개 테스트 항목 PASS. 그중 환자 알림 테스트 12개 PASS. 일부 기존 파일은 내부 복수 검사를 하나의 항목으로 보고한다.
5. 격리 Chrome + 임시 합성 데이터 서버: 1920×1080에서 8행 전체 표시, 필터/검색, 강조와 읽음 분리, 판본 교체 중 상세·펼침·포커스 보존, 오래된 인용 차단, 사건 전환, 초안 유지, 키보드, 움직임 줄이기, 대형 화면을 확인했다. 320/390/768/1024/1366/1440/1920px에서 패널 폭을 확인했다. JavaScript 오류 0, AI 호출 0.
6. 첫 브라우저 실행은 시험 코드가 존재하지 않는 `/api/monitor` POST를 호출해 실패했다. 기존 `/api/sessions/{id}/pin` 경로로 시험 코드를 수정한 뒤 통과했다. 앱 API를 새로 만들지 않았다.

`serve_patient_ui.py`는 임시 DB와 가상 환자 A~H만 생성한다. 외부 DB·LIVE 모델·실제 환자 자료를 사용하지 않는다. 브라우저 시험은 이 서버를 종료하고 스크린샷을 임시 폴더에 보관한다.

## 후속 범위

P1 선택 읽음/담당자 검토 이력, P2 승인형 일괄 AI 검토, P3 선박·현장 등 다른 종류의 알림은 미구현이다. 이 단계에서는 동작하지 않는 체크박스나 일괄 버튼을 만들지 않았다. 원격 환자의 신규 판정 종단 지연, 장시간 운용, 실제 모바일 기기·Safari의 새 패널 검증은 아직 수행하지 않았다. 기존 Python 전체는 선행 업로드 때 172개 실행/4개 skip/나머지 PASS이며, 이후 제품 Python 코드는 변경하지 않았다.

## 2026-09-29 — 클릭 전 붉은 점멸 강화

patient-notify.has-new-patients의 CSS를 1.4초 배경·테두리·광원 맥동과 2.4초 빛 이동으로 강화했다. 기존 상황실장 작업 표시와 같은 방향의 광원 이동을 붉은색으로 사용한다. 텍스트는 계속 보이며 크기나 배치를 흔들지 않는다. 클릭으로 클래스가 제거되면 점멸과 가상 요소도 사라진다. 새 판본이 오면 기존 상태 관리에 따라 다시 강조한다. prefers-reduced-motion에서는 애니메이션/빛 이동 없이 선명한 고정 붉은색·테두리를 제공한다.

CSS만 수정했다. 가상 Chrome에서 실제 0/700ms 배경 차이·1400ms 주기, 클릭 후 정지, 320/768/1024/1440 화면 폭, reduced-motion 고정 표시, AI 요청/JS오류0을 확인했다. 별도 단위·백엔드·LIVE 모델 시험은 실행하지 않았다.

## 2026-09-29 — 화면 명칭 변경

최신 사용자 결정에 따라 화면 표기는 ‘중요 알림’으로 통일한다. 버튼·고정 요약·패널 제목·검색/목록/닫기 접근성 이름에도 적용한다. 이 문서의 이전 ‘주요 알림’은 변경 전 명칭이며 동작 변경은 없다.
