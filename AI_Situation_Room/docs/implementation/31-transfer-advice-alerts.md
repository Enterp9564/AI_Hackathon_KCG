# 링크온 이송 권고의 주요 알림 표시

2026-09-29. [환자 수신 계약](../contracts/linkone-patient-alerts.md), [관리 종결 알림 제외](30-ended-patient-alerts.md)의 후속이다.

## 실제 수신 확인과 원인

사용자가 지정한 두 환자의 최신 patient_ai_analysis.outcomes에는 모두 AIR_TRANSFER가 있고, 한 명은 VESSEL_TRANSFER도 포함한다. 해온 SQLite의 최신 수신 원문에서도 같은 코드를 확인했다. 수신 누락이 아니라 목록이 긴급도·요약만 표시하고 이송 결과를 상세 원문에 넣어 둔 표시 문제였다. 현재 두 환자의 관리 상태는 ENDED이므로 실제 활성 알림에 복구하지 않는다.

Link-One 프런트엔드의 코드 표시명도 확인했다. AIR_TRANSFER는 ‘헬기 이송 필요’, HOSPITAL_TRANSFER는 ‘의료기관 이송 필요’, VESSEL_TRANSFER는 ‘함정 이송 필요’다. 이는 출처 AI 판정이며 실제 현장의 요청, 배차·출동 지시, 이송 완료와 다르다. 이번 확인에서 해당 사건의 transport_order 4건은 DONE이었다. 환자 AI 결과만으로 진행 중인 헬기 출동 요청을 추정하지 않는다.

## 표시·수신 계약

- 기존 3초 수신으로 받은 outcomes를 사용한다. DB 쿼리·API·폴링·AI 호출을 추가하지 않는다. 원격 AI 분석 생성 주기가 느리면 해온이 그보다 먼저 결과를 만들 수는 없다.
- 상시 주요 알림 요약에 활성 환자의 헬기·의료기관·함정 이송 권고 인원수를 표시한다. 한 사람이 복수 권고를 가질 수 있으므로 종류별 수를 합산한 값을 고유 환자 수로 해석하지 않는다. 모든 수가 0이면 이 줄을 숨긴다.
- 환자 목록에 출처와 함께 붉은 문자 배지를 표시한다. 색상 외에도 ‘헬기 이송 필요’ 등 문구로 종류를 구별한다. 클릭 전 버튼 강조와 새 판본 재강조는 기존 동작을 유지한다.
- 이송 권고 전체·헬기·의료기관·함정 필터를 추가한다. 이름/내용 검색과 기존 유형 필터·컬럼 정렬을 함께 적용한다. 번역된 결과 문구도 검색·내용 정렬에 포함한다.
- 상세 상단은 ‘링크온 AI 권고’로 표시한다. reasons의 text, record, criterion을 각각 권고 이유·현장 기록 인용·링크온 적용 기준으로 구별해 보여준다. 현장 기록 인용은 출처 AI 결과에 포함된 문자열이며 해온이 현장 요청을 독립 검증했다는 뜻이 아니다.
- status=OK인 결과만 현재 권고 배지·집계·필터에 사용한다. 중복 코드는 한 번만 세며 알 수 없는 코드는 ‘출처 코드’로 보존한다. 실패 결과에 남은 과거 outcomes를 새 권고로 표시하지 않는다. 원문과 기존 인용 검토 흐름은 유지한다.
- 관리 종결 ENDED는 목록·권고 집계에서 계속 제외한다. 읽기·검색·필터는 AI 실행과 무관하다. 추가 AI 검토는 기존 명시적 인용 전송으로 진행한다.

## 구현 위치

- prototype/static/alert-list.js: 코드 표시명, 권고 추출·배지·상세 근거 렌더링, 검색 대상 내용.
- prototype/static/patient-alerts.js: 상시 집계·필터·목록·상세 연결.
- prototype/static/index.html, style.css: 요약 줄, 필터 옵션, 강조 스타일.
- prototype/tests/test_patient_alerts_ui.cjs: 복수 이송 권고·필터·검색·상세·실패 결과·중복 코드 검증.

## 검증과 적용

신규 Node 시험에서 기능 부재를 확인하고 구현 후 전체 JavaScript 25개 통과. 기존 가상 환자 Chrome 회귀(8명 목록, 강조/열람 구분, 판본 변경, 오래된 인용 차단, 초안, 사건 전환, 키보드, 대형 화면, 모바일) 통과.

추가 가상 Chrome 시험에서 헬기 권고 2명·함정 권고 1명, 필터·검색, 상세 출처/기록/기준, 390px 화면을 확인했다. AI 전송 요청과 JavaScript 오류는 0건이다. 실제 종결된 환자를 수정하거나 실제 사건 AI 검토를 실행하지 않았다. 백엔드 변경이 없어 이번에는 전체 Python·LIVE 모델 시험을 다시 실행하지 않았다. 기존 시험 기록은 PROGRESS의 이전 항목에 보존한다.

실행본에는 정적 파일만 적용한다. 새로고침 후 반영되며 서버 재시작·원격 DB 변경은 필요 없다. 실사건의 새 이송 권고 발생부터 화면 도착까지의 지연과 장시간 성능은 이번에 측정하지 않았다.

적용 후 8860/8861의 HTML·JS·CSS가 검증 파일과 바이트 단위로 같은 것을 확인했다. 첫 HTTP 확인은 정적 경로를 /static/으로 잘못 지정해 404였으며 서버의 실제 루트 경로로 수정한 뒤 두 서버 모두 통과했다. git diff --check도 통과했다.

## 가상 알림 1건 시연

후속 사용자 요청으로 별도 임시 DB·loopback 서버에 MANAGED 환자1명의 AIR_TRANSFER/RECHECK 결과를 넣고 기존 수신 워커·화면으로 표시했다. 미열람1건·상단 헬기1명·목록 배지·필터와 AI실행0건을 Chrome에서 확인했다. 브라우저 확인은 목록까지만 수행해 사용자 열람 전 상태를 보존했다. 실제 링크온 AI의 권고 생성 시험은 아니며 기존 환자 기록·운영 세션은 변경하지 않았다.
