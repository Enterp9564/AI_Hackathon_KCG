# Link-One 알림 2초·현재 상태 3초 수신

2026-09-30 구현·8860 적용. [검증요원 설정](36-critic-toggle.md)은 별도 기능이다.

## 동작과 경계

- 환자·선체 알림: 기존 읽기 전용 워커의 정상 주기를 3초에서 **2초**로 변경했다. 종결 알림 제외·읽음·인용 승인 동작은 유지한다.
- 현재 상황·승선원·환자 상태·최근 현장기록: 별도 워커가 **3초**마다 조회한다. 브라우저는 해온의 캐시를 1초마다 읽으며 탭 수가 원격 조회 횟수를 늘리지 않는다.
- 현재 상태 수신은 session.facts/version, 기존 분석용 수신본, 메시지, AI 실행 문맥을 수정하지 않는다. 자동 AI 호출·원격 DB 쓰기는 없다.
- 전체 분석 자료를 새로 받아 AI가 검토하게 하려면 기존 ‘링크온 동기화’를 사용한다. ‘저장 자료 재분석’은 저장된 분석 수신본을 사용한다.
- 정상 주기는 고정이다. 상시 성능 측정·진단 SQL·p95 계산·자동 주기 조절은 추가하지 않았다. 기존 조회 시각과 오류 기록은 유지한다.

## 파일과 데이터 경로

`linkone_current_source.py` → `linkone_current.py` → `server.py` → `static/linkone-current.js` / `app.js`.

1. `AlertSource(worker_module=...)`의 프로세스·SSH 수명 관리만 재사용한다. 기존 알림 워커와 연결·실패 상태는 독립적이다.
2. PostgreSQL 읽기 전용 repeatable-read 트랜잭션에서 room/person/person_state/closure_place와 RECORD를 제한된 필드로 조회한다. 쿼리별 제한 시간은 1,500ms다.
3. RECORD는 1인당 최근 5건과 전체 건수를 읽는다. 음성은 저장된 RECORD의 text/category/via만 표시하며 오디오·전사 원문·AI_ADVICE를 가져오지 않는다. AI 판정 완료를 기다리지 않는다.
4. UNDO의 undo_of 또는 payload.eventId가 같은 사건·같은 환자의 기록을 가리키면 취소 참조를 표시한다. 취소의 재취소까지 현재 유효성으로 확정하지 않으며 ‘취소 참조 있음 (원본 확인)’으로 표시한다.
5. 원격 결과와 분석용 전체 수신본을 같은 정규화 함수로 비교한다. 시간 문자열을 UTC로 맞추고 허용 필드의 정렬된 SHA-256 지문을 만든다. 시각이 같은 정정·삭제도 지문이 바뀐다.
6. 동일 지문은 상세 재전송·변경 이력 저장을 생략한다. 수신이 바뀌면 `linkone_current_cache`와 불변 `objects(kind=linkone_current_snapshots)`에 저장한다. 연결 대상이 바뀌거나 삭제되면 늦은 응답을 버린다.

상한은 사건 32개, 전체 명부 2,000명·최근 기록 2,000건·응답 2MB다. 초과·누락·다른 사건 참조를 오류로 처리하고 마지막 정상 자료를 보존한다. 완전하지 않은 명부를 0명으로 표시하지 않는다. 총원·구조 집계는 기존 전체 수신과 `person_summary`를 공유한다.

## API·UI

- `GET /api/sessions/{sid}/linkone-current`: 상세 캐시. HTTP GET은 원격 조회를 직접 실행하지 않는다.
- 기존 세션 GET의 `live_situation`: 요약·지문·조회 성공 시각·수신 시각·원본 변경 시각·분석 수신본 일치 여부. Engine이 사용하는 Store.snapshot에는 합성하지 않는다.
- 우측 현재 상황은 사용 가능한 현재 캐시의 총원/구조/미구조를 표시한다. 마지막 전체 수신보다 먼저 시작한 자동 조회 결과는 전체 수신을 덮어 표시하지 않는다.
- 승선원 창은 ‘현재 상태 · 자동 갱신’과 ‘분석 수신본 · 변경 내역’을 구분한다. 자동 갱신 시 검색·정렬·스크롤·펼친 환자 기록을 보존한다. 최근순은 상태 변경과 현장기록 중 더 최근 시각을 사용한다.
- 이전 AI 보고와 다른 현장 상태 및 선택한 과거 보고의 기준을 구별한다. 자동 수신을 검증 완료로 표시하지 않는다.

오류 시 재시도 간격은 6→12→24→48→60초이며 회복하면 정상 주기로 돌아온다. 느린 조회는 중첩하거나 밀린 횟수만큼 몰아서 실행하지 않는다. 10초 이상 확인이 없거나 재시작 직후에는 마지막 정상 자료와 갱신 지연/대기를 표시한다. 2초/3초는 음성 입력부터 화면 반영까지의 보장 시간이 아니다.

현재 상태 수신 중지: 서버 옵션 `--linkone-current-interval 0`. 기본은 3이며 허용값은 0/3이다. 기존 캐시·이력은 삭제하지 않는다.

## 검증 및 적용 기록

- Python 전체 218개: **214 통과·4 건너뜀**. Node **31 통과**. JS 문법·diff 검사 통과.
- 최초 HTTP 시험은 샌드박스 포트 권한 때문에 실패했고, 허용된 실행으로 다시 시험해 통과했다. 기존 3초 기대값은 승인된 2초 계약에 맞춰 수정했다.
- 실제 읽기 전용 조회: 연결 사건 3개·승선원 201명·최근 기록 16건. 무변경 두 번째 응답의 상세 생략 확인. 부하/속도 벤치마크는 하지 않았다.
- 격리 브라우저: 구조 1→2명, 음성 기록 1→2건 자동 표시. 검색어·정렬·펼친 기록·채팅 초안 보존 확인.
- 새 코드 정적 검토에서 최신 상태 시각 정렬과 선택한 과거 보고 기준 표시를 보완했다. 해당 회귀 시험 실패→수정→통과 후 전체 재실행.
- 운영 8860 재시작 전 유휴 확인 및 DB 백업. 기존 13개 세션·facts/version·분석/메시지 수·모델·매뉴얼 설정 보존 확인. 연결 사건 3개 모두 현재 상태 ready, 알림 2초/현재 상태 3초 확인. 당시 8861은 중지 상태라 새로 실행하지 않았다.
- 실제 LLM 재분석·품질 비교·원격 DB 변경은 하지 않았다.
