# 검증요원 ON/OFF 설정

2026-09-30 구현·8860 적용. 기본값은 **ON**이며 운영 설정을 임의로 OFF로 바꾸지 않았다.

## 사용자 동작

우측 상단 **설정 → 검증요원 사용**에서 바꾼다. 스위치를 바꾸면 바로 저장된다.

- ON: 전문요원 보고 → 검증요원 → 상황실장 종합.
- OFF: 전문요원 보고 → 상황실장 종합. 별도 검증 모델 호출·task·보고·시간축 구간은 생성하지 않는다.
- 해당 서버 DB의 모든 세션에 적용하고 재시작 후에도 유지한다. 별도 DB의 서버들은 설정을 공유하지 않는다.
- 새 요청을 접수할 때 적용한다. 이미 진행·대기 중인 요청은 당시 선택을 유지하므로 설정 변경으로 현재 검증 호출이 취소되지는 않는다.
- 상황실장은 계속 종합한다. OFF에서도 근거·형식 검사와 매뉴얼 인용 검사·세션 격리는 유지한다.

검증요원과 상황실장은 검토 항목이 일부 겹치지만 별도 검증을 생략한 품질이 같다고 보장하지 않는다. 기존 최종 종합 호출에 근거·충돌·미확인 사항 확인을 요청하는 짧은 지침을 추가했다. 검증 전체 프롬프트나 추가 호출은 넣지 않았다.

## 저장·API·실행 계약

- `settings.critic_enabled`: JSON boolean. 미설정은 true. 실제 boolean 이외 입력은 400으로 거부한다.
- `GET/POST /api/settings/critic`. POST `{enabled:false}`. 응답 `{enabled,scope:"server",applies_to:"new_requests"}`. 기존 Host/Origin·쓰기 토큰 검사를 적용한다.
- Store._enqueue의 기존 세션 DB 트랜잭션에서 `run.critic_enabled`를 저장한다. 중복 request_id는 처음 저장된 값을 유지한다. 일반 채팅·인용·링크온 동기화/재분석의 공통 접수 지점을 사용한다.
- `run.critic_review.status`: pending / running / completed / failed / skipped / not_applicable. 생략 이유는 disabled_by_setting이며 서버가 기록한다. 모델이 수행 상태를 결정하지 않는다.
- 전문요원 없는 직접 처리에서는 not_applicable. ON 검증 실패는 failed이며 자동 OFF 전환 없이 기존 실패 경로를 유지한다.
- 이전 run의 정책 필드가 없으면 실행 호환 기본값은 ON. 과거 화면의 수행 여부는 실제 task 기록을 사용하며 근거가 없으면 미확인이다.

## 화면과 파일

`store.py` 저장/접수 → `engine.py` 분기 → `models.py` 최종 지침 → `server.py` 설정 API → `static/model-settings.js` 스위치 → `static/app.js` 실행 상태.

OFF 실행에는 ‘검증요원 생략 · 설정 OFF’를 표시한다. 전문요원이 끝나면 검증 대기에 머물지 않고 상황실장 종합으로 전환한다. 최종 상세·이력은 선택한 실행의 실제 기록을 따르며 현재 스위치로 과거 보고를 바꾸지 않는다. 저장 실패 시 스위치 선택을 복원하고 채팅 초안과 모델 설정 입력은 유지한다.

## 검증과 제한

가짜 모델·격리 SQLite/HTTP에서 기본 ON·OFF 지속·엄격한 boolean·중복 요청·대기 요청 중 설정 변경·직접 처리·검증 실패·잘못된 근거 ID 검사를 확인했다. 격리 브라우저에서 OFF 저장 후 새 DEMO 실행이 검증요원 없이 최종 종합까지 완료되는 것을 확인했다. 기존 ON 실행 보고와 초안은 유지됐다.

전체 시험: Python 218개 중 214 통과·4 건너뜀, Node 31 통과. 별도 실제 LLM 속도/품질 비교는 실행하지 않았다. 과거 관측치(OpenAI 검증 39.706초, 로컬 28.342초)는 참고 기록이며 이번 OFF 실행의 단축 시간 측정값이 아니다.
