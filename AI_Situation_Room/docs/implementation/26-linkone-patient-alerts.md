# 26 · Link-One 환자 판정 알림 — 3초 수신

2026-09-29. 연결된 사건의 `patient_ai_analysis` 결과를 읽어 해온에 표시한다. 환자 상태를 재판정하거나 링크온의 모델 실행 주기를 바꾸는 기능은 아니다. [DB 계약 조사](../contracts/linkone-patient-alerts.md) · [설계](../superpowers/specs/2026-09-29-linkone-patient-alerts.md).

## 부하 판단

사용자가 응급·중요 정보의 빠른 반응을 위해 3초 수신을 요청했다. 기존 수동 수신은 매번 SSH·DB 연결을 열고 수신 사이 5초를 기다리므로 그대로 재사용하지 않았다.

실제 DB에서 지속 연결 하나로 3초 간격 10회 비식별 집계를 측정했다. 최신 분석 7건, 판정 데이터 예상 크기 합계 14,380바이트였다. 왕복 중앙값 105.263ms, 최대 134.135ms; EXPLAIN ANALYZE의 DB 실행 0.234ms, 계획 0.171ms, shared hit 10/read 0이었다. 환자 원문을 전송한 시험이 아니라 DB 내부에서 크기를 합산해 시간·건수만 받은 시험이다.

정상 시 서버당 분당 약 20회, 시간당 약 1,200회의 일괄 변경 확인이다. 현재 표본에서는 3초 조회가 적절하다고 판단했다. 표본 7건·짧은 기간·캐시가 있는 DB 측정이므로 대규모 사건이나 동시 다중 해온 서버의 부하를 보장하지 않는다.

처음 제안한 환자 원문 반복 수신 부하 시험은 자동 승인 검토가 거절했다. 원문을 반출하지 않는 집계로 바꿔 측정을 완료했다. 이 거절을 우회해 원문 반복 시험을 실행하지 않았다.

## 수신 구조

- `linkone_source.connection()`이 호스트 키 고정 SSH·기존 읽기 전용 PG 접속을 제공한다. 수동 전체 동기화도 같은 자원 정리 함수를 사용한다.
- `linkone_alert_source.AlertSource`는 기존 private psycopg Python으로 자식 프로세스를 한 개 실행한다. 이 프로세스는 SSH·DB 연결을 유지한다. 키나 암호를 명령행·로그·응답에 넣지 않는다.
- `PatientAlerts`는 서버당 스레드 하나로 연결 세션의 room UUID를 중복 제거하여 일괄 조회한다. 일반 세션과 MCP 사건 링크는 대상이 아니다. 연결 세션이 없으면 외부 연결도 닫는다.
- 정상 조회 시작 간격은 3초다. 3초 이상 걸린 작업은 완료 후 3초를 쉬고 다음 확인을 한다. 요청 중첩과 밀린 실행 재생은 없다. 브라우저 탭 수는 DB 조회 수를 늘리지 않는다.
- 최신 선택은 `(room_id, person_id)`별 `finished_at DESC, id DESC`다. 판정의 허용 필드와 같은 사건의 `person_state.last_event_id`로 DB에서 MD5 지문을 계산한다. MD5는 변경 감지용이며 무결성 서명으로 사용하지 않는다.
- 지문이 바뀐 사건만 상세 결과를 받아 SHA-256 판본 키로 로컬에 보존한다. 수정된 같은 분석 ID, 현재 상태 이력 변경도 감지한다. 원시 모델 입력 `sent`·계정·provider/model·내부 error는 수신하지 않는다.
- 매 조회는 짧은 READ ONLY / REPEATABLE READ 트랜잭션으로 끝낸다. 3초 대기 동안 트랜잭션을 유지하지 않는다.
- 수동 전체 수신의 연결과 알림 연결은 별개다. 둘이 겹치면 서버당 최대 두 개의 읽기 연결이 사용될 수 있다.

## 제한·장애·종료

- 사건 최대 32개, 최신 판정 합계 1,000건, IPC 응답 2,000,000바이트, 판정당 24,000바이트.
- SQL statement timeout 1,500ms, 작업 IPC timeout 20초. 상한 초과·잘린 결과·다른 사건 혼입·중복 환자를 성공으로 저장하지 않는다.
- 실패 시 마지막 성공본과 시각을 보존한다. 재시도는 6 → 12 → 24 → 48 → 60초이며, 성공 후 3초로 복귀한다.
- 정상 무변경 확인 시각은 메모리에서 갱신한다. 내용 변경·장애·복구 시에 SQLite 상태를 저장해 3초마다 불필요한 쓰기를 줄인다. 재시작 직후는 이전 연결을 정상으로 표시하지 않는다.
- 프로세스 생성/종료 락과 영구 종료 플래그를 사용한다. 종료 시 프로세스 그룹을 정리하며, 시작 포트 충돌 시에는 주기 작업을 시작하지 않는다.

## 저장·API

SQLite `patient_alerts`: `id`, `session_id`, `source_id`, `hash`, `person_id`, `current`, `data`. `(session_id, source_id, hash)`가 유일 키다. data에 원본 허용 필드, 수신/읽음 시각, 최초 인용 메시지를 보존한다. 세션 삭제 시 CASCADE 삭제한다.

`patient_alert_state`: 세션별 연결 상태와 마지막 성공/시도 시각, 다음 확인 시각. 다른 사건 응답과 삭제된 사건의 늦은 응답을 버린다. 재생성한 사건은 지문 캐시를 재사용하지 않는다.

- `GET /api/sessions/{sid}/patient-alerts`: 해당 세션의 최신 판정·읽지 않은 건수·연결 상태. 원격 DB 조회나 AI 실행을 직접 일으키지 않는다.
- `POST .../patient-alert-seen`: `{alert_id}`. 현재 세션 소유권 확인 후 그 판본의 상세 열람을 기록한다.
- `POST .../patient-alert-review`: `{alert_id}`. 서버 저장 원문으로 인용을 만들고 기존 Engine에 `patient-alert:{local_id}` 요청 키로 접수한다. 이중 클릭과 응답 유실 재시도는 같은 실행으로 합쳐진다.
- 쓰기는 기존 X-Session-Token 및 Host/Origin 검사 대상이다. 일반 `/message`에서 환자 알림용 요청 키를 사용할 수 없다.
- 수신은 facts·상황 버전·명부 스냅샷·요원 호출을 바꾸지 않는다. 명시적 인용 요청만 기존 상황실장/요원 흐름으로 전달된다. 인용·실행 여부는 저장된 인용과 run.request_id로 추적한다.

## 화면

`static/patient-alerts.js`가 빨간 Link-One 버튼을 소유한다. 숫자는 현재 사건에서 아직 상세를 열지 않은 최신 판정 수다. 확정 응급환자 수가 아니다. 미연결/확인 전/실패와 0건을 구별한다.

버튼 아래 화면 범위 안에 모달 플로팅 패널을 띄우고, 좁은 화면에서는 하단에 배치한다. 환자별 목록 → 같은 패널 상세 → 목록 복귀를 제공한다. 배경 조회로 열린 상세와 포커스를 재생성하지 않는다. 세션 전환 시 즉시 초기화한다.

기존 명부 수신본이 있으면 그 명부의 이름을 표시하고, 없으면 환자 UUID 일부로 표시한다. 출처 긴급도·요약·근거·부족 정보·기준/완료/수신 시각을 보여준다. 실패/미지원 코드와 현재 이력 불일치를 표시한다. 읽음은 위험 해소가 아니다.

‘해온에 인용하여 검토’는 `send({patientAlert})`를 사용해 기존 채팅 초안을 보존한다. Link-One MCP 수신함은 패널의 ‘외부 보고(MCP)’에서 계속 접근한다. RESAID AI는 기존 경로를 유지한다.

브라우저는 1초마다 로컬 캐시를 확인한다. 이상이 DB에 저장된 후 정상 연결에서 감지까지 최대 약 3초와 조회 시간이, 화면 반영까지 추가로 최대 약 1초가 걸릴 수 있다. 이 시간은 보장 SLA가 아니다. 링크온의 AI 결과 생성이 지연되면 해온의 짧은 조회 간격으로 해결되지 않는다.

## 검증과 남은 범위

- 단위/HTTP: 전체 Python 172개 PASS. 신규 17개는 세션 격리, 반복 수신, 새 판본, 실패/지수 재시도, 사건 재생성, 삭제 중 응답, 무중첩, 초안과 별개인 서버 인용 멱등, 권한, 프로세스 생성 중 종료, 포트 충돌을 포함한다.
- JS: 변경 파일 문법 검사 PASS. 브라우저 실제 가상 자료로 목록/상세/읽음, 같은 인용 재전송, 작성 초안 보존, 기존 MCP 접근, 다른 사건 0건, 390px 패널 경계, 콘솔 오류 0건을 확인했다.
- 실제 DB: 빈 기존 시험 사건에서 지속 연결로 3초 간격 4회 조회. 154.45/128.44/132.96/128.02ms. 최초 빈 수신 후 나머지는 지문 일치로 원문 수신을 생략했다. 실제 환자 원문 수신 시험은 아니다.
- 코드 리뷰: 종료 경쟁, 포트 충돌 자원 누수, 상세 포커스 초기화 세 건을 수정하고 종료 테스트 3개와 리뷰 재확인을 통과했다.
- 아직 하지 않은 시험: 실제 환자 판정 원문이 있는 사건의 UI, 원격 신규 판정 발생부터 화면까지 지연, 장시간/대규모 부하, 실제 네트워크 장애 후 복구, 새 LIVE 모델 인용.
- 과거 판정은 저장하지만 이력 탐색 UI는 후속이다. 임상 경보 해제 기준, 링크온 3분 생성 주기와 전체 코드 의미는 미확정이다. 현재 결과 없음은 정상 환자라는 뜻이 아니다.
