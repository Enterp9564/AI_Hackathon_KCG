# 링크온 상황실 화면 전환

## 현재 제공 범위 — 2026-09-29 수동 로그인 유지 반영

상단 대형 화면 메뉴 옆에 `해온 상황실`·`링크온 상황실` 버튼을 추가했다. 원본 사이트는 `https://114-110-181-118.sslip.io/`다. 첫 클릭에만 iframe을 만들고 해온 화면을 오가거나 해온 사건을 바꿔도 유지한다. 사용자가 링크온에서 한 번 직접 로그인하고 근무자·사건을 선택하는 방식이다. 해온 채팅 DOM을 제거하지 않으므로 작성 중 지시·가정이 남는다. 환자 알림·해온 실행 상태는 공통 영역에 남는다.

**최신 사용자 결정은 직접 로그인한 화면을 유지하는 것이다. 자동 로그인 및 같은 링크온 사건 자동 입장은 구현하지 않았다.** 계정 로그인 성공 확인과 제품의 자동 로그인 구현 완료는 다르다. 현재 링크온은 로그인 → 근무자 선택 → 사건 선택 → 입장의 순서이고, 조사한 공개 SPA에는 사건 URL·외부 화면 전환 메시지 수신 경로가 없었다. 공유 GitHub `Link_One` 폴더에도 README만 있다. 소스 위치는 사용자도 모르는 상태다.

해온은 연결 사건명·room_id를 참고로 표시하고, 링크온에서 같은 사건을 직접 선택하도록 안내한다. iframe 로딩을 로그인/사건 일치 성공으로 해석하지 않는다. 원본이 표시되지 않는 환경에는 `별도 창` 링크를 제공한다. **현재 Codex 내 브라우저의 임베드는 빈 화면으로 남았으며 실제 원본 임베드 성공으로 기록하지 않는다.** 별도 탭의 원본 사이트 로그인 화면은 접근했다. 후속 비교에서 같은 iframe·sandbox가 Safari에서는 정상 표시됐다. 해온 8860 내부 로그인 화면과 현재 연결 사건 표시를 확인하고 사용자 직접 로그인을 위해 열어뒀다. Codex의 정확한 내부 차단 원인은 확정하지 않았다.

## 구현 위치 및 상태

- `prototype/static/linkone-workspace.js`: 탭 전환, 첫 클릭 지연 생성, 같은 세션에서 iframe 유지, 사건 참조 표시.
- `prototype/static/index.html`: 상단 버튼 그룹, 공통 알림 영역, 두 화면 영역, 별도 창과 다시 열기.
- `prototype/static/app.js`: `resetView`에서 프레임을 보존한 채 해온으로 복귀하고 사건 변경 안내 표시. `renderSnapshot`에서 세션·room_id 변경을 재확인.
- `prototype/static/style.css`: 기존 색상·헤더 규칙을 따르는 전환 버튼과 반응형 원본 화면.
- `prototype/server.py`: 새 JS 정적 경로 및 정확한 HTTPS 원본만 `frame-src` 허용. 기존 스크립트·API 출처 제한 유지.

`resetLinkoneWorkspace`는 프레임을 제거하지 않는다. 해온으로 돌아오며 사건 변경 안내를 표시한다. `renderLinkoneWorkspace`는 세션 ID 또는 room_id 변경을 감지하면 같은 안내를 표시한다. 안내는 실제 사건이 자동으로 전환됐다는 뜻이 아니며, 사용자가 링크온에서 직접 현재 사건을 선택해야 한다. 다른 출처의 화면이므로 링크온이 선택한 사건·로그인 여부를 해온이 직접 읽거나 검증하지 않는다.

`링크온 다시 연결`은 초기화/재로그인 가능성을 확인한 경우에만 iframe을 다시 만든다. 단순 왕복·1초 상태 갱신·해온 사건 변경에서는 src를 다시 설정하지 않는다. 해온 페이지 새로고침·탭 종료는 프레임 수명을 끝내므로 화면 선택까지 영구 보존하지 않는다. 링크온 자체 세션 만료·로그아웃 규칙도 적용된다. 비밀번호 저장은 이 기능의 요구조건이 아니다.

iframe은 `allow-scripts allow-same-origin allow-forms allow-downloads`로 제한하고 referrer를 보내지 않는다. 사용자 비밀번호·토큰을 HTML·JS·URL·postMessage·해온 저장소에 넣지 않는다. 환자 알림의 3초 수신과 기존 AI 승인 흐름에는 연결하지 않는다. 원본 사이트가 열린 동안 자체 네트워크 요청은 발생할 수 있다.

## 향후 자동 입장으로 확대할 경우 필요한 후속 구현 (현재 범위 밖)

목표는 담당자가 해온의 버튼을 누르면 **인증된 근무자와 정확한 room_id가 확인된 원본 상황실**로 들어가는 것이다. 다음은 구현 계약 제안이며 실제 존재하는 API가 아니다.

1. 링크온 서버에 사건 범위가 제한된 일회용 입장 코드 발급·소비 API를 제공한다. 서버 간 인증, 사용자/근무자, room_id, 허용 출처, 30~60초 만료, 1회 사용을 검사한다. 계정 비밀번호를 클라이언트에 전달하지 않는다.
2. 원본 프런트엔드에 입장 코드 처리 페이지를 추가한다. 코드 소비 후 기존 인증·근무자 선택·`enterRoom` 흐름을 정식으로 호출한다. 활성 근무자를 임의로 탈취하거나 새 사용자를 자동 생성하지 않는다. 전용 열람 근무자/권한은 링크온 팀과 정한다.
3. 링크온은 실제 입장 완료 시에만 `room_id`와 요청 nonce를 부모에 알린다. 양쪽 모두 정확한 `origin`·`source`·nonce를 확인하고 `*` 대상 메시지를 사용하지 않는다. 비밀번호나 장기 토큰은 메시지에 포함하지 않는다.
4. 해온 서버는 선택 세션의 저장된 room_id로만 입장을 요청한다. 브라우저가 임의 대상 URL이나 room_id를 서버에 전달해 다른 사건을 열도록 하지 않는다. 응답 대기 중 사건 변경 시 취소/무시하고 이전 프레임을 제거한다.
5. 프레임 허용 정책과 쿠키/세션 저장 정책을 원본 앱에서 지원해야 한다. 지원 불가 환경은 같은 입장 계약으로 별도 탭을 연다. 핫스팟 LAN 주소가 바뀌면 개발용 허용 출처를 명시적으로 갱신한다.

완료 조건: 클릭→자동 로그인→정확한 사건 입장, 왕복 시 원본 화면·해온 초안 유지, 사건 A→B 전환 중 오래된 응답 차단, 만료/중복 코드 거절, 로그아웃·네트워크 단절 안내, iframe/별도 탭 검증. 링크온 소스와 배포 협조를 확보하기 전에는 이 완료 조건을 충족했다고 표시하지 않는다.
