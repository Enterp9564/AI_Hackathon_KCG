# 25. 검증요원 입력 경량화와 호출 진단

2026-09-29. 검증요원 LIVE 호출이 약 90초 후 실패한 간단 실운용 시험에 대한 후속 변경이다. 이전 실패는 [시험 기록](24-local-manual-rag-smoke.md)에 보존한다.

## 동작

- `critic.py`의 전용 지침을 `critic/report`에만 사용한다. 근거 없는 주장·보고 간 모순·사실과 가정 혼동을 점검한다. 일반 요원의 장부 갱신·임무 배정·새 출동안 작성 지침은 전달하지 않는다.
- 요약 1문장, 중요 수정사항 최대 3개, 권고 1문장, 미확인사항 최대 3개를 요청한다. 필수 추가 질문은 최대 2개이며 출동안은 빈 배열로 지시한다. 기존 report JSON 형식과 UI를 유지한다. 개수 제한은 모델 지침이며 새 서버 강제 스키마는 아니다.
- 모델/추론 수준은 기존 `gpt-6-luna`/`medium`. 검증 응답 토큰 상한만 6,000 → 2,400으로 변경했다. 다른 역할은 6,000을 유지한다. 이 상한은 표시 글자 수가 아니며 추론 토큰도 사용할 수 있다.
- `review_context`는 session의 facts/incident/weather와 같은 ID의 근거 JSON이 정확히 같을 때만 session 쪽 중복을 제거하고 `session_evidence_refs`를 남긴다. 대응 근거가 없거나 다르면 상태를 그대로 보낸다. 원본 객체·근거 본문·제한·판본·요원 보고·가정은 자르거나 수정하지 않는다.
- Link-One 및 경사 지침은 해당 입력이 있을 때만 추가한다. 외부 보고의 미확인 상태, 자료 내 지시 무시, 실제 가용성/출동과 후보 구분, SAR 초안·부분 검색 제한을 유지한다.
- 검증이 끝나야 최종 종합한다. 실패한 검증을 통과로 바꾸거나 자동 재전송하지 않는다. 기존 호출의 90초 제한은 유지한다.

## 진단 기록

`models.py`는 호출별 `diagnostics`를 반환하고 `Engine.call`은 성공/실패 모두 calls에 저장한다.

- 입력·지침 문자 수, 출력 상한, 대기 제한, 헤더 수신까지/전체 경과 ms.
- `phase`: await_headers, read_body, validate_response, completed.
- `error_kind`: timeout, network, http, invalid_response, incomplete, invalid_json. HTTP 오류는 상태 코드만 보존한다.
- 연결 초기 오류뿐 아니라 응답 도중 연결 초기화·불완전 응답도 구분한다. 키·헤더·원문 오류·응답 본문은 진단에 넣지 않는다.
- 헤더/본문 경계는 클라이언트가 관찰한 구간이며 모델 내부 추론 시간이나 원격 서버 대기열을 측정한 것은 아니다.
