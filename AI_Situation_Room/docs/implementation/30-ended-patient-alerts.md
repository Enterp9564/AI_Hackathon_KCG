# 관리 종결 환자의 알림 제외

2026-09-29 구현. [환자 수신 계약](../contracts/linkone-patient-alerts.md), [주요 알림](29-alert-sorting-vessel.md)의 후속이다.

## 실제 DB 확인

KISTI 사건의 room.status는 ACTIVE다. person_state의 management enum은 MANAGED(관리 중), ENDED(관리 종결)이며 종결된 4명의 location_kind는 CLOSURE였다. 최신 환자 분석 5건 중 4건이 ENDED, 나머지 1건은 조인된 현재 상태가 없었다. 상태 부재는 종결로 추정하지 않는다.

선박 경고 11건에는 모두 ack 기록이 있었지만 경고 종결 필드는 없었다. ack는 확인 기록이므로 이번 환자 관리 종결 필터에 포함하지 않는다. 사건 종결·개인 종결·이송 종결·선박 경고 확인은 서로 다른 의미다.

## 처리 계약

- 기존 3초 지속 연결 워커에서 latest patient_ai_analysis와 person_state를 사건/인물 ID로 조인한다. 허용 필드에 management 및 management_updated_at을 추가하고 변경 지문에도 포함한다. management_updated_at은 person_state.updated_at이며 종결 전용 시각이 아니다.
- 명시적인 management=ENDED만 현재 환자 알림 목록·미열람·긴급 분류 집계에서 제외한다. null/알 수 없는 값은 남긴다. 위치=CLOSURE 또는 이송 종결 시각만으로 종결을 추정하지 않는다.
- 수신 원문은 SQLite에 판본별로 보존한다. latest ENDED 판본도 current=1로 보관하고 view에서 제외하므로 이전 활성 판본이 살아나지 않는다. 폐기/삭제 쿼리는 없다. 종결은 missing_count에 포함하지 않는다.
- 기존 patient-alerts 응답에 ended_count와 ended_person_ids를 추가한다. 화면은 종결 환자 상세를 해제하고, 현재 목록에 없는 판본의 클릭 전 강조를 제거한다. 요약에 관리 종결 N명 제외를 표시한다.
- 종결 판본의 인용은 서버 quote에서 거절한다. 종결 이전 판본도 current=false 검사로 인용할 수 없다. 이미 과거에 실행된 보고는 보존한다.
- CLOSE_CANCEL 등으로 최신 상태가 MANAGED로 바뀌면 같은 AI 분석 ID라도 현재 관리 상태/수정 시각/이력 ID가 바뀐 새 판본을 수신하고 다시 알린다. 새 AI 분석을 기다리지 않는다. 자동 AI 실행은 없다.
- 수신 실패 시 마지막 성공 자료를 유지한다. 종결 필드가 정상 수신된 적 없는 오래된 저장본을 추정으로 숨기지 않는다. 재시작 후 저장된 종결 상태는 유지하고 연결 상태는 첫 확인 대기다.

DB의 환자 상태/경고/확인 기록에 쓰지 않는다. 로컬 사건 장부·명부 수신본·기존 AI 보고도 변경하지 않는다. 종결은 해온의 의료적 회복 판정이 아니라 Link-One 관리 상태다.
