# 선박 경사 판단 보완

2026-09-28. 사용자 제공 이미지의 각도별 설명을 검토해 기존 링크온 분석 흐름에 반영했다. 모델에 실제 전달되는 기준 및 원문 링크는 [경사 판단 참고](../../prototype/knowledge/ship-tilt-guidance.md)에 모았다.

## 반영한 동작

- `ship_tilt.py`가 전체 hull_tilt 수신본을 측정 시각으로 정렬한다. 최신 유효 각도·방향·측정 후 경과시간, 직전과의 부호 포함 변화/절댓값 변화, 평균 변화율을 계산한다. 보조표 본문이 입력 예산 때문에 잘려도 계산은 전체 행을 사용한다.
- `linkone_data.evidence()`의 `tilt_assessment`에 계산을 제공한다. 원본 DB·저장 해시·수신 이력은 바꾸지 않는다. 시간대 없는 시각·미래 시각·유효 각도가 없는 행은 제외하고 수를 알린다. 한 축만 유효한 행은 해당 축만 사용한다. 최신 또는 직전 시각에 복수 기록이 있으면 불확실한 변화율을 만들지 않는다.
- `tools.evidence_for()`가 링크온 분석의 모든 모델 단계에 `ship_tilt_guidance`를 함께 제공한다. 기존 모델 지침에서 최신 측정·적용 가능한 참고 조건·우선 확인/조치 1~2개를 연결하도록 명시했다.
- 이미지의 7°/15° 설명을 여객선 손상 후 최종 평형 상태 계산 기준으로 정정했다. 승선원 생존확률이 아니다. 기관 기준의 앞뒤 5°는 사용하지 않으며 SOLAS II-1/26.6의 동적 피칭 7.5°와 중앙값 트림을 구별한다.
- 10° 승객 편중/선회, 15° 정적 경사·22.5° 동적 횡동요 기관 조건, 진수장치 20°/10°, 비상전원 22.5°/10°는 각 적용 조건을 붙인다. 관측 절댓값과 참고 숫자의 비교만 계산하며 안전 등급·장비 고장·규정 위반·퇴선 결정을 자동 생성하지 않는다.
- 사용자 ‘권장대로’ 선택에 따라 8분에 3° 증가, 12분 경과는 고정 운영 경보 임계값으로 등록하지 않았다. 수치·경과시간은 사실대로 제공한다.

별도 패키지·서비스·DB 테이블·자동 폴링·추가 모델 호출은 없다. 기존 호출의 근거 문서 분량은 늘어난다. 복원성 물리 모델이나 선박별 법규 적합성 판정은 구현하지 않았다.

## 검증 기록

- 초기 신규 시험은 모듈 미구현으로 실패. 구현 후 잘못된 각도와 다른 축의 유효값이 섞인 시험을 ‘부분 유효’ 계약에 맞춰 수정했다.
- 신규 계산/근거 시험 8개: 이미지 예시, 음수 각 감소, 방향 전환, 미래/결측/잘못된 시각·각도, 동일시각 중복, 경계 숫자 비교, 부분 측정, 입력 예산과 원본 불변성.
- 기존 분석 흐름 시험으로 상황실장·정보·수색구조·자원·검증의 모든 단계에 기준 전달을 확인했다. 전체 단위/HTTP/MCP 112개 통과(8.219초). 직전 전체 111개 통과 후 입력 예산/불변성 시험 1개 추가.
- 개인정보 없는 가상 사례의 LIVE 수색구조 분석 1회(14.94초): 6°→9°/8분, 마지막 측정 12분 전, 트림 5°를 사용. 7°/15° 생존확률 해석을 부정하고 재측정·침수·대피로 확인을 권고했다. 불확실성 문장에 ‘12분 전 수신본’이라는 부정확한 표현이 남았다(실제로는 측정 시각). 따라서 모든 문장·역할의 의미 정확성 보장을 주장하지 않는다. 결과는 로컬 `prototype/runtime/linkone-evidence/tilt-guidance-live-check.json`에 보존한다.
- 진행 중 실행/수신이 없음을 확인한 뒤 8860 서버 재시작. HTTP에서 기존 12개 세션 보존 및 퀸메리호의 측정 3건을 이용한 계산/기준 제공 확인. 이 확인은 저장 자료 조회이며 원격 DB 새 수신 또는 실제 사건 LIVE 재분석이 아니다.

## 사용

기존 상황을 삭제할 필요 없다. 화면을 새로고침한 뒤 현재 자료 재분석을 실행하면 새 기준을 쓴다. 현장 최신 데이터가 필요하면 링크온 동기화를 먼저 실행한다. 과거 보고는 그대로 보존된다. 브라우저 UI는 변경하지 않았고 이번 변경의 브라우저 시험은 별도로 하지 않았다.


## 2026-09-28 · 현장 경사 계측값을 신뢰하는 조언 방식

사용자가 링크온 경사가 실제 현장의 계측 장비 실측이며 신뢰성 재검토보다 즉시 대응 조언이 필요하다고 명확히 했다. 이 결정은 앞선 ‘오래된 측정 또는 증가 관측이면 재측정 우선’ 지침을 대체한다.

- tilt_assessment.measurement_source에 field_instrument 및 user_confirmed_linkone_workflow를 넣었다. 사용자 확인에 따른 수신 경로의 출처 표시이며 해온이 개별 장비 교정 인증을 수행했다는 의미는 아니다. 원본 기록·해시는 바꾸지 않는다.
- models.py의 일반 사용자 신고 문구가 링크온 실측을 미확인 신고로 낮추지 않도록 구별했다. 유효 실측값을 전제로 대응 조언 1~2개를 먼저 제시하고, 측정 경과시간은 신뢰성 결함이 아닌 현재성 한계로 다룬다.
- linkone-semantics.md / ship-tilt-guidance.md에서 증가·큰 각도만으로 신뢰성 검증·재측정·교차검증을 선행 조건으로 요구하지 않게 했다. 필요한 최신값 요청과 현장 상태 확인은 대응과 병행한다. 명시된 고장·동일시각 충돌·결측/형식 오류는 해당 기록의 구체적 한계로 남긴다.
- 검증요원은 측정 출처를 재입증시키지 않고 부호·단위·시간·설계 기준 적용·대응 조언을 검토한다. 과거 보고의 포괄적 신뢰성 검토 요구는 최신 출처 설명에 맞춰 바로잡는다.

검증: 새 출처 계약/모델 요청 지침 시험의 실패 확인 후 수정, 관련11개 및 전체 단위/HTTP/MCP112개 통과(8.277초). 개인정보 없는 가상 계측 사례에서 잘못된 ‘재측정 전 대응 보류’ 보고를 입력하고 LIVE 검증요원→상황실장2회 확인: 두 역할 모두 해당 권고를 바로잡고 실측 기반 대응과 경로/전원 확인 병행을 제시했다. 결과는 prototype/runtime/linkone-evidence/tilt-instrument-live-check.json에 보존했다. 실제 사건 재분석 또는 현장 조치 실행 시험은 아니다.

12개 세션 및 분석/수신 유휴 확인 후8860서버 재시작, 기존 퀸메리호의 저장 자료에 실측 출처와 수정 지침 제공을 HTTP로 확인했다. 화면 새로고침 후 현재 자료 재분석으로 적용한다. 과거 보고는 보존한다. 추가 서비스·패키지·상시 작업·모델 호출 단계는 없다.
