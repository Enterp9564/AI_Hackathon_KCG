# 국제 SAR 매뉴얼 검색·요원 연동 구현계획

> 2026-09-29 실행 상태: M1의 기존 14개 요약 검색·요원/근거 화면 연결을 기본 off인 시험 기능으로 구현했다. 전체 원문 정제·G2 출동 분류 개선·전체 LIVE 수용평가·로컬 생성은 미완료다. 완료 범위와 계획 조정은 [실행 기록](2026-09-29-sar-rag-progress.md), 실제 계약은 [24 상세 구현](../../implementation/24-local-manual-rag.md)을 따른다. 아래 미완료 체크박스를 일괄 완료로 바꾸지 않는다.

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking. 개발 보조 에이전트 사용은 별도 사용자 결정에 따른다.

**Goal:** 현재 사건과 요원 임무에 맞는 공개 SAR 근거를 로컬에서 찾아, 출처·적용 조건을 유지한 조언을 제공한다.

**Architecture:** 원문과 정제 자료를 보존하고 로컬 임베딩·벡터 검색·키워드 검색을 결합한다. 서버가 기본 검색을 수행하며 전문요원 → 검증요원 → 상황실장에 실제 사용 근거를 전달한다. 사건 기록은 기존 SQLite를 유지한다.

**Tech Stack:** 기존 Python HTTP·SQLite·HTML/CSS/JavaScript. 추가 제안은 Qdrant Python 로컬 모드, Sentence Transformers, 로컬 다국어 임베딩, pypdf다. 패키지 버전은 대상 장비에서 호환성을 확인하고 잠근다.

**Spec:** [매뉴얼 로컬화 요구·설계](../../improvements/03-local-manuals.md). 본 계획은 그 설계를 구체화한 **검토용 제안**이며 앱 구현 완료나 기술 선택의 사용자 확정을 뜻하지 않는다.

## Global Constraints

- 명칭은 HAEON(해온), 해양경찰 멀티에이전트 의사결정 지원 시스템이다.
- 기존 스택과 세션 격리·정정 이력·Enter 전송·Shift+Enter 줄바꿈을 유지한다.
- 현재 클라우드 설정은 `gpt-6-luna`, 모든 역할 `medium`이다. 로컬 전환은 별도 단계다.
- 상황실장은 짧게 배정하고 독립 요원은 병렬 검토한다. 내부 추론 원문·가짜 진행률을 표시하지 않는다.
- Link-One·RESAID AI 수신만으로 검색을 포함한 요원 실행이나 현재 상황판 갱신을 시작하지 않는다.
- 공개 자료 초안과 국내 승인 SOP를 구분한다. 등록 세력은 실제 가용·출동 상태가 아니다.
- 기존 `prototype/.secrets/`, `prototype/runtime/` 자료를 삭제하지 않는다. 키·환경변수 값은 출력하지 않는다.
- 내부 매뉴얼은 이번 배포에 포함하지 않는다. 추후 검색 권한과 외부 전송 차단을 구현한 뒤 연결한다.
- 단위·HTTP·브라우저·실제 검색·LIVE·로컬 LLM 검증을 구분한다. 실행하지 않은 시험은 `not_run`으로 남긴다.

## Review Focus

1. “오염 없음·지원 종료”가 다시 출동 제안으로 바뀜 → 요원 연동 G2에서 회귀 시험.
2. 새 판본 배포 중 실행이 서로 다른 원문을 받음 → 검색 S2와 연동 G1에서 세대 고정 시험.
3. 검색된 조항의 조건·예외가 문맥 예산 때문에 잘림 → 자료 C2와 검색 S3에서 단위 보존 시험.
4. 전문요원은 인용했으나 검증·최종 단계에는 근거가 없음 → 연동 G1에서 단계 간 포함 관계 시험.
5. 네트워크 단절·손상 인덱스가 정상 검색이나 DEMO 성공처럼 표시됨 → 검색 S2·S4, 로컬 L2에서 실패 구분 시험.

## 1. 현재 확인된 출발점

- 공개 국제 원본 6개·561쪽, 페이지별 추출 텍스트, 한국어 주제 문서 8개·요약 14개가 있다.
- 별도로 국내 보조 구절 6개가 있으나 첫 검색 배포의 기본 대상은 국제 묶음으로 제한한다.
- 원문 전체의 조항 구조·표·예외를 검색용으로 정제한 상태는 아니다. 전체 전문가 검토도 미실시다.
- `manuals.manual_evidence()`는 기존 기본 매뉴얼·동해 세력만 반환한다.
- `tools.evidence_for()`는 공통 근거와 단어 기반 첨부 검색을 제공한다.
- `engine.py`에는 역할별 호출·근거 ID 검사·병렬 실행이 있고, `store.py`는 JSON 실행 기록을 저장한다.
- `static/app.js`는 기존 근거 이름을 표시하지만 새 구절·판본을 해석하는 기능은 없다.
- 국제 평가 초안 20개는 검색 목표와 행동 목표가 섞여 있으므로 분리해야 한다.

## 2. 문서 지도와 의존 순서

1. [자료 파싱·정제](2026-09-28-sar-rag-corpus.md): 원문 구조, 검토 상태, 출처, 수록 범위.
2. [로컬 하이브리드 검색](2026-09-28-sar-rag-search.md): 임베딩·Qdrant·키워드 검색·버전 교체·검색 평가.
3. [요원·기록·화면 연동](2026-09-28-sar-rag-agents.md): 자동 검색·출처 인계·실행 보존·승인 흐름·회귀 검증.
4. [로컬 LLM 전환·운영 검증](2026-09-28-sar-rag-local.md): 장비 측정·모델 연결·완전 오프라인·동시 실행.

실행 순서: C1 → C2 → S1 → S2 → S3 → S4 → G1 → G2 → G3 → G4. C3의 원문 확대는 최초 14개 요약으로 검색을 검증한 뒤 진행할 수 있다. L1은 장비 정보가 준비되면 수행하고, L2는 G3 완료 후 실행한다.

## 3. 두 번에 나누어 출시

### M1: 현재 준비된 요약으로 연결 검증

- 정제된 14개를 새 데이터 계약으로 변환하고 원문 위치를 확인한다.
- 로컬 임베딩·벡터+키워드 검색, 역할별 근거 전달, 출처 표시, 실행 스냅샷을 완성한다.
- 수록 범위는 화면과 문서에 14개 요약이라고 명시한다. 561쪽을 모두 이해·검증했다고 표현하지 않는다.
- 생성 모델은 기존 LIVE를 유지한다. 검색은 로컬이지만 답변 생성은 외부 API라는 경계를 표시한다.
- 담당자 승인·중복 방지·정정·세션 격리 회귀 시험을 통과하면 시험 가능한 첫 버전이다.

### M2: 원문 수록 범위 확대와 추가 검색

- 561쪽 모두에 처리 상태를 기록하고, 핵심 4분야(접수·수색·구조 자원·다수 인명)를 먼저 검토한다.
- 검토한 절을 순차적으로 검색 대상에 편입한다. 표·계산식·의료 수치는 검토 기준을 별도로 충족해야 한다.
- 근거 부족 시 전문요원당 최대 1회 추가 검색·재검토를 허용한다(G4).
- 새 정보가 들어온 새 지시마다 현재 사건을 기준으로 다시 검색한다. 이전의 가정이나 검색 결과를 현재 사실로 재사용하지 않는다.

### M3: 로컬 생성 모델

- 장비·모델·실제 문맥 길이·응답 형식 검증 후 전환한다.
- 로컬 매뉴얼 검색 완료와 완전 오프라인 추론 완료를 따로 선언한다.

## 4. 첫 기술 선택안

- **벡터 저장:** Qdrant Python 로컬 모드. 단일 앱 프로세스가 소유하고 검색은 전용 작업자 하나로 직렬화한다. 모델 요원 검토의 병렬 처리는 유지한다.
- **임베딩 후보:** `intfloat/multilingual-e5-small`. 한국어 신고↔영문 원문 평가를 먼저 수행한다. 성능 부족 시 큰 모델부터 도입하지 말고 자료·용어·후보 선택 실패를 분류한다.
- **키워드 검색:** 검토한 한국어·영어 용어 사전과 BM25. 점수의 단순 합산 대신 순위 기반 RRF로 결합한다.
- **원본 저장:** 기존 PDF·JSONL은 근거 원본, 벡터 DB는 재생성 가능한 검색 산출물이다.
- **후순위:** 재순위 모델, 별도 검색 서버, 외부 프로젝트의 직접 DB 접근, 자동 웹 검색, 내부 매뉴얼 반입.

이 선택의 근거는 [Qdrant 로컬 모드](https://github.com/qdrant/qdrant-client#local-mode), [하이브리드 검색](https://qdrant.tech/documentation/search-tuning/hybrid-search/), [E5 모델 설명](https://huggingface.co/intfloat/multilingual-e5-small/blob/main/README.md)이다. 특정 모델이 HAEON에서 더 정확하다는 실측 근거는 아직 없다.

## 5. 일정과 난이도 — 작업량 추정

- M1: 환경 준비·검색 평가·앱 회귀를 포함해 **약 2~4 작업일**. 기존 6~12시간 추정은 선별 요약의 단순 연결 범위였으며, 이번 벡터 검색·색인 관리 범위에는 그대로 적용하지 않는다.
- M2: 전체 페이지 처리 상태 점검과 핵심 절 확대에 **추가 약 2~5 작업일**. 모든 페이지의 전문 운용 검토는 별도이며 이 시간으로 완료를 보장하지 않는다.
- M3: L1 장비 측정 후 재산정한다. 모델 다운로드 시간·장비 성능·외부 검토 대기는 위 추정과 별개다.
- 가장 어려운 부분은 PDF 저장이 아니라 조건·예외 보존, 실제 검색 품질, 여러 요원의 근거 일관성이다.

## 6. 출시·복구 기준

- S4 검색 기준과 G3 회귀 기준을 충족하지 못하면 시험 모드로 유지한다.
- 기능 설정 `--manual-search off|lexical|hybrid`를 추가하고 개발 기본값은 `off`로 둔다. 배포 시 시험을 통과한 방식을 명시적으로 선택한다.
- `off`는 기존 기본 매뉴얼·첨부 경로를 유지한다. 오류로 자동 전환할 때에는 `degraded`와 원인을 남겨 정상 hybrid 실행처럼 표시하지 않는다.
- 색인 교체는 새 세대를 완성한 뒤 앱 재시작 시 활성화한다. 진행 중 실행에는 기존 세대가 유지된다.
- 각 작업 완료 시 변경 파일만 검토·커밋한다. 기존 미커밋 변경을 섞지 않고 GitHub 업로드는 별도 요청에 따른다.

## 7. 이번 계획 문서의 검증

- 앱 코드·데이터·의존성·런타임을 변경하지 않는다.
- 작성 후 문서 링크, 계약 이름, 단계별 수용 기준, 코드 변경 여부를 검사한다.
- 구현 시험·새 LIVE·로컬 LLM·브라우저 검증은 이 계획 작성 작업의 결과로 주장하지 않는다.

작성 후 자체 검토에서 사용자 요구를 C1~L2에 연결하고 데이터/함수 이름, 근거 인계, 검색 실패, 버전 교체, 오프라인 경계를 대조했다. 생성 모델·장비는 L1의 명시적 결정 항목으로 남겼다. 계획/안내/인수인계 문서의 로컬 링크 59개가 존재하며, 기존 앱 기준 파일 25개의 해시가 이전 인수인계 기준과 일치한다. 이는 문서 정합성 확인이며 기능 구현 시험이 아니다.
