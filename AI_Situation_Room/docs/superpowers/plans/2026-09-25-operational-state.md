# 신고 기반 상황 갱신 구현 계획

> 과거 구현계획 보존본. 현재 모델·UI·개발 우선순위는 [2026-09-26 인수인계](../../../13_현재상태_요구사항_인수인계.md)를 우선한다. 이 문서의 당시 설정·체크 표시는 최신 전체 검증을 뜻하지 않는다.

Goal: 사용자 승인한 개선 — 신고가 DB/상황판에 반영되고 이름 정정이 실제 필드를 수정한다.
Architecture: 상황실장 plan에 구조화 patch와 선택 배정 결합. 저장소가 버전·인원 합계·세션 소속을 검사하고 적용한다. 단순 접수/정정 tasks=[]는 저장 영수증으로 완료. 분석은 갱신 스냅샷을 기준으로 수행한다.
Tech: 기존 Python/SQLite/JS 유지. 기존 미커밋 변경·발표 보존.
Spec: prototype/scenarios/cheonghae-fire.md 및 사용자 승인한 직전 소감의 개선 방향.

- [x] 상태 patch·멱등·이름 속성 보존·시뮬레이션 격리·합계/버전 충돌 테스트 후 저장 구현.
- [x] 계획 단계 갱신, 선택적 분석, 원문 근거 ID, 축약 입력 테스트 후 연결.
- [x] 상황판 명부/분포/환자 및 변경 이력 표시. 함께 열린 브라우저에서 검증.
- [x] 전체 회귀 및 실제 15건 재시험. 이전 결과와 비교, 남은 한계 기록.

Constraints: 보고는 사용자 출처로 표시, 독립 확인을 꾸미지 않음. 알 수 없는 이름/좌표/상태는 만들지 않음. 가정은 사실에 반영하지 않음. 사용자 원문과 이전 상태를 보존. 합계 불일치는 전체 트랜잭션 거절. 요원에게 전체 assistant history를 중복 전달하지 않고 최신 상황과 원문 근거를 전달.

최종 결과: prototype/scenarios/cheonghae-improvement-results.md. 브라우저를 공유하며 검증했다. 실제 테스트 중 거절된 갱신 1회와 수정 후 재시도를 기록했다.
