# Link-One 환자 알림 구현 계획

사용자 후속 승인: 실제 부하를 확인하고 적절하면 3초 수신 적용. 측정 10회 중앙 105.263ms, 최대 134.135ms, DB 실행 0.234ms. 표본은 최신 7건이며 민감한 원문을 가져오지 않은 집계 시험이다.

**목표:** 연결된 사건의 환자 판정을 서버 하나가 3초 간격으로 확인하고, 변경 결과를 저장·표시하며 사용자가 요청할 때만 AI 검토한다.
**구조:** 기존 SSH 검증 연결을 전용 자식 프로세스에서 유지한다. 매 주기 세션의 room_id를 일괄 조회하고 지문이 변한 사건만 허용된 판정 원문을 읽는다. 자동 모델 호출 없음.
**스택:** 기존 Python HTTP / SQLite / HTML CSS JS. 기존 psycopg 환경 재사용.
**설계:** `docs/superpowers/specs/2026-09-29-linkone-patient-alerts.md`. 최신 사용자 요구로 180초를 3초로 변경한다.

## 고정 조건

- 서버당 작업 하나. 겹치는 요청·누적 큐 없음. 정상 조회 시작 간격 3초, 지연 시 완료 후 다음 주기로 넘기고 밀린 실행은 버린다.
- 지속 연결, 트랜잭션은 조회마다 종료. 오류 시 연결을 버리고 6/12/24/48/60초 후 재시도. 정상 확인 후 3초 복귀.
- 사건 최대 32개, 최신 판정 합계 1,000건, 전송 2MB, 판정당 24KB. 상한 초과는 실패로 표시하고 이전 결과 유지.
- 쿼리 제한 1,500ms, IPC 응답 제한 20초. SSH 자식은 그룹 종료하고 비밀·원문 오류를 로그에 출력하지 않는다.
- 상세 텍스트는 이스케이프. ID는 문자열. 읽음·인용은 판본별 저장. 조회 성공은 환자 상태 최신 판정 보장이 아니다.

## 중점 검증

새 room 추가에 과거 worker 캐시를 잘못 재사용하지 않는지, 다중 세션 삭제가 늦은 수신을 복원하지 않는지, 같은 ID 수정이 읽음과 인용을 초기화하는지, 원격 SQL 실패가 빈 목록이 되지 않는지, UI 세션 전환 중 응답이 다른 사건에 표시되지 않는지 확인한다. 알림 없음·미연결·미수신·연결 실패는 구별한다.

## 실행 기록

172개 Python 전체 시험·JS 문법 통과. 실제 원문 반복 부하시험은 자동 승인 거절되어 비식별 집계로 대체했다. 주기 수신은 실제 빈 사건에서 검증했다. 브라우저 가상 자료 검증 및 리뷰 3건 수정 완료. 상세는 docs/implementation/26-linkone-patient-alerts.md. 실제 환자 원문/UI·장시간·새 LIVE는 미실시다.
