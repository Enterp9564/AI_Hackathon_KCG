# Link-One 환자 알림 연동 설계

상태: **3초 수신·목록/상세·인용 구현, 가상 자료와 실제 빈 사건으로 검증**. 작성일 2026-09-29. 기존 설계에서 최신 사용자 요청에 따라 주기를 변경했다. 세부 구현과 한계는 [구현 기록](../../implementation/26-linkone-patient-alerts.md)을 우선한다.

## 1. 사용자 결정과 목표

- Link-One에 연결된 해온 세션에서 환자 알림을 주기적으로 확인한다.
- 기존 외부 보고의 Link-One 버튼을 빨간색으로 강조한다. 누르면 요약 목록, 항목을 누르면 상세를 플로팅 패널에 표시한다.
- 사용자 확정: **링크온 판정 표시 + 필요할 때 해온 AI 검토**. 주기 확인 자체는 모델을 호출하지 않는다.
- 사용자가 알고 있는 약 3분 주기는 아직 링크온 구현으로 검증되지 않았다. 사용자의 후속 지시에 따라 측정 후 해온 기본 조회 간격을 **3초**로 변경했다. 링크온 생성 주기는 별도다.
- Python HTTP·SQLite·기존 HTML/CSS/JS를 유지한다. 새 외부 DB 쓰기 권한이나 프레임워크는 필요하지 않다.

## 2. 조사 결과와 접근 선택

실제 읽기 전용 DB에서 `patient_ai_analysis`와 상태·구조를 확인했다. 상세는 [원격 데이터 계약 조사](../../contracts/linkone-patient-alerts.md)에 분리했다. 환자 이름·개별 의무 내용·모델 입력을 조사 출력에 포함하지 않았다.

현재 `linkone_source.py`의 허용 필드에는 환자 AI 분석이 없고, `linkone_sync.py`는 수동 전체 수신 후 변경 시 AI까지 실행한다. `static/inbox.js`의 Link-One 버튼은 MCP 수신함을 연다. 이 차이를 해소하기 위해 별도의 3초 환자 분석 조회를 구현했다.

접근 선택:

1. **별도 경량 DB 조회를 권장한다.** 기존 읽기 전용 연결을 재사용하고 환자 분석 결과만 가져온다. 사용자 선택과 일치하며 전체 요원 실행 부하를 만들지 않는다.
2. 기존 전체 동기화를 3분마다 실행하면 명부 전체 수신과 자동 AI 분석까지 반복된다. 이번 요구에는 맞지 않는다.
3. Link-One이 알림 API/MCP 푸시를 제공하는 방식은 장기 확장 후보다. 현재 해당 계약이 확인되지 않아 이번 구현의 전제조건으로 삼지 않는다.

## 3. 주기 조회와 저장

- 대상은 로컬에 저장된 `session.linkone.room_id`가 있는 세션이다. 일반 세션과 MCP 사건 ID만 연결된 세션을 DB 연동 세션으로 취급하지 않는다.
- 서버가 실행되는 동안 최초 한 번, 이후 정상 시 3초 시작 간격으로 연결된 사건을 일괄 조회한다. 느린 조회는 완료 후 3초를 기다리며 밀린 실행은 버린다. 브라우저 탭 수와 무관하게 같은 사건은 한 번만 조회한다.
- 기존 고정 호스트 키·읽기 전용 연결 함수를 공유하되, 알림 전용 프로세스의 연결 하나를 유지한다. 수동 전체 수신의 5초 제한과 분리하며 서버당 알림 작업은 하나만 실행한다. 수동 수신과 겹치면 연결은 두 개일 수 있다. 실제 감지·표시까지는 조회·UI 갱신 시간이 추가된다.
- 서버 정지 시 조회도 정지한다. 재시작하면 저장된 결과와 읽음 상태를 복원하고 다시 확인한다. 세션 삭제 후 늦게 돌아온 응답은 버린다.
- `room_id`를 매개변수로 제한하고 환자별 최신 분석을 조회한다. 이름·현재 상태를 결합할 때도 같은 사건 조건을 적용한다.
- 매 3초 최신 판정의 DB 지문을 비교하고 바뀐 사건만 허용된 필드의 완전 수신본을 받는다. 수신 바이트·행·문자열·시간에 상한을 두고, 상한 초과나 부분 수신이면 이전 성공본을 유지한다. 사건 32개, 최신 판정 합계 1,000건, 응답 2MB, 판정당 24KB, SQL 1,500ms, IPC 20초로 제한한다. 실패 시 6/12/24/48/60초로 재시도 간격을 늘린다.
- SQLite에 세션별 조회 상태와 수신 판정 기록을 저장한다. 식별자는 `(room_id, analysis_id)`이고 bigint는 문자열로 유지한다. 같은 ID의 내용 변경도 해시로 감지해 원본 판본을 보존한다.
- 반복 조회만으로 새 알림·읽지 않음·AI 실행을 늘리지 않는다. 새로운 ID 또는 내용 변경만 새 판정으로 기록한다.
- 세션 `facts`, 상황 버전, 기존 명부 수신본과 분석 결과를 자동 변경하지 않는다. 알림 저장은 별도 데이터다.

## 4. 판정·신선도·읽음의 의미

- 한 환자의 여러 분석을 모두 현재 알림으로 세지 않는다. 목록 기본은 환자별 최신 분석, 이전 결과는 상세 이력이다.
- `status=OK`는 링크온 분석 생성 성공이다. 환자 상태의 사실 확인이나 위험 해소를 의미하지 않는다.
- 최신 결과가 `FAILED`이면 실패를 표시한다. 이전 성공 결과를 보여줄 경우 그 시각과 ‘이전 판정’을 명시한다. 내부 `error` 문자열을 화면에 노출하지 않는다.
- 분석 기준 시각(`based_on_at`)·완료 시각(`finished_at`)·해온 수신 시각을 구별한다. 방금 조회했어도 오래된 판정일 수 있다.
- `based_on_event_id`와 현재 환자 상태의 `last_event_id`가 다르면 ‘판정 이후 상태 변경 가능 · 재분석 확인 필요’를 표시한다. 최근 분석이라고 임의로 해석하지 않는다.
- 읽음은 해당 판본의 상세를 열었음을 뜻한다. 치료 완료·이송 완료·위험 해소나 링크온 측 확인 처리를 뜻하지 않는다. 원격 DB에 acknowledge를 쓰지 않는다.
- 새 판정이 생기면 이전 판정은 이력으로 옮긴다. 원격 최신 목록에서 사라진 항목은 ‘이번 조회에서 미확인’으로 구분하며 위험 해소로 표시하지 않는다.
- 미지원 긴급도·누락 값은 ‘분류 확인 필요’와 원본 코드를 표시한다. 낮은 위험으로 추정하거나 알림에서 숨기지 않는다.
- 연결 실패 시 마지막 성공 결과와 ‘연결 확인 필요’를 함께 표시한다. 실패를 빈 목록이나 0건으로 바꾸지 않는다.
- 임상적인 경보 해제 규칙은 추가하지 않는다. 링크온 판정 결과를 출처와 함께 전달하는 기능이다.

## 5. 버튼과 플로팅 패널

### 버튼

- 기존 위치의 `Link-One` 버튼을 `Link-One 환자 알림`으로 변경한다. 빨간 테두리·어두운 붉은 배경·명확한 텍스트 대비를 사용한다.
- 숫자는 **현재 세션의 미확인 최신 판정 수**다. 총 환자 수나 응급환자 확정 수로 표현하지 않는다.
- 새 판정이 있으면 은은하게 강조한다. `prefers-reduced-motion`에서는 정적 강조만 사용한다.
- 미연결 세션은 ‘미연결’, 조회 전은 ‘확인 전’, 실패는 경고 표시를 사용한다. 이 상태를 0건으로 뭉뚱그리지 않는다.
- 기존 MCP 수신 건수는 패널의 ‘외부 보고(MCP)’ 메뉴에 별도 표시한다. RESAID AI 동작은 유지한다.

### 목록

- 넓은 화면에서는 버튼 부근에 위치하고 화면 가장자리를 넘지 않는 하나의 패널을 연다. 좁은 화면은 하단 패널로 표시한다.
- 상단에 연결 사건명, 마지막 성공 조회, 다음 확인 예정, 연결 상태를 보여준다. 약속한 주기와 실제 시각을 혼동하지 않게 한다.
- 항목은 환자 식별 표시, 링크온 긴급도, 한 줄 요약, 분석 완료 시각, 읽음 여부를 보여준다. 이름이 없으면 ID 일부와 미상 표기를 사용한다.
- 관측된 `IMMEDIATE`를 먼저, `WITHIN_30`을 그다음 표시하는 순서와 원본 코드 표기를 제안한다. 미지원·실패 항목은 별도 ‘확인 필요’ 영역에 두어 누락을 막는다. 의료 처치 기한을 새로 계산하지 않는다.
- ‘아직 분석 결과 없음’, ‘연결 실패 · 이전 결과 표시’, ‘미지원 결과 확인 필요’를 구별한다.

### 상세

- 목록 항목을 누르면 같은 패널의 본문이 상세로 바뀌고 ‘목록으로’가 나타난다. 중첩 팝업을 만들지 않는다.
- 환자·사건·링크온 판정·요약·판정 근거·부족 정보·기준 시각·완료 시각을 표시한다. `pre_ktas`는 원본 출처와 함께 링크온의 참고 분석으로 표시한다.
- 모델명·프롬프트·원시 모델 입력·계정 식별자·내부 오류는 제품 화면에 표시하지 않는다.
- ‘해온에 인용하여 검토’ 버튼으로 현재 사건에서만 추가 검토를 요청할 수 있다. 연결 사건과 기준 시각이 보이고, 오래된 판정은 전송 전에 경고를 유지한다.
- 패널을 닫으면 버튼으로 포커스를 돌린다. Escape·키보드 이동·명시적인 닫기 버튼을 지원한다. 목록 갱신이 현재 상세나 키보드 포커스를 강제로 바꾸지 않는다.
- 세션을 바꾸면 이전 요청 결과를 버리고 패널을 닫는다. 다른 사건의 상세·뱃지·전송 요청이 섞이지 않게 한다.

## 6. 사용자 요청 시 AI 검토

- 기존 채팅 전송과 세션 대기열을 재사용한다. DOM Enter 입력을 흉내 내지 않고, 작성 중인 초안은 보존한다.
- 서버가 저장된 원본 판본으로 인용 메시지를 구성한다. 클라이언트가 보낸 환자·사건·판정 텍스트를 신뢰해 실행하지 않는다.
- 인용에 Link-One 출처, 사건, 분석 ID, 판정 기준/완료 시각, 수신 시각, 요약·근거·부족 정보를 포함한다. ‘링크온 AI 판정이며 현재 환자 상태의 확정 사실은 아님’을 명시한다.
- 원본 텍스트는 자료로 취급하고 그 안의 명령을 실행하지 않는다. 기존 상황실장 배정 → 요원 → 검증 → 종합을 그대로 따른다.
- 같은 세션·같은 분석 판본에 대한 이중 클릭·재전송·응답 유실 재시도는 같은 실행을 돌려준다. 실행 ID와 인용 시각을 남긴다.
- 오래된 명부 수신본과 새로운 환자 판정이 함께 제공되면 각각의 기준 시각을 표시한다. 알림 인용이 전체 명부의 최신 동기화를 뜻하지 않는다.

## 7. 모듈 경계와 검증 순서

원격 수신은 `linkone_source.py`에 제한된 분석 조회를 추가한다. 새 환자 알림 모듈이 정규화·저장·주기 확인·읽음/인용을 담당하고 `server.py`가 세션 API와 생명주기를 연결한다. UI는 별도 알림 JS를 추가하며 `inbox.js`의 버튼 렌더링 충돌을 제거한다. 기존 MCP 수신함과 명부 수동 동기화는 각자의 저장 경로를 유지한다.

구현 순서: 수신 계약·가상 데이터 → 영속 저장·주기 조회 → 알림 목록·상세 → 승인형 AI 인용 → 실연결 검증.

수용 시험:

- 반복 조회·동시 탭·서버 재시작에서 원격 조회와 읽음 상태가 중복되지 않는다. 조회만으로 모델 호출 0회, 상황 버전 변화 0회다.
- 세션 A/B, 삭제 중 수신, 사건 전환 중 느린 응답에서 환자 정보가 섞이지 않는다.
- 실패·빈 결과·과거 기준 사건·알 수 없는 긴급도·최신 분석 실패·대용량 결과가 명시적으로 표시되고 이전 성공본을 보존한다.
- 상세 열기, 목록 복귀, Escape, 모바일 화면, 초안 보존, 이중 클릭 인용, 기존 MCP 접근을 브라우저에서 확인한다.
- 단위/HTTP/브라우저/실제 DB/LIVE 결과를 각각 기록한다. 시험 결과와 미실시 항목은 구현 기록에 구분한다.

## 8. 남은 외부 확인

1. 링크온의 3분 주기가 배치 실행·프런트 갱신·최소 재분석 간격 중 무엇인지 소스 또는 개발자 계약으로 확인해야 한다.
2. 전체 `urgency`/`outcomes`/`pre_ktas.state` 코드와 최신/실패/제외 환자 규칙은 아직 확정 계약을 받지 않았다. 관측된 값이 전체 목록이라고 가정하지 않는다.
3. 기존 테스트 사건에는 새 분석 결과가 없었다. 실제 결과가 있는 연동 사건에서 목록·상세 수용 시험을 해야 한다. 공개 문서에는 환자 자료를 넣지 않는다.

이 확인 전에도 읽기 전용 조회·원본 코드 표시·가상 데이터 UI 검증은 가능하다. 의료적 긴급도 재분류나 분석 결과 없음=정상이라는 동작은 추가하지 않는다.

## 현재 범위의 차이

과거 판정은 로컬 DB에 보존하되 화면의 과거 이력 탐색은 후속이다. 패널은 모달 dialog로 구현했다. 최신 판정은 완료 시각·ID 내림차순으로 선정한다. 실제 판정이 있는 사건의 원문 표시와 새 임상 변경 발생부터 UI 도착까지의 지연, 장시간 부하, 실패 후 실제 네트워크 복구, LIVE 인용은 아직 검증하지 않았다.
