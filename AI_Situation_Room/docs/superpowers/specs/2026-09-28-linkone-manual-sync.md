# 링크온 수동 동기화 설계

사용자 요청: 링크온 상황 선택 → 전용 해온 세션 → 수동 DB 수신 → 이전 수신과 차이 비교 → AI 상황 인식. 자동 폴링은 후속이다. 기존 승인형 MCP 수신은 유지하며 이번 경로는 DB 읽기 연동으로 표시한다.

## 확인한 링크온

제공된 임시 웹 계정으로 로그인해 구조본부 화면을 확인했다. 실상황 목록의 퀸메리호와 여객선 한서호, 명부·구조·중증도·위치·이송 지시·종결지·인수 불가·경사 표시를 확인했다. 퀸메리호 UI는 명부 100/구조 6/미구조 94, 선내 잔류 5/세력 관리 1이다. 상태 미생성자를 UI에서 미구조로 표시함을 확인했지만 미탑승·병합·정정의 모든 도메인 규칙을 검증한 것은 아니다.

## 동작

- 사이드바 ‘링크온 동기화’로 실시간 상황 목록을 조회한다. 이름을 하드코딩하지 않는다. 실상황/훈련·종결 상태를 구분한다.
- 사건 UUID마다 독립 전용 세션 하나를 생성한다. 같은 사건 선택은 기존 세션으로 복귀한다. 다른 일반 세션을 재사용하지 않는다.
- 수신 작업은 비동기이고 실제 단계 문구만 표시한다. 서버 UI 폴링은 원격 DB를 조회하지 않는다.
- 원본 선택 필드·출처·수신시각·해시·수신 차수·변경 전후를 SQLite에 보존한다. 같은 자료는 차수를 늘리거나 AI를 반복 실행하지 않는다.
- 전체 스냅샷을 일관된 읽기 전용 트랜잭션으로 받는다. 조회당 1,000행, 수신 작업 사이 5초(표별 대기는 사용자 요청으로 제거), 전체 행/시간/바이트 상한 초과 시 실패로 처리하고 이전 자료 유지.
- UI에 승선원 검색·구조/중증도/위치, 변경 요약·개인별 전후, 원본 이력·위험 자료를 표시한다. 로그인 비밀·연락처·주소·생년월일·바이너리 미수신.
- 수신 자료의 집계는 별도 ‘링크온 명부 기준’으로 표기한다. 상태 미기록 수, 명부 미확보, 제외/병합을 구분한다. 이름 대신 UUID로 비교한다.
- 사용자 확정: 동기화 후 자동 분석한다. 분석 방식 LIVE/DEMO를 선택한다. 키가 있으면 LIVE 기본, 없으면 DEMO. 신규/변경 수신 후 기존 요원 실행 경로에 출처와 차이를 근거로 전달한다. DEMO를 실제 AI 분석으로 표시하지 않는다.
- 링크온 세션에서는 원본 facts 직접 수정과 모델 갱신을 차단한다. 사용자 질문은 분석/가정으로 받는다. 과거 스냅샷을 최신 근거로 혼합하지 않는다.
- 동기화/AI 진행 중 삭제·중복 동기화 차단. 실패/재시작은 기존 스냅샷 보존 후 재시도 가능. 대형 상황판에도 연동 출처·수신시각 표시.

## 구조

linkone_data.py(정규화·검증·집계·diff·모델 근거), linkone_source.py(SSH 및 DB 수신 프로세스), linkone_sync.py(세션 매핑·영속 저장·작업·AI 연결), static/linkone.js(목록·패널·상세). server/store/engine/tools에 필요한 연결만 추가한다. 소스 조회는 기존 격리 venv를 자식 프로세스로 사용해 앱 실행 Python의 의존성을 바꾸지 않는다.

## 검증

유닛: 다른 사건 혼입 거절, ID 기반 정정/삭제/취소, 미확보 명부, 상태 미기록, 원본 불변, 반복 수신 멱등성, 실패 보존, 재시작, 진행 중 보호, AI 근거 격리/원본 수정 차단.
HTTP: 인증·잘못된 입력·동기화/조회/재분석·기존 API 회귀.
브라우저: 선택→세션→수신/차이/승선원/분석, 오류·빈 값·키보드·모바일·기존 입력 보존.
실제 DB와 DEMO를 우선 검증하고 LIVE는 별도 결과로 기록한다. 외부 DB 쓰기는 하지 않는다.
