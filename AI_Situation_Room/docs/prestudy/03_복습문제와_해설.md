## 문제 — 1일차

**1.** “청해호에서 3명을 동진호로 이송했다”에서 선박명과 이동 인원을 필드로 뽑는 것은 요약, 분류, 정보 추출 중 무엇인가?

**2.** ‘화재’의 토큰 ID가 100, ‘구조’의 ID가 200이다. 구조가 화재보다 두 배 중요하다고 해석할 수 있는가? 토큰 ID와 임베딩의 차이는 무엇인가?

**3.** “기름 유출 있음”과 “기름 유출 없음”이 검색 결과에서 모두 나왔다. 임베딩이 잘못된 것이라고 바로 판단해도 되는가?

**4.** 역할 프롬프트에 “너는 해양 수색구조 전문가다”라고 넣었다. 이 모델을 별도로 전문가 학습시켰다고 설명해도 되는가?

**5.** 토큰 예측에서 ‘8’이 높은 확률을 받았다. 이것을 현실의 승선원이 8명이라는 사실의 높은 신뢰도로 받아도 되는가?

**6.** 사전학습 모델이 있는데도 앱에서 세션별 DB를 유지하고 필요한 기록을 입력에 넣는 이유는 무엇인가?

## 문제 — 2일차

**7.** “14:23 승선원 8명 전원 구조, 선내 잔류 없음”에서 숫자와 불용어를 모두 제거하는 전처리의 문제를 두 가지 말하라.

**8.** 전체 200건에서 TP=30, FP=10, FN=20, TN=140이다. 양성은 화재 관련이다. 정확도·정밀도·재현율·F1을 계산하라.

**9.** 실제 양성이 100건 중 1건이다. 모두 음성으로 예측해 정확도 99%가 나왔다. 이 모델의 양성 재현율은 얼마인가? 왜 정확도만 보면 안 되는가?

**10.** 청해호 최초 신고 10건을 학습 자료에 넣고 같은 사건의 후속 신고 5건을 시험 자료에 넣었다. 새 사건에 대한 실력을 평가하는 데 어떤 문제가 있는가?

**11.** 학습 데이터 120개, 배치 크기 30, 4에포크다. 각 배치마다 한 번 파라미터를 갱신하며 데이터를 버리지 않는다. 1에포크의 배치 수와 총 갱신 횟수는?

**12.** 길이 8토큰의 입력에 폭 3, stride 1, dilation 1, 패딩 없는 CNN 필터를 적용한다. 필터 하나의 출력 길이는? 필터가 4개이고 각 필터에 전체 길이 최대 풀링을 하면 숫자는 몇 개 남는가?

**13.** 에포크가 늘수록 학습 정확도는 계속 오르지만 검증 정확도는 떨어졌다. 가능한 현상 이름과 먼저 할 대응을 말하라.

**14.** 검증 데이터의 결과를 보며 설정을 고르고, 시험 데이터의 결과를 본 뒤 다시 설정을 고치는 일을 반복했다. 마지막 시험 점수를 독립적인 최종 평가라고 해도 되는가?

**15.** 최종 보고가 읽기 좋고 정밀도도 높은 분류기를 썼다. 그럼 기관장 이름 정정·환자 이송 장부도 정확하다고 볼 수 있는가?

## 해설 — 1일차

**1. 정보 추출.** 입력에서 특정 정보를 찾아 구조화하는 작업이다. 전체 문장을 짧게 줄이면 요약, 사건 범주를 부여하면 분류다.

**2. 해석할 수 없다.** 토큰 ID는 구별용 번호다. 임베딩은 학습된 숫자 벡터로, 모델이 관계와 패턴을 처리하는 표현이다. ID의 산술 크기에 의미의 크기가 있는 것은 아니다.

**3. 바로 단정할 수 없다.** 두 문장은 같은 주제를 다뤄 관련 자료 후보로 함께 검색될 수 있다. 검색 단계의 유사성과 판단 단계의 사실 일치는 별개다. ‘없음’을 읽고 현재 상황에 맞는 의미를 확인해야 한다.

**4. 안 된다.** 역할 지시는 이번 호출의 행동을 유도한다. 가중치를 바꾸는 미세조정과 다르다. 현재 프로젝트는 역할 지침과 제공 근거로 전문 검토를 구성한다.

**5. 안 된다.** 다음 토큰 분포는 현실의 사실이 참일 확률과 같지 않다. 사용자 신고나 다른 근거에 8명이 있는지 확인해야 한다.

**6. 모델의 일반 지식과 사건별 기억은 다르기 때문이다.** 오늘 접수한 이름 정정과 구조 위치는 앱이 기록·선별해 제공해야 한다. 다른 사건의 정보가 섞이지 않도록 세션 경계도 필요하다.

## 해설 — 2일차

**7. 인원·시각이 사라지고 부정의 의미도 바뀔 수 있다.** 8명이라는 집계, 14:23이라는 경과, 선내 잔류가 없다는 상태를 보존해야 한다. 무조건 지우는 대신 작업에 필요한 정보인지 판단한다.

**8. 계산:**

```text
전체 = 30 + 10 + 20 + 140 = 200
정확도 = (30 + 140) / 200 = 85%
정밀도 = 30 / (30 + 10) = 75%
재현율 = 30 / (30 + 20) = 60%
F1 = 2 × 0.75 × 0.60 / (0.75 + 0.60)
   ≈ 66.7%
```

**9. 재현율 0%.** 실제 양성 1건을 놓쳤다. 대부분인 음성을 맞히는 것만으로 전체 정확도가 높아질 수 있으므로 양성의 놓침과 오탐을 따로 본다. 양성 예측이 아예 없을 때 정밀도는 분모가 0이므로 평가 정책을 명시해야 한다.

**10. 같은 사건의 내용이 양쪽에 걸쳐 있다는 점.** 공유되는 이름·맥락·반복 문장 때문에 새로운 사건보다 쉬운 시험이 될 수 있다. 새 사건 일반화를 보려면 사건 단위로 묶어 분할하고, 시간에 따른 예측에서는 미래 정보가 과거 입력에 섞이지 않게 한다.

**11. 1에포크 4배치, 총 16회 갱신.** 120÷30=4, 4×4=16이다. 기울기 누적 등 다른 설정이 있으면 갱신 횟수가 달라질 수 있지만 문제는 매 배치 갱신 조건이다.

**12. 출력 길이 6, 풀링 후 숫자 4개.** 8−3+1=6개 위치다. 필터마다 점수 6개를 만들고 각 필터에서 최댓값 하나를 택하므로 필터 4개면 4개 값이 남는다.

**13. 과적합 가능성.** 마지막 모델을 자동으로 선택하지 않고 검증 성능이 좋았던 시점, 조기 종료, 정규화, 데이터 품질·양 등을 검토한다. 먼저 데이터와 측정 오류도 확인한다.

**14. 독립적인 최종 평가로 보기 어렵다.** 시험 결과로 반복해서 선택했으므로 시험 데이터에도 맞춰진다. 설정 탐색은 검증 분할에서 하고 최종 시험은 별도로 유지한다.

**15. 아니다.** 분류 점수·문장 유창성과 장부 정정의 정확성은 다른 기준이다. 이름 필드, 속성 보존, 환자 위치, 총원 합계 등을 직접 검사해야 한다.

## 한 사건으로 끝내는 10분 연습

다음은 직접 만든 축약 연습이다. 실제 청해호 15단계 시험의 재현 결과가 아니다.

**입력 A:** “어선에 검은 연기. 선명과 승선 인원 확인 중.”

할 일: 알고 있는 정보 두 개, 모르는 정보 두 개, 질문 두 개와 각각 필요한 이유를 적는다.

예시 답: 어선·검은 연기는 신고됨. 현재 위치·총원은 미확인. “현재 위치는 어디인가요? 현장 접근 검토의 기준이 필요합니다.” “승선 인원과 대피 상태는 어떤가요? 인명 위험 규모를 파악해야 합니다.” 정답 문장은 하나가 아니지만 신고에 없는 사실을 만들지 않아야 한다.

**입력 B:** “총 8명. 3명은 지원선으로 이송했고 5명은 사고선박에 남아 있다.”

할 일: 현재 분포의 합계를 계산하고, 추가로 어떤 상태가 불명확한지 적는다.

예시 답: 3+5=8. 이송 보고와 선내 잔류는 구별된다. 부상 상태·대피 안전·지원선 이름 등은 추가 정보이며 한꺼번에 모두 묻기보다 현재 판단에 필요한 것을 고른다.

**입력 C:** “기관장 이름은 이기란이 아니라 이기관. 다른 정보는 유지.”

할 일: 바꿀 필드와 유지할 필드를 구별한다.

예시 답: 동일 인물의 name을 이기관으로 갱신하고 기존 ID·직책·위치·상태를 보존한다. 원문과 변경 이력은 남긴다. 이전에 없는 위치·건강 정보를 새로 만들어 넣지는 않는다.

**평가 기준:** A는 미확인 정보와 질문 이유, B는 인원 합계와 분포, C는 이름 변경과 속성 보존이다. ‘좋은 답변인가’라는 한 가지 느낌으로 평가하지 않는다.

## 강의 중 물어볼 질문

### 1일차

- 한국어 토큰화에서 형태소 분석과 부분단어 방식은 어떤 경우에 다르게 선택하나요?
- 이번 실습에서 사용하는 모델·토크나이저와 입력 길이 제한은 무엇인가요?
- 프롬프트 개선, 검색 근거 추가, 미세조정 중 어느 방법이 필요한지 어떻게 판단하나요?
- 모델이 출력한 신뢰도와 실제 정답률을 어떻게 구별하나요?

### 2일차

- 같은 사건의 연속 기록은 학습·시험 분할에서 어떻게 묶어야 하나요?
- 희귀한 사고 유형의 누락을 평가하려면 어떤 지표를 함께 봐야 하나요?
- 숫자·시각·부정 표현을 보존하려면 전처리를 어떻게 점검하나요?
- CNN 필터의 폭과 풀링이 문장 순서·장거리 문맥에 어떤 영향을 주나요?
- 이번 실습의 분류 성능을 실제 업무 데이터로 확인하려면 무엇이 더 필요한가요?

## 수업 직전 1분 요약

- 토큰화는 단위를 나누고, 임베딩은 숫자 표현을 만든다.
- 언어모델의 자연스러운 문장은 사실 확인을 대신하지 않는다.
- 프롬프트·자료 제공·세션 저장과 모델 학습은 구별한다.
- 전처리로 숫자·부정·정정 정보를 잃지 않는다.
- 학습·검증·시험을 분리하고 같은 사건의 누수를 경계한다.
- 정확도는 전체 정답, 정밀도는 양성 예측의 정확함, 재현율은 실제 양성의 탐지 비율이다.
- CNN은 연속 토큰 패턴을 훑고 특징을 모아 분류에 활용할 수 있다.
- 우리 앱은 유창성뿐 아니라 정정·인원·근거·질문·지연을 따로 검증한다.
