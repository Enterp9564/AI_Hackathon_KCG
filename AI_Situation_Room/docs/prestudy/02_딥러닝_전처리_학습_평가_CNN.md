## 1. 딥러닝은 무엇을 학습하는가

신경망은 입력 숫자를 여러 계산 단계에 통과시켜 출력을 만든다. 그 과정의 조절 가능한 숫자를 **파라미터(parameter)**라고 한다. 가중치와 편향이 대표적이다.

신고를 ‘화재 관련 / 비화재’로 나누는 교육용 분류기를 생각해 보자.

```text
신고 문장 → 토큰 → 임베딩 → 신경망 → 화재 관련 점수 → 범주 선택
```

**입력 X**는 신고 문장, **정답 y**는 미리 정한 라벨이다. 모델의 예측과 정답이 얼마나 다른지 나타내는 **손실(loss)**을 줄이도록 파라미터를 조정한다.

‘AI가 배운다’는 것은 여기서는 데이터를 보면서 내부 계산에 쓰이는 숫자를 조정한다는 뜻이다. 코드에 사례 하나를 if문으로 추가하는 것과 다르다.

### 딥러닝이 항상 먼저 필요한 것은 아니다

정확한 합계 계산이나 고정 형식 검사는 간단한 코드로 처리할 수 있다. 반대로 여러 표현으로 들어오는 신고의 의미를 파악하는 일은 데이터 기반 모델이 도움이 될 수 있다. 작은 기준 모델이나 규칙과 비교해야 더 복잡한 모델의 이득을 알 수 있다.

## 2. 텍스트 전처리: 정보를 지우는 작업이 아니다

전처리는 데이터를 모델이 일관되게 읽을 수 있도록 준비하는 과정이다. 공백 정리, 인코딩 확인, 토큰화, 길이 조정 등을 포함한다. 필요한 처리 방식은 작업과 모델마다 다르다.

### 먼저 원문을 보존한다

가상 원문:

> “14:12  동진호에 3명 이송. 기름 유출 없음!!  청해호 5명 잔류.”

중복 공백을 하나로 줄이는 것은 가능하다. 그러나 숫자·시각·‘없음’을 일괄 삭제하면 중요한 정보가 사라진다.

```text
원문: 기름 유출 없음
잘못된 처리: 기름 유출
결과: 부정이 사라져 반대 의미로 읽힐 수 있음
```

### 전처리할 때 판단할 항목

- **공백·줄바꿈:** 불필요한 중복은 정리할 수 있지만 문서 구조나 문장 구분은 보존한다.
- **구두점:** 감정 분류에서는 느낌표가 유용할 수 있다. 업무 기록에서는 마침표·슬래시가 경계를 나타낼 수 있다.
- **숫자·단위:** 인원·거리·시간·풍속처럼 업무 핵심이면 지우지 않는다.
- **불용어(stopwords):** 자주 나오지만 일부 작업에서 덜 유용한 단어다. 목록을 그대로 적용하지 말고 ‘아니’, ‘없음’ 같은 의미를 검사한다.
- **이름·식별자:** 오타처럼 보여도 원문 근거 없이 자동 치환하지 않는다.
- **형태소·부분단어:** 사용하는 모델과 전처리 체계에 맞춘다. 사전학습 모델에는 보통 그 모델과 짝인 토크나이저를 사용한다.
- **중복 자료:** 같은 기록의 복제인지, 실제 반복 신고인지 구별한다.

### 패딩과 잘라내기

여러 문장을 한 묶음으로 계산할 때 길이를 맞추려고 짧은 문장 뒤에 **패딩(padding)**을 붙일 수 있다. 모델이 이를 실제 내용으로 잘못 쓰지 않도록 처리해야 한다. 긴 문장을 제한 길이에서 자르는 것은 **잘라내기(truncation)**다.

우리 사건에서는 문장 끝의 “앞의 7명을 8명으로 정정”이 가장 중요할 수 있다. 앞부분만 남기는 정책은 정정을 잃을 수 있다. 길이를 줄일 때 무엇이 사라지는지 실제 사례로 확인해야 한다.

**손으로 해보기:** “14:23 8명 전원 구조, 선내 잔류 없음”에서 삭제하면 안 되는 정보를 다섯 가지 이상 찾아보자. 시각, 총원, 전원 구조, 선내라는 범위, 잔류 없음 등이 해당한다.

## 3. 학습·검증·시험 데이터를 나누는 이유

시험문제와 정답을 외운 사람이 새 문제도 잘 푸는지는 별도 확인해야 한다. 모델도 마찬가지다.

1. **학습 데이터(train):** 파라미터를 바꾸는 데 사용한다.
2. **검증 데이터(validation):** 설정·모델·학습 종료 시점을 고르는 데 사용한다.
3. **시험 데이터(test):** 선택을 끝낸 뒤 새로운 데이터에서 성능을 평가한다.

예를 들어 70/15/15로 나눌 수 있지만 정해진 정답 비율은 아니다. 데이터 크기, 희귀 사고의 수, 시간 순서, 실제 사용 목적을 고려한다. 시험 결과를 보고 계속 모델을 고치면 그 시험 데이터도 사실상 선택에 사용한 셈이다.

### 우리 프로젝트에서 특히 중요한 데이터 누수

같은 청해호 사건의 최초 신고를 학습에, 이름만 약간 바꾼 후속 신고를 시험에 넣었다고 하자. 서로 많은 내용이 겹치므로 완전히 새로운 사건에 대한 성능보다 좋아 보일 수 있다.

**데이터 누수(data leakage)**는 실제 예측 때 알 수 없는 정보나 시험 정보가 학습·선택 과정에 흘러드는 문제다.

- 같은 사건의 기록이 학습과 시험에 섞임.
- 거의 같은 문장 복사본이 양쪽에 존재함.
- 전체 자료를 보고 단어 사전·통계·특징 선택을 먼저 계산함.
- 최초 신고를 판단하면서 나중의 최종 구조 결과를 입력에 넣음.

원칙적으로 같은 사건의 관련 기록을 같은 분할에 묶고, 시간에 따라 예측하는 업무라면 과거로 학습하고 미래로 평가하는 방식도 검토한다. 학습 데이터에서 계산해야 하는 전처리 통계는 학습 분할에서만 구한다.

## 4. 훈련은 어떤 순서로 진행되는가

```text
데이터 일부 선택
 → 모델 예측
 → 정답과 비교해 손실 계산
 → 각 파라미터가 손실에 미친 영향을 계산
 → 파라미터 조정
 → 다음 데이터로 반복
```

**순전파(forward)**는 입력으로 예측을 만드는 계산이다. **역전파(backpropagation)**는 손실에 대한 파라미터의 기울기를 계산하는 과정이다. **옵티마이저(optimizer)**는 이 기울기를 이용해 파라미터를 갱신한다. 역전파와 실제 갱신은 구별되는 단계다. [PyTorch 학습 안내](https://docs.pytorch.org/tutorials/beginner/introyt/trainingyt)

### 자주 나오는 다섯 단어

- **배치(batch):** 한 번의 계산에 함께 사용하는 데이터 묶음.
- **에포크(epoch):** 학습 데이터 전체를 한 번 훑는 단위.
- **학습률(learning rate):** 파라미터를 조정하는 보폭을 결정하는 설정.
- **손실 함수(loss function):** 예측이 정답과 얼마나 어긋났는지 계산하는 방식.
- **하이퍼파라미터(hyperparameter):** 학습률·배치 크기·층 수처럼 학습 절차나 구조에 대해 정하는 값.

모델이 학습으로 바꾸는 가중치는 파라미터이고, 사람이 설정하거나 탐색하는 학습률은 하이퍼파라미터다.

### 간단한 계산

학습 문장 100개, 배치 크기 20, 마지막 데이터를 버리지 않는다고 하자.

- 1에포크: 배치 5개 처리.
- 3에포크: 배치 처리 15회.
- 매 배치마다 한 번 갱신하는 단순 설정이면 파라미터 갱신 15회.

### 너무 오래 학습하면 항상 좋은가

아니다. **과적합(overfitting)**은 학습 자료에는 잘 맞지만 새로운 자료에는 잘 일반화하지 못하는 상태다.

가상의 예에서 학습 정확도가 70→90→99%로 오르는데 검증 정확도는 68→80→73%로 떨어진다면 마지막 모델을 무조건 고르면 안 된다. 검증 성능에 따라 조기에 멈추거나 데이터·모델 크기·정규화 등을 검토한다.

반대로 학습·검증 모두 낮다면 **과소적합(underfitting)**, 라벨 문제, 표현 부족, 학습 설정 문제 등 여러 가능성이 있다. 숫자 하나만으로 원인을 확정하지 않는다.

**학습과 추론 구별:** 이미 학습된 모델을 API로 호출해 보고서를 받는 것은 추론이다. 우리 앱에서 세션 기억을 저장하는 것도 곧바로 모델 가중치를 학습하는 것은 아니다.

## 5. 평가: 정확도 하나로 충분하지 않다

다음은 ‘화재 관련 신고를 탐지하는 분류기’의 가상 결과다. 양성은 화재 관련으로 정의한다.

- 실제 화재 관련 20건 중 15건을 찾아내고 5건을 놓쳤다.
- 실제 비화재 80건 중 10건을 화재 관련으로 잘못 알리고 70건을 맞혔다.

```text
TP(정탐) = 15 : 실제 양성이고 양성으로 예측
FN(미탐) =  5 : 실제 양성인데 음성으로 예측
FP(오탐) = 10 : 실제 음성인데 양성으로 예측
TN(정상 음성 판정) = 70 : 실제 음성이고 음성으로 예측
전체 = 100건
```

이 네 숫자를 정리한 것이 혼동행렬(confusion matrix)의 기본 구성이다. 무엇을 양성으로 정의했는지 반드시 먼저 밝힌다.

### 정확도 — 전체에서 얼마나 맞혔는가

```text
Accuracy = (TP + TN) / 전체
         = (15 + 70) / 100 = 85%
```

한계: 실제 화재가 100건 중 1건이면 전부 ‘비화재’라고 하는 모델도 정확도 99%다. 중요한 사건은 하나도 찾지 못했다. 이런 상태를 **클래스 불균형**과 함께 살펴봐야 한다.

### 정밀도 — 화재라고 알린 것 중 얼마나 맞는가

```text
Precision = TP / (TP + FP)
          = 15 / 25 = 60%
```

정밀도가 낮으면 오탐으로 인한 불필요한 확인이 늘어난다.

### 재현율 — 실제 화재 중 얼마나 찾았는가

```text
Recall = TP / (TP + FN)
       = 15 / 20 = 75%
```

재현율이 낮으면 중요한 사건을 놓친다. 놓침의 비용이 큰 업무에서는 특히 주의하지만, 무조건 모든 것을 화재라고 표시해 경보를 늘리는 것이 해결책은 아니다.

### F1 — 정밀도와 재현율을 함께 보기

```text
F1 = 2 × Precision × Recall / (Precision + Recall)
   = 2 × 0.60 × 0.75 / 1.35 ≈ 0.667 = 66.7%
```

F1은 두 값의 조화평균이다. 정밀도·재현율이 크게 불균형하면 그 영향을 받는다. TN은 직접 포함하지 않으며 모든 업무 비용을 대표하지도 않는다. 분모가 0인 경우의 처리 규칙도 평가 때 정해야 한다. 정의 확인: [scikit-learn 평가 지표 문서](https://scikit-learn.org/stable/modules/model_evaluation.html).

### 임계값을 바꾸면

분류 점수가 일정 기준 이상이면 양성이라고 결정할 수 있다. 같은 점수를 유지한 채 기준을 낮추면 더 많은 건이 양성으로 분류돼 재현율은 낮아지지 않지만 오탐이 늘 수 있다. 정밀도는 데이터에 따라 달라지므로 매번 확인해야 한다.

업무상 놓침과 오탐의 비용을 고려해 검증 데이터에서 기준을 선택한다. 모델의 점수가 현실 사건의 정확한 확률인지도 별도 문제다.

### 선택 학습: 범주가 여러 개라면

화재·충돌·침수 등을 각각 평가할 수 있다. **Macro F1**은 범주별 F1을 같은 비중으로 평균낸다. **Weighted F1**은 각 범주의 사례 수로 가중한다. 큰 범주가 전체 점수를 지배할 수 있으므로 희귀 범주의 점수도 함께 읽는다. 하나의 사고에 화재와 침수가 동시에 있으면 한 범주만 고르는 다중분류보다 여러 라벨을 허용하는 문제가 맞을 수 있다.

## 6. CNN이 문장을 읽는 방법

CNN은 **Convolutional Neural Network**, 합성곱 신경망이다. 이미지뿐 아니라 텍스트의 국소 패턴을 찾는 데도 사용할 수 있다. 대표적인 문장 분류 연구는 단어 벡터 위에 합성곱 필터와 풀링을 적용한다. [Kim의 문장 분류 CNN 논문](https://arxiv.org/abs/1408.5882)

### 문장을 행렬로 만들기

교육용으로 토큰 6개, 토큰마다 숫자 4개의 임베딩이 있다고 하자. 입력은 6×4 행렬이다.

```text
[기관실] → 숫자 4개
[화재]   → 숫자 4개
[발생]   → 숫자 4개
[선원]   → 숫자 4개
[선수로] → 숫자 4개
[대피]   → 숫자 4개
```

실제 모델에서는 토큰 분할과 임베딩 크기가 다를 수 있다. 여기서는 모양을 이해하기 위한 예시다.

### 작은 창으로 연속 표현을 훑기

폭 3토큰의 필터를 한 칸씩 이동시키면 다음 네 구간을 본다.

```text
1. 기관실 / 화재 / 발생
2. 화재 / 발생 / 선원
3. 발생 / 선원 / 선수로
4. 선원 / 선수로 / 대피
```

필터는 각 구간의 숫자에 같은 가중치를 적용해 특징 점수를 만든다. ‘같은 계산 규칙을 문장의 여러 위치에서 쓴다’는 점이 핵심이다. 사람이 모든 필터를 ‘화재 전용’, ‘대피 전용’으로 직접 지정하는 것은 아니다. 유용한 패턴은 학습 과정에서 형성된다.

### 풀링으로 대표 특징 모으기

한 필터의 가상 점수가 다음과 같다고 하자.

```text
네 구간의 점수 = [0.1, 0.8, 0.3, 0.6]
최대 풀링(max pooling) 결과 = 0.8
```

여러 위치에서 얻은 값 중 최댓값을 대표로 택한다. 여러 필터의 결과를 모아 분류 층에 전달하면 범주별 점수 등을 만들 수 있다. 전체 문장에 대한 최대 풀링은 특징이 어느 정확한 위치에 있었는지에 관한 정보를 줄일 수 있다.

### 모양을 직접 계산하기

조건은 토큰 수 6, 임베딩 4차원, 필터 폭 3, 이동 간격(stride) 1, 패딩 없음, 확장 간격(dilation) 1이다.

```text
필터가 놓이는 위치 수 = 6 - 3 + 1 = 4
필터 1개 → 점수 4개
필터 2개 → 각각 점수 4개
각 필터에 전체 길이 최대 풀링 → 숫자 2개
그 숫자 2개를 분류 층의 입력으로 사용
```

이 조건이 바뀌면 출력 길이도 달라진다. 라이브러리마다 차원 배치 표기가 다를 수 있으므로 강의 코드에서는 배치·채널·길이 축을 확인한다.

### CNN의 장점과 한계

짧은 연속 표현의 패턴을 이용하는 분류에 유용한 구조다. 하지만 멀리 떨어진 정정과 이전 신고를 연결하는 문제는 단순한 얕은 CNN과 전체 최대 풀링만으로 충분하지 않을 수 있다.

“처음에는 7명이라고 했지만 선장을 포함하면 8명”에서는 화재 단어가 있는지만 찾는 것보다 현재 유효한 숫자를 선택하는 문제가 중요하다. CNN을 배운다고 현재 앱 전체를 CNN으로 바꿀 필요는 없다. 신고 분류 보조 기능으로 검토하고 실제 자료에서 비교할 수 있다.

## 7. 분류 지표를 우리 앱 평가로 확장하기

화재 분류의 F1과 최종 보고서의 품질은 같은 것이 아니다. 우리 앱에는 업무별 검사가 필요하다.

### 교육용 평가 설계 예

**정보 추출:** 선박명·현재 총원·잔류 인원·환자 위치를 정답과 대조한다. ‘모름’을 허용한 항목과 정답이 있는 항목을 구별한다.

**정정:** 기관장 이름을 바꿨을 때 직책·위치·상태가 유지되는지 검사한다. 이름만 맞고 다른 필드가 손실되면 통과가 아니다.

**요약:** 전원 구조·잔류 열기·침수 의심·예인 대기 등 필수 사실을 빠뜨리지 않는지 확인한다. 반드시 필요한 정보 목록을 사람이 먼저 정한다.

**질문:** 이미 받은 것을 반복하지 않는지, 지금 판단에 필요한지, 이유가 있는지 평가한다. 질문이 적다는 사실만으로 좋은 질문은 아니다.

**지연·자원:** 최초 배정, 첫 요원 보고, 최종 응답 시간을 따로 잰다. 전체 토큰과 호출 수도 함께 기록한다.

### 비교 실험의 최소 조건

- 같은 사건과 같은 제공 근거를 사용한다.
- 원하는 출력과 평가 기준을 고정한다.
- 코드·모델·설정·날짜를 기록한다.
- 실패와 재시도도 기록한다.
- 비교에 쓰지 않은 사건에서도 확인한다.

청해호 1개 사건의 최종 상태가 맞았다는 것은 가치 있는 확인이다. 그러나 모든 새로운 사건에서 정확하다거나 여러 에이전트가 단일 모델보다 우수하다고 결론 내릴 수는 없다.

## 8. 수업 코드에서 볼 순서

프레임워크가 무엇이든 다음 질문을 순서대로 따라가면 흐름을 놓치기 어렵다.

1. 입력 문장과 정답 라벨은 어디에서 오는가?
2. 학습·검증·시험 자료가 섞이지 않았는가?
3. 토큰 ID와 패딩은 어떻게 만들었는가?
4. 모델 입력과 출력의 숫자 배열 모양은 무엇인가?
5. 손실을 계산하는 정답은 무엇인가?
6. 어느 줄에서 기울기를 계산하고 가중치를 바꾸는가?
7. 평가 때 가중치를 바꾸지 않는가?
8. 어떤 지표로 성공을 판단하는가?

PyTorch가 쓰인다면 `model.train()`과 `model.eval()`은 일부 층의 동작을 바꾸는 모드 전환이며, `eval()`만으로 기울기 계산이 자동 중지되는 것은 아니라는 점을 알아두면 좋다. 구체 코드는 강의 환경을 따른다. [PyTorch 기초 학습 경로](https://docs.pytorch.org/tutorials/beginner/basics/intro)
