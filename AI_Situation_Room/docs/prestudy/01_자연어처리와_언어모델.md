## 1. 자연어 처리는 무슨 일을 하는가

자연어는 사람이 일상에서 사용하는 한국어·영어 같은 언어다. 자연어 처리(NLP)는 컴퓨터가 이 언어를 분석하거나 생성하도록 만드는 분야다.

다음 신고 한 문장으로 생각해 보자.

> “묵호 동방 5해리에서 어선에 검은 연기가 보이고 승선 인원은 확인 중입니다.”

같은 문장을 처리해도 목표에 따라 다른 작업이 된다.

- **분류:** 이 신고가 화재 관련인지, 충돌 관련인지 분류한다.
- **정보 추출:** 위치는 ‘묵호 동방 5해리’, 선박 종류는 ‘어선’, 승선 인원은 ‘미확인’으로 정리한다.
- **개체명 인식:** 문장에서 지명·사람·선박 등 개체의 표현을 찾는다.
- **요약:** “어선 검은 연기 신고, 인원 미확인”으로 줄인다.
- **질의응답:** “승선 인원이 확인됐는가?”에 답한다.
- **생성:** 추가 확인할 질문이나 보고 문장을 작성한다.

모두 NLP지만 평가 기준은 다르다. 분류는 범주를 맞히는지, 추출은 필드가 정확한지, 요약은 중요한 내용과 불확실성을 보존하는지 확인한다.

### 왜 어려운가

다음은 단어 몇 개가 바뀌었을 뿐이지만 의미가 크게 다르다.

- “기름 유출이 **있다**.”
- “기름 유출은 **없다**.”
- “기름 유출이 **의심된다**.”
- “기름 유출이 있었으나 **차단됐다**.”

‘기름’과 ‘유출’을 찾는 규칙만으로 현재 상태를 결정하면 틀릴 수 있다. 부정, 시점, 확실성까지 해석해야 한다. 우리 상황실에서 출동안이 반복되는 문제도 이런 구분과 연결된다.

### 연구 방식은 어떻게 바뀌었나

크게 보면 사람이 규칙을 작성하는 방식에서, 데이터로 통계적 패턴을 학습하는 방식, 신경망으로 표현을 함께 학습하는 방식, 큰 사전학습 모델을 여러 작업에 활용하는 방식으로 발전했다. 이것은 이해를 돕는 흐름이며 이전 방식이 모두 사라졌다는 뜻은 아니다.

실제 제품은 혼합한다. AI가 신고를 해석하고 프로그램이 ‘구조 인원이 총원을 넘는지’를 계산하는 방식이 한 예다. 정해진 산술 검사까지 전부 언어모델에 맡길 필요는 없다.

**확인 질문:** 신고를 유창하게 요약하면 위치·인원 추출도 항상 정확할까? 그렇지 않다. 서로 다른 능력과 평가가 필요하다.

## 2. 언어모델의 네 요소: 데이터 → 토큰화 → 임베딩 → 모델

문장을 그대로 계산할 수는 없으므로 컴퓨터가 처리할 숫자로 표현한다.

```text
사람의 문장
  → 토큰 단위로 분리
  → 각 토큰의 ID
  → 토큰 ID를 벡터로 변환
  → 모델이 문맥 처리
  → 분류 점수 또는 다음 토큰의 확률 등
```

### 데이터: 무엇을 보고 배웠는가

모델 학습에 사용하는 글 묶음을 **말뭉치(corpus)**라고 한다. 데이터는 양만큼 내용도 중요하다.

- 맞는 정보와 잘못된 정보가 함께 있을 수 있다.
- 같은 문서가 반복되면 특정 표현을 과도하게 배울 수 있다.
- 일반 문서가 많고 해상 신고가 적으면 현장 표현에 약할 수 있다.
- 과거 자료만 배웠다면 현재 가용 함정이나 최신 상황을 알 수 없다.

**사전학습 데이터와 지금 입력한 신고는 다르다.** 대화에 신고를 넣으면 이번 응답의 입력이 되지만, 일반적인 추론 호출에서 곧바로 모델의 가중치가 바뀌는 것은 아니다.

### 토큰화: 계산할 단위로 나누기

토큰(token)은 모델이 입력·출력을 처리하는 단위다. 단어 전체일 수도, 단어 조각일 수도, 문자·구두점·바이트에 기반한 단위일 수도 있다. ‘한국어 한 글자 = 한 토큰’으로 고정되지 않는다.

```text
문장: 청해호 승선원은 8명이다.
교육용 분해 예: [청해] [호] [승선] [원] [은] [8] [명] [이다] [.]
```

위 분해는 설명용 예시다. 실제 사용 모델의 토크나이저 출력은 아니다.

토큰마다 ID가 붙지만 ID의 크기가 의미의 크기는 아니다. 예를 들어 ‘화재’의 ID가 27, ‘구조’의 ID가 91이라 해도 구조가 화재보다 더 크거나 중요하다는 뜻은 없다. 사전에서 찾기 위한 번호와 비슷하다.

한국어는 ‘승선원’, ‘승선원은’, ‘승선원이’처럼 조사·어미가 결합한다. 형태소 분석은 의미·문법 단위로 나누려는 방법이고, 부분단어 토큰화는 모델에 적합한 반복 조각을 사용하는 방법이다. 둘은 같은 작업이 아니다.

**우리 앱과 연결:** 이름 이기란→이기관을 고칠 때 토큰 분할이 비슷하다는 이유로 동일 인물임을 확정하면 안 된다. 사용자 정정과 저장된 인물 ID가 중요하다.

## 3. 임베딩: 번호를 관계가 있는 숫자 표현으로 바꾸기

**벡터(vector)**는 숫자를 순서대로 나열한 것이다. **차원(dimension)**은 그 숫자의 개수다.

```text
[0.2, -0.7, 0.4]  → 숫자 3개이므로 3차원 벡터
```

임베딩(embedding)은 단어나 문장 같은 대상을 학습된 벡터로 표현한다. 잘 학습된 표현에서는 관련 표현들이 비교 가능한 관계를 갖는다. 다만 벡터 한 칸이 ‘화재 위험’, 다른 칸이 ‘구조 중요도’처럼 사람이 정한 의미를 가진다고 생각하면 안 된다.

### 원핫과 임베딩의 차이

표현할 단어가 화재·연기·구조 세 개뿐이라고 가정하자.

```text
원핫 표현
화재 = [1, 0, 0]
연기 = [0, 1, 0]
구조 = [0, 0, 1]
```

각 단어를 구별할 수 있지만 이 표현 자체에는 화재와 연기의 관련성이 들어 있지 않다. 임베딩은 데이터에서 유용한 관계를 학습해 밀집된 숫자 표현에 담는다. 숫자가 적다고 언제나 더 정확한 것은 아니며 목적과 학습 결과가 중요하다.

### 단어의 비슷함과 사실의 같음은 다르다

“유출 있음”과 “유출 없음”은 주제와 단어가 비슷하다. 검색용 벡터에서도 가까울 수 있지만 대응에 필요한 의미는 반대다.

따라서 임베딩 검색은 관련 후보를 찾는 수단이다. 검색 결과가 실제로 질문에 답하는지, 부정 표현이 있는지, 최신 기록인지 다시 확인해야 한다.

### 보충: Word2Vec와 문맥에 따른 표현

Word2Vec는 주변 단어를 이용해 단어 벡터를 학습하는 대표적 방법이다. CBOW는 주변 단어로 중심 단어를, Skip-gram은 중심 단어로 주변 단어를 예측하도록 학습한다. 전형적인 Word2Vec 표현에서는 같은 단어가 문맥마다 별도 벡터로 바뀌지는 않는다. [원 논문](https://arxiv.org/abs/1301.3781)

‘배를 구조했다’와 ‘배를 먹었다’의 ‘배’는 다르다. 문맥을 처리하는 언어모델의 내부 표현은 주변 토큰에 따라 달라질 수 있다. 그렇다고 모든 중의성을 항상 해결하는 것은 아니다.

Word2Vec의 수식이나 구현을 외우는 것보다 **학습된 숫자 표현을 사용한다**, **문맥을 반영하는 방식에 차이가 있다**는 점을 기억하자.

## 4. 언어모델: 다음에 무엇이 올지 예측하기

생성형 언어모델을 이해할 때는 ‘지금까지의 토큰을 보고 다음 토큰의 확률을 계산한다’는 출발점이 유용하다. 모든 언어모델이 같은 학습 목표를 쓰는 것은 아니다.

```text
입력: 승선원은 총
다음 후보: 8 / 7 / 몇 / ...
```

여러 후보 중 하나를 선택해 붙이고, 길어진 문맥을 보고 다시 다음 토큰을 고른다. 이 과정이 이어져 보고서나 코드가 된다.

가상의 후보 확률이 8에 0.5, 7에 0.3, 기타에 0.2라고 해도 ‘승선원이 실제 8명일 확률 50%’라는 뜻은 아니다. 이것은 해당 문맥에서 다음 토큰을 생성할 모델의 분포다. 현실의 사실 여부를 별도로 확인해야 한다.

### 확률과 사실을 혼동하지 않기

신고에 승선 인원이 없는데 모델이 자연스럽게 ‘8명’이라고 썼다면 유창하지만 근거 없는 답일 수 있다. 이 때문에 우리 프로젝트는 ‘미확인’을 허용하고 추가 정보를 질문해야 한다.

**컨텍스트(context)**는 이번 응답에 제공된 입력 정보다. 모델의 사전학습 지식, 앱의 DB, 현재 컨텍스트는 구별해야 한다. DB에 기록이 있어도 앱이 필요한 내용을 호출 입력으로 전달하지 않으면 모델이 그 기록을 사용할 수 없다.

## 5. 트랜스포머: 문맥에서 관련 정보를 연결하기

Transformer의 중요한 구성 요소는 **어텐션(attention)**이다. 토큰 표현을 계산할 때 다른 토큰의 정보를 얼마나 반영할지 가중치를 계산한다. 여러 관점의 관계를 함께 다루기 위해 다중 헤드 어텐션을 사용한다. [원 논문](https://arxiv.org/abs/1706.03762)

다음 문장을 보자.

> “청해호에서 3명을 동진호로 옮겼고, 청해호에는 5명이 남았다.”

‘3명’은 이동한 인원, ‘5명’은 청해호 잔류 인원이다. 앞뒤의 선박명·이동·잔류 표현을 연결해야 한다. 어텐션은 이런 문맥 관계를 학습할 수 있는 계산 방식이다. 어텐션 가중치만 보고 모델의 판단 이유 전체를 알아냈다고 말하지는 않는다.

### 순서 정보도 필요하다

“청해호에서 동진호로 이동”과 “동진호에서 청해호로 이동”은 같은 선박 이름을 포함하지만 방향이 반대다. 토큰 순서를 구별할 위치 정보가 필요하다.

### CNN·RNN과 어떻게 다른가

- **CNN:** 가까이 있는 토큰 묶음의 패턴을 찾는다. 2일차에 배운다.
- **RNN:** 앞 단계 상태를 다음 단계로 넘기며 순서를 처리한다.
- **Transformer:** 어텐션 등을 이용해 여러 토큰의 관계를 처리한다.

트랜스포머가 학습 과정에서 여러 위치의 계산을 병렬화할 수 있다는 것과, 생성형 모델이 답변 전체를 동시에 만들어 낸다는 것은 다른 말이다. 일반적인 자기회귀 생성은 다음 토큰을 순차적으로 이어간다. 이것은 우리 앱에서 여러 요원의 API 호출을 병렬 실행하는 것과도 다른 층위다.

### 선택 학습: 인코더와 디코더

인코더 중심 모델은 입력을 이해하는 표현을 만들고 분류·추출에 활용할 수 있다. 디코더 중심의 자기회귀 모델은 앞선 토큰으로 다음 토큰을 생성한다. 인코더–디코더 구조는 입력을 읽고 별도의 출력 시퀀스를 만드는 번역 같은 작업에 활용된다. 예습에서는 구조 이름과 목적 정도를 구별하면 충분하다.

## 6. 사전학습과 후속 학습

**사전학습(pretraining)**은 대량의 데이터에서 넓게 활용할 수 있는 표현과 패턴을 학습하는 과정이다. 다음 토큰 예측처럼 데이터 자체에서 학습 신호를 만드는 자기지도학습이 쓰인다.

**미세조정(fine-tuning)**은 사전학습 모델의 가중치를 추가 데이터로 조정하는 방법이다. 지시와 답변 예시를 이용한 학습은 사용자의 요구에 맞춰 응답하도록 만드는 데 쓰일 수 있다.

이후 학습에는 사람의 선호 등을 반영하는 방법도 있다. 예습에서는 구체 알고리즘을 모두 외우기보다 ‘기본 언어 학습’과 ‘원하는 방식으로 응답하도록 조정’하는 목적을 구별하자.

### 우리 프로젝트에서 헷갈리기 쉬운 세 가지

1. **프롬프트에 “수색구조요원”이라고 적기:** 이번 호출의 역할과 응답 방식을 지시한다.
2. **매뉴얼을 입력 근거로 제공하기:** 이번 답변에 참고할 정보를 추가한다.
3. **전문 데이터로 미세조정하기:** 모델의 학습된 가중치를 변경한다.

현재 프로젝트의 역할 분리와 근거 제공을 세 번째 작업이라고 부르면 안 된다. ‘전문가 학습이 완료된 AI’ 대신 ‘전문 역할과 근거를 부여해 집중 검토하는 AI’라고 설명하는 것이 맞다.

## 7. 생성형 언어모델을 어떻게 활용하는가

모델은 요약, 추출, 질의응답, 초안 작성, 분류 등 여러 업무에 활용할 수 있다. 원하는 결과를 안정적으로 얻으려면 다음을 구체화한다.

- **할 일:** 문장 요약인지, 인원 추출인지, 추가 질문인지.
- **근거:** 현재 신고와 장부 중 무엇을 사용할지.
- **출력:** 예를 들어 총원·구조·잔류 필드와 미확인 정보.
- **제약:** 원문에 없는 숫자·이름·출동 완료를 만들지 않기.
- **검사:** 숫자 합계, 자료 소속, 필수 필드 등을 코드로 검증하기.

### 직접 해보기: 모호한 요청을 고쳐 보기

원래 요청:

> “상황을 잘 정리해줘.”

학습용 개선 예:

> “다음 신고에서 선박명·위치·총원·부상 정보를 추출해줘. 원문에 없는 값은 미확인으로 남기고, 현재 대응 판단에 필요한 질문을 최대 2개 골라 이유를 한 문장씩 붙여줘. 출동 지시는 실행 사실로 쓰지 마.”

이 요청이 모든 오류를 막지는 않는다. 결과를 검사하기 쉬운 목표를 만든다는 점이 중요하다.

### temperature는 정답률 조절기가 아니다

생성 과정에서 후보 선택의 무작위성을 조절하는 설정이 있을 수 있다. 무작위성을 낮춰도 모델이 가진 잘못된 판단이나 입력의 누락이 사라지지는 않는다. 제공되는 설정과 효과는 모델에 따라 다르다.

## 8. 3일차를 위한 연결만 미리 보기

**RAG:** 관련 자료를 검색해 답변 입력에 넣는 방식. 모델 자체를 다시 학습시키는 것과 구별한다.

**도구 사용:** 외부 함수나 API로 조회·계산·작업을 수행하는 것. 모델이 문장으로 ‘조회했다’고 쓰는 것만으로 실제 도구가 실행된 것은 아니다.

**에이전트:** 목표를 위해 모델 판단과 도구·상태·실행 흐름을 연결하는 구성. 여러 역할이 있다는 사실만으로 더 정확하거나 저렴해지는 것은 아니다.

이 세 가지의 실제 실습과 MCP는 3일차 범위다. 오늘은 모델·문맥·검색·실행이 서로 다르다는 점만 기억하자.
