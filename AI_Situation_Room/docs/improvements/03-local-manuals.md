# 구난구조 매뉴얼 로컬화

> 2026-09-29 후속: [M1 상세 구현](../implementation/24-local-manual-rag.md)을 추가했다. 기존 14개 한국어 요약을 선택적으로 검색해 요원에게 제공하고 당시 근거를 저장한다. 기본 off. 전체 원문 확대·전문 검토·로컬 생성 모델·추가 검색 루프는 여전히 후속 범위다. 아래는 자료를 준비한 시점의 기록이다.

> 2026-09-28. 최신 사용자 결정: 보안·해커톤 준비 시간 제약을 고려해 공개 국제 SAR 자료를 기반으로 초안을 만들고 내부 매뉴얼은 나중에 추가한다. 이번 산출물은 로컬 자료 묶음과 검색 연결 설계다. 앱의 검색·모델 호출 변경은 아직 없다.

## 1. 목적과 현재 상태

인터넷이 끊겨도 저장된 지침을 찾아 근거와 함께 검토하게 한다. 로컬 LLM의 지식·검색 도구 사용 능력에만 의존하지 않고, 프로그램이 필요한 문서 구절을 먼저 제공하는 방식이다. RAG는 모델을 재학습하는 작업이 아니다.

현재 `manuals.manual_evidence()`는 기존 기본 초안 전체와 등록 세력 전체를 매번 넣는다. 첨부 검색은 단어 일치 방식이다. 새 자료는 [로컬 자료 시작점](../../prototype/manuals/library/README.md)에 준비했다. 해당 폴더를 만들었다고 현재 앱이 자동으로 읽는 것은 아니다.

## 2. 자료 준비 결과

### 중심 자료: 공개 국제 SAR

[국제 SAR 묶음](../../prototype/manuals/library/international/README.md)에 AMSA 2026 National Search and Rescue Manual과 IMO 회람 5개의 원본 PDF를 보관했다. 총 561쪽이며 페이지별 추출 텍스트, 한국어 분야별 초안 8개, 선별 구절 14개, 출처·페이지·해시, 미실행 평가 사례를 함께 준비했다.

분야는 조난 접수·기록, 지휘·조정, 수색 계획, 구조·자원, 사고선 외부 지원, 대량구조, 의료정보 인계, 종결·재개다. 원문의 인용 대상 절을 대조했으며 전체 561쪽의 전문가 검토를 완료한 것은 아니다.

AMSA의 매뉴얼은 IAMSAR를 고려하여 작성한 호주 국가 매뉴얼이다. 이를 IAMSAR 원문 자체라고 부르지 않는다. [AMSA 배포 페이지](https://www.amsa.gov.au/national-search-and-rescue-council/manuals-and-publications/national-search-and-rescue-manual)와 [IMO의 SAR 관련 자료 목록](https://www.imo.org/en/ourwork/safety/pages/imo-documents-relevant-to-sar.aspx)을 확인했다. IMO 목록에는 IAMSAR가 구매 출판물로 안내된다. 이번 묶음은 IAMSAR 유료 본문 전체를 포함하지 않는다.

발표 문구: **“보안과 해커톤 준비 시간을 고려해 공개 국제 SAR 지침과 해외 공개 SAR 매뉴얼로 판단 보조 초안을 구성했으며, 향후 국내 지침과 내부 승인 매뉴얼로 보완한다.”**

### 보조 자료: 국내 공개 안내·사례

- 공식 페이지 본문을 직접 확인한 출처 5개: 행정안전부 물놀이 행동요령, 평택해경 연안 안전수칙, 서해해경 응급환자 이송·화재 대응 사례, 여수해경 방제훈련 사례, IMO IAMSAR 소개.
- 분야별 문서 6개: 접수·근거 판단, 익수, 갯벌·연안 고립, 환자 이송·선박 화재 사례, 충돌·오염 훈련 사례, 수색구조 조정 자료 안내.
- 출처 등록부, 기계가 읽을 수 있는 구절 JSONL, 파일 SHA-256 목록, 검색·답변 평가 사례를 함께 보관한다.
- 국내 보조 요약은 직접 확인한 공개 본문의 범위로 제한했다. 국내 SOP 원본 전체를 확보한 것으로 표시하지 않는다. 원문 URL·본문 위치·게시일·확인일과 로컬 요약을 연결한다. 전문 운용 검토는 미실시다.

### 자료 선별에서 제외하거나 보류한 것

- 도봉구 해양 선박사고 안내: `보트 전복` 제목 아래 좌초 대응 설명이 있어 분류 해석이 필요하다. 이번 운용 구절에는 넣지 않았다. [확인 페이지](https://www.dobong.go.kr/Contents.asp?code=10010083&tab=9).
- 질병관리청 저체온증 안내: 검색 결과는 찾았으나 본문 열기가 실패했다. 내용을 확인한 자료로 등록하지 않았다. [후속 확인](https://health.kdca.go.kr/healthinfo/biz/health/gnrlzHealthInfo/gnrlzHealthInfoView.do?cntnts_sn=3690).
- IAMSAR: 이번에 확인한 것은 IMO의 권별 소개다. 전문 절차·표·계산식을 읽거나 저장한 것으로 취급하지 않는다.
- USCG CI 16130.2I: 공식 목록에서 2026-02-02 판본을 확인했으나 원본 접근이 거절됐다. 확보 자료에 포함하지 않았다. 이전 판본을 최신판으로 대체하지 않았다.

## 3. 로컬 LLM에 맞춘 준비

긴 매뉴얼 전체를 작은 모델에 넣는 대신, 각 구절에 다음을 붙인다.

- 어떤 사고·임무에 해당하는지와 검색용 표현.
- 원문이 말하는 사실의 요약.
- 적용 대상과 적용할 수 없는 범위.
- HAEON이 추가로 확인하도록 제안하는 항목. 이 항목은 공식 문구와 구별한다.
- 문서 ID·버전·원문 위치·확인일·검토 상태.

예를 들어 과거 헬기 이송 사례를 찾더라도 현재 헬기가 출동 가능하다고 결론 내리지 않는다. 일반인 물놀이 안내를 전문 잠수팀의 입수 기준으로 사용하지 않는다. 새로운 보고와 과거 사례의 사람·위치·세력을 섞지 않는다.

## 4. 검색 연결 제안 — 아직 미구현

### 추천: 문서·구절 구조를 먼저 고정하고 로컬 단어 검색부터 연결

기존 Python·SQLite를 유지한다. 분류·제목·검토한 동의어로 후보를 찾고 관련 구절과 출처를 `tools.evidence_for()`의 매뉴얼 근거로 전달한다. 모델이 검색 호출을 빠뜨려도 필요한 자료가 공급되도록 서버가 호출한다. 초기 자료가 적어도 시작할 수 있고 검색 실패를 조사하기 쉽다.

그다음 한국어 로컬 임베딩 검색을 같은 평가 사례로 비교한다. 단어 검색과 의미 검색을 합치면 표현 차이에 대응할 수 있지만 모델 파일·메모리·한국어 검색 품질 검증이 더 필요하다. 현재 로컬 PC 사양과 사용할 모델이 정해지지 않았으므로 임베딩 모델이나 Vector DB를 확정하지 않는다.

문서를 전부 프롬프트에 붙이는 방식은 자료가 늘 때 문맥 한도와 불필요한 정보 문제가 커져 확장 방향으로 채택하지 않는다.

### 필요한 연결 계약

1. `retrieve_manuals(query, incident_type, role, scope, limit, budget)` 입력을 설계한다. 임무·현재 사건 정보를 사용하되 미확인 보고가 사실로 바뀌지 않게 한다.
2. 반환 항목은 `chunk_id`, `document_id`, `version`, `content`, `source_kind`, `source_url`, `locator`, `review_status`, `limitations`를 포함한다.
3. 일반 행동요령·사례·운용 SOP를 별도 유형으로 필터링한다. 사례가 높은 점수여도 운용 SOP로 승격하지 않는다.
4. 검색 실패·자료 없음·인덱스 오류를 서로 다른 상태로 반환한다. 무관한 구절로 개수를 채우지 않는다.
5. 실제 모델의 문맥 한도에서 지시문·현재 사건·출력 공간을 빼고 검색 예산을 정한다. 조건·예외·금지사항 중간을 잘라 전달하지 않는다.
6. 요원·최종 보고의 근거 ID 검증과 UI 원문 표시를 새 구절 ID에 맞춘다. 기존 `basic_manual` 참조도 호환 계획이 필요하다.
7. 실행 기록에는 사용한 구절 내용·버전·해시를 저장한다. 이후 매뉴얼 개정으로 과거 보고의 근거가 달라져 보이지 않게 한다.

SQLite FTS5는 후보이며 실행 환경 지원을 확인해야 한다. trigram만 사용하면 세 글자 미만 검색어를 다루는 데 한계가 있으므로 `불`, `물`, `침수` 같은 표현의 대체 처리를 검증한다. [SQLite 공식 설명](https://www.sqlite.org/fts5.html#the_trigram_tokenizer).

### 온라인 보완

로컬 매뉴얼 검색은 온라인·오프라인 공통 기반으로 둔다. 인터넷 연결 여부와 별개로 모델 또는 서버에 실제 웹 검색 도구가 연결되어 있어야 검색할 수 있다. 현재 앱에 일반 웹 검색 기능이 구현되어 있다고 가정하지 않는다.

온라인 검색 결과에는 출처·확인 시각·대상 해역·기준시각을 표시한다. 검색 결과로 승인 매뉴얼을 자동 교체하지 않는다. 네트워크 단절 시 현재 시점의 기상·현장 상황을 과거 저장값으로 가장하지 않는다.

내부 자료를 추가할 때는 `external_use=deny`가 기본이다. 인터넷이 연결돼 있어도 클라우드 LLM·웹 검색 질의·외부 로그로 내부 원문이 넘어가지 않도록 모델 호출 직전에 필터링해야 한다. 현 LIVE 경로는 외부 API를 사용하므로 이 경계 구현 전 내부 자료를 앱에 연결하지 않는다.

## 5. 후속 수용 기준

- 네트워크 차단 상태에서 문서와 검색 인덱스를 읽고, 검색 도중 다운로드나 외부 API 호출이 없음을 확인한다.
- 동의어·복합사고·무관한 질문·자료 부족·과거 사례·부정 문장·현재 위험 해소를 평가한다.
- 인용 ID가 제공한 구절과 연결되고 실제 주장도 그 구절로 뒷받침되는지 확인한다. ID 검사만으로 의미 일치가 증명되지는 않는다.
- 자료 업데이트 후 재색인, 구버전 배제, 실패 시 기존 인덱스 유지, 과거 실행 근거 보존을 검증한다.
- 다른 사건의 첨부·내부 자료가 섞이지 않게 한다. 외부 수신함 승인 흐름은 기존 계약을 유지한다.
- 같은 자료·질문으로 클라우드/로컬 모델의 누락·오인용·근거 없는 지시·응답시간을 비교한다. 성능 동등성을 미리 주장하지 않는다.

## 6. 이번 확인과 남은 작업

이번에는 공식 웹·PDF 인용 절 확인, 로컬 원문·추출 텍스트·한국어 초안·메타데이터 작성 및 정적 무결성 검사를 수행했다. 앱 단위·HTTP·브라우저·LIVE·로컬 LLM 추론·검색 성능 검증은 이번 결과에 포함하지 않는다.

다음 구현 단위는 **로컬 구절 검색 → 기존 근거 전달 → 출처 표시**다. 로컬 LLM 연결과 온라인 검색 도구 연결은 각각 별도 작업이다. 준비 자료가 내부 승인 SOP를 대체하지 않도록 자료 검토와 코드 검증을 함께 진행한다.

## 7. 후속 구현계획 · 2026-09-28

사용자는 벡터 DB 활용, 원문 사전 파싱, 로컬 LLM의 상황별 매뉴얼 참조를 논의한 뒤 구현계획 작성을 요청했다. [구현계획 시작점](../superpowers/plans/2026-09-28-sar-rag.md)과 자료·검색·요원·로컬 모델의 별도 계획 4개를 작성했다.

앞의 단어 검색 우선 제안은 비교 기준으로 유지한다. 새 계획은 로컬 Qdrant와 다국어 임베딩을 후보로 평가하고 키워드 검색과 결합하는 방향이다. 실제 제품 선택·설치·색인 생성은 아직 하지 않았다. 14개 요약으로 연결을 먼저 검증하고 원문 561쪽은 처리 상태를 기록하며 검토된 절부터 확대한다. 제한된 추가 검색과 완전 오프라인 생성 모델 전환은 후속 단계다.

이번 산출물은 계획 문서다. 원문 전체 정제·벡터 DB·자동 RAG·로컬 LLM·새 근거 UI가 구현된 것으로 해석하지 않는다.
