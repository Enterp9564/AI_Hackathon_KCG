# 02 · 정보와 처리 규칙

2026-09-29 · **제안 / 미구현** · [개선안 전체](../04-main-alerts.md)

## 1. 다섯 가지 상태를 분리한다

- **버튼 알림 인지:** 새 수신분이 있으면 강조하며 버튼 클릭으로 해제한다. 개별 원문을 읽었다는 기록과 구분한다.

- **출처 판정:** 링크온의 urgency/outcomes/status와 원문. 해온이 임의 수정하지 않는다.
- **열람:** 판본별 `seen_at`. 읽었음을 뜻하며 위험 해소가 아니다.
- **해온 검토 상태:** 검토 대기 → 검토 중 → 확인 정리. 담당자가 명시적으로 바꾸며 확인 정리에는 사유가 필요하다. 다시 검토 대기로 돌릴 수 있다.
- **원본 관리 상태:** 위치·이송·종결 등. 출처/수신 시점과 함께 표시한다. 원본 종결을 해온 검토 완료나 의학적 위험 해소로 바꾸지 않는다.

‘확인 정리’는 해온에서 확인 내용을 기록했다는 뜻이다. 임상적 경보 해제 기능을 만들지 않는다. 최신 판정 전체 집계는 읽음·확인 정리 후에도 유지하고, 필요하면 별도의 `해온 검토 대기` 건수를 표시한다. 자동 숨김·자동 정상 판정은 없다.

첫 UI 단계에는 검토 상태 DB를 추가하지 않는다. 열람과 출처 정보를 먼저 개선한다. 검토 상태를 추가할 때는 세션+환자 단위의 업무 기록과 판본별 열람 이력을 따로 저장한다. 변경 시점·이전/이후 값·사유·대상 판본을 보존한다. 현 앱에는 담당자 인증이 없으므로 인증된 개인별 처리 이력이라고 주장하지 않는다.

버튼 강조는 현재 `unread_count`와 분리한다. P0에서는 `sessionStorage`에 해온 세션+출처별 인지한 판본 ID와 강조 대기 판본 ID만 저장하고 환자 원문은 저장하지 않는다. 최초 진입의 미열람 판본과 이후 새로 수신한 판본을 강조 대기에 넣는다. 이미 인지한 판본의 반복 수신은 제외한다. 강조 대기는 상세 읽음으로 제거하지 않는다. 정상적으로 패널을 연 뒤 클릭 당시 판본 집합만 인지로 옮기며, 뒤늦게 도착한 판본은 대기에 남긴다.

같은 탭 새로고침에는 유지하며, 새 탭/저장소 초기화 후에는 미열람 자료를 다시 강조한다. 저장소 사용 불가 시 메모리로 동작하고 새로고침 후 다시 강조할 수 있다. 이 값은 해당 화면의 인지 표시이며 공동 담당자의 확인 기록으로 사용하지 않는다. 삭제된 세션의 값은 정리하고 저장량에는 상한을 둔다. 상한 초과 시 오래된 인지 기록을 제거하여 재강조를 허용하되 새 알림을 숨기지 않는다.

새 분석 ID/분석 내용 변경은 미열람 판본이 된다. 확인 정리 후 새 분석 내용이 오면 검토 대기로 돌린다. 동일 지문 재수신·무변경 조회는 이력을 추가하거나 다시 열지 않는다. 현재 상태 이력만 바뀐 경우에는 `판정 이후 기록 확인 필요`를 표시하고 검토 대상으로 되돌린다. 과거 판본의 정리 이력은 보존한다.

## 2. 코드·자료 신선도

IMMEDIATE/WITHIN_30은 출처 요청 긴급도로 표현한다. 원본 명부 중증도와 자동 변환하지 않는다. OBSERVE는 의미가 확정될 때까지 `출처 분류 OBSERVE · 의미 확인 중`으로 표시한다. 모르는 코드는 원문을 유지하고 정상/오류 분류를 임의 대입하지 않는다.

`status=FAILED`, 시각 누락/해석 실패, 알려지지 않은 코드는 각각 다른 표시가 필요하다. `last_event_id != based_on_event_id`는 판정과 현재 기록이 다르다는 신호이며 상태 악화의 증거로 단정하지 않는다.

수신 실패 시 마지막 성공 자료와 시각을 남긴다. 새 결과가 없거나 이전 환자가 최신 응답에서 빠진 것을 정상/해소로 처리하지 않는다. `missing_count`와 연결 대기/실패를 통신·자료 영역에 표시한다. 연결 복구가 환자 상태 회복을 뜻하지 않는다.

위치·이송·종결은 기존 수동 명부 수신본을 먼저 사용하고 `명부 수신 HH:MM 기준`으로 표시한다. 최신성이 다른 자료를 한 줄에 합쳐 최신 현황처럼 보이게 하지 않는다. 더 빠른 관리 상태가 필요하면 읽기 허용 필드·변경 지문·인덱스·부하 검증을 별도 단계로 확장한다. 3초마다 전체 수동 동기화를 호출해서는 안 된다.

## 3. 일괄 읽음 처리

`선택 판본 읽음 처리`는 사용자가 체크한 local alert ID 목록에만 적용한다. 필터 결과의 현재 N건을 선택하는 버튼은 대상 수를 표시한다. 화면 밖의 모든 사건이나 이후 도착할 판정을 포함하지 않는다.

제안 API: `POST /api/sessions/{sid}/patient-alert-seen-batch`에 `{alert_ids:[...]}` 전달. 이는 아직 없는 API다. 기존 토큰/Host/Origin 검사와 세션 소유권 검사를 유지한다.

서버는 중복 ID를 제거하고 상한 100건을 검사한다. 모든 ID의 소유권·최신 판본 여부를 검증한 후 단일 트랜잭션으로 기록한다. 판본 변경이면 전체를 409로 거절해 조용한 일부 성공을 피한다. 같은 판본 재요청은 기존 seen_at을 유지한다. 읽음 API는 AI를 실행하지 않는다.

## 4. 선택 판정 함께 AI 검토

화면에서 선택 → 출처·대상·기록 시점·검토 요청문 미리보기 → `해온에 함께 검토 요청` 순서다. 전송은 기존 채팅 함수와 Engine 흐름을 확장한다. 채팅 초안은 유지한다. 사용자 요청 한 번에 한 run을 만들며 필요한 요원은 기존 배정 규칙을 따른다. 한 run이 모델 한 호출이라는 뜻은 아니다.

검토는 같은 해온 세션의 최신 판본만 대상으로 한다. 첫 제안 상한은 8명이며 서버가 실제 전송문 총 8,000자 이내인지 검사한다. 필수 출처·판본·요약·근거·부족 정보·시점을 조용히 잘라 맞추지 않는다. 초과 시 대상 축소를 안내하고 자동 분할 실행하지 않는다. 화면의 8명 전수 열람은 AI 입력 상한과 무관하게 제공한다.

제안 API 흐름:

1. `POST .../patient-alert-batches`에 선택 ID를 보내면 서버가 저장 원문으로 미리보기를 만들고 `batch_id`를 발급한다. 세션/room, 정렬된 local ID+해시, 상황 버전, 전송문, 생성 시각을 고정한다. AI는 실행하지 않는다.
2. `POST .../patient-alert-batches/{batch_id}/review`로 승인한다. 접수 전 판본/사건/상황 버전이 달라졌으면 409와 재검토 안내를 반환한다. 미리보기 유효시간은 제안상 5분이며 의료적 판정 유효시간이 아니다.
3. `patient-alert-batch:{batch_id}`를 Engine 요청 키로 사용한다. 동일 선택+상황 버전의 준비 요청 재시도는 기존 batch를 반환하고, 기존 실행이 있으면 그 결과로 이동한다. 접수된 요청의 재시도는 만료/변경 검사보다 기존 실행 확인을 먼저 해 중복 실행을 막는다.

세션의 다른 검토가 진행 중이면 추가 실행을 자동 예약하지 않고 현재 진행을 안내한다. 실패 후 자동 재실행도 하지 않는다. 명시적 재검토는 기존 시도 이력에 연결한 새 attempt로 처리한다. 원문 속 지시를 실행 명령으로 취급하지 않는 기존 규칙을 유지한다.

## 5. 결과 확인과 추적

공통 핵심 제안은 1~2개로 유지하되 선택된 환자마다 식별·검토 요지·추가 확인 또는 검토 불가 이유를 남긴다. 총 8명 중 일부만 언급하고 전부 검토했다고 표시하지 않는다. 서버가 대상 ID 집합과 결과의 대상 포함 여부를 검증한다. 누락은 `일부 결과 누락`으로 표시하고 완료를 자동 선언하지 않는다. 식별자 포함 검사는 임상적 검토 품질 검증과 별개다.

저장 원문/선택 판본, 배치, 채팅 메시지, run ID를 연결한다. AI 완료는 열람·확인 정리 상태를 자동 변경하지 않는다. 링크온 DB 쓰기·실제 이송 지시·외부 메시지 전송은 이 흐름에 포함하지 않는다.

## 6. 다른 중요 알림의 확장

환자, 선박·현장, 통신·자료는 공통 표시 형태를 사용하되 출처 ID·발생/기준/수신 시각·최신/누락·해온 검토 상태를 구분한다. 환자 판정과 경사 경보를 하나의 임상 위험 점수로 합산하지 않는다.

선박 경사는 `hull_tilt_alert`/확인 이력 등 실제 계약을 먼저 조사한다. 기존 수동 수신한 경사값으로 링크온 경보와 같은 자동 판정을 흉내 내지 않는다. RESAID AI는 준비된 MCP 보고 범위부터 표시하고 미완성 팀 기능을 연결 완료로 소개하지 않는다. 외부 확인/해제와 해온 열람은 각각의 이력으로 유지한다.
