# 03 · 구현 순서와 인수 기준

2026-09-29 · **제안 / 구현 및 아래 시험 미실시** · [개선안 전체](../04-main-alerts.md)

## P0 · 상시 요약과 전수 비교 — 우선 구현 권고

대상: `prototype/static/index.html`, `style.css`, `patient-alerts.js`, 필요 시 `app.js`.

- 공통 헤더 아래 고정 요약을 추가하고 기존 알림 버튼을 같은 주요 알림 패널에 연결한다.
- 미열람 수와 버튼 인지 상태를 분리한다. 새 수신분은 클릭 전까지 붉은 강조를 유지하고, 패널 열기 성공 시 클릭 당시 판본 집합만 인지 처리한다. 상세 읽음·검토 완료·AI 실행은 별도다.
- `showModal()` 중심의 목록/상세 교체를 비모달 목록+옆 상세로 개선한다. 기존 MCP 진입은 유지한다.
- 기존 `/patient-alerts` 응답으로 집계/필터/시점/불일치를 표시한다. 위치·종결의 출처가 없으면 확인 불가다.
- 기본 3초 DB 확인과 로컬 캐시 조회를 유지한다. 대형 화면은 고정 사건 조회만 추가하고 쓰기 UI는 제공하지 않는다.
- 선택/스크롤/포커스 보존, 변경 배지, 해온 사건 전환 격리를 구현한다. 첫 단계에서는 아직 없는 일괄 처리 API를 호출하지 않는다.

완료 조건: 8명 핵심 비교가 개인 상세 왕복 없이 가능하고 읽은 중요 판정도 남는다. 해온/링크온 왕복, 사건 전환, 원격 장애에서도 표시 기준이 분명하다.

## P1 · 선택 읽음과 해온 검토 상태

대상: `prototype/patient_alerts.py`, `server.py`, `store.py`의 저장/마이그레이션 경로, 관련 UI.

- 판본별 읽음과 환자별 해온 검토 상태/이력을 분리한다.
- 선택 읽음 원자적 처리, 확인 정리 사유, 다시 검토, 새 판본 재개 규칙을 구현한다.
- 기존 자료를 보존하는 추가 테이블/필드 방식으로 마이그레이션한다. 기존 `seen_at`은 읽음으로만 이전하고 완료 상태를 추론하지 않는다.
- 위치/관리 상태를 명부 수신본에서 보강한다면 출처 시각을 응답에 포함한다. 원격 최신 자료로 오인시키지 않는다.

완료 조건: 읽음 후에도 중요도 집계가 사라지지 않고, 각 변경의 대상 판본·시각·사유를 추적할 수 있다. 반복 클릭·동시 갱신·오래된 요청으로 다른 환자나 판본이 처리되지 않는다.

## P2 · 선택 일괄 AI 검토

대상: `patient_alerts.py`, `server.py`, `static/app.js`의 공통 전송, `engine.py`의 요청 멱등/결과 검증 경계.

- 서버 미리보기/배치 저장, 승인 전송, 중복 방지, 실행 기록 연결을 구현한다.
- 기존 단건 인용과 일반 채팅을 유지한다. 단건 함수를 환자 수만큼 반복 호출하지 않는다.
- 환자별 결과 포함 여부를 검증하고 공통 제안은 간결하게 유지한다.
- 화면 수신/열람/선택으로 모델을 호출하지 않는다. 준비된 배치도 승인 전에는 실행하지 않는다.

완료 조건: 적합한 가상 판정 8개를 선택하면 한 run으로 접수되고 각 환자 결과를 찾을 수 있다. 한도를 넘는 입력은 설명과 함께 거절되고 조용히 축약·다중 실행되지 않는다. LIVE 소요 시간은 측정 후 보고하며 현재 지연보다 빠르다고 미리 약속하지 않는다.

## P3 · 주요 알림의 종류 확장

환자 흐름 안정화 후 선박·현장 경보, 원격 수신 이상, RESAID 보고를 연결한다. 통신 이상은 기존 해온 수신 상태만으로 먼저 표시할 수 있다. 선박/팀 경보는 원본 계약·해제 의미·사건 매핑·읽기 비용을 확인해야 한다.

외부 경보 수가 늘어도 앞의 알림을 처리해야 나머지가 보이는 구조를 만들지 않는다. 유형별 전체 목록과 검색을 제공하고 과거 이력은 별도 진입으로 남긴다.

## 검증 시나리오

아래는 앞으로 실행할 인수 시험이다. 실환자 원문 대신 가상 환자 A~H와 합성 상태를 사용한다.

### 단위·HTTP

1. IMMEDIATE 5/WITHIN_30 2/OBSERVE 1과 미열람 8을 별도 집계한다. 모두 읽어도 출처 판정 집계는 유지된다.
2. FAILED, 모르는 코드, 시각 누락, 0건, 미연결, 수신 실패를 정상으로 합치지 않는다.
3. 다른 세션 ID·다른 room·오래된 판본의 일괄 처리를 거절한다. 선택 후 변경 시 부분 처리 없이 충돌을 반환한다.
4. 같은 판정 재수신에는 상태/이력 변화가 없고 새로운 판본은 미열람 및 재검토 대상으로 나타난다.
5. 배치 승인 더블 클릭, 응답 유실 후 재시도, 서버 재시작 후 조회에서 동일 run이 반환된다.
6. 접수 전 판본/상황 버전 변경과 접수 후 변경을 구분한다. 접수된 과거 요청의 재시도가 새 run을 만들지 않는다.
7. 입력 한도/8명 상한, 병행 검토 거절, 초안 보존, 결과 대상 누락 표시를 확인한다.

### 브라우저

8. 1920×1080에서 넓게 보기의 8행 핵심 정보가 함께 보인다. 1366×768에서는 고정 요약·목록 내부 스크롤, 390px에서는 가독성과 모든 동작 접근을 확인한다.
9. 키보드로 패널 진입·행 상세·선택·닫기가 가능하고, 닫은 뒤 포커스가 호출 버튼으로 돌아온다. 색을 구별하지 않아도 중요도·실패·새 판정을 읽을 수 있다.
10. 새 판정 수신 중 읽는 행·스크롤·포커스·초안이 유지된다. 선택 이후 온 항목은 자동 선택되지 않는다.
11. 해온 사건 A→B 전환에서 A의 상세/선택/지연 응답이 B에 나타나지 않는다. 유지 중인 링크온 iframe 사건을 해온 사건으로 추정하지 않는다.
12. 대형 화면은 고정 사건 기준으로 요약을 갱신하고 사용자 화면의 사건 선택을 따라 잘못 바뀌지 않는다. 쓰기 동작이 없다.
13. 환자 알림 첫 클릭, 단건 인용, Link-One MCP, RESAID 수신함, 화면 전환·로그인 유지가 회귀하지 않는다.

버튼 강조 추가 시험: 새 수신 → 시간 경과에도 강조 유지 → 버튼 클릭 시 강조만 해제 → 미열람 건수 유지 → 이후 새 판본에 재강조를 확인한다. 동일 응답 반복, 패널이 이미 열린 상태, 클릭 직후 수신, 열기 실패, 사건 왕복, 같은 탭 새로고침/새 탭, 저장소 실패, 키보드 조작, 움직임 줄이기도 확인한다. AI 호출은 전 과정에서 0회여야 한다.

### 부하·DEMO·LIVE

14. 화면/탭 수를 늘려도 원격 조회 주기가 서버당 기존 3초보다 늘어나지 않는지 확인한다. 브라우저는 로컬 캐시만 읽는다.
15. DEMO에서 합성 8명 배치 접수·결과 연결·누락 감지를 시험한다. LIVE는 같은 합성 자료로 별도 1회 시험하고 요원/검증/전체 시간과 입력량을 기록한다. 성공 여부와 관계없이 기록을 남긴다.

## 중단·축소 기준

- 시간이 제한되면 P0를 먼저 완성하고 P1~P3을 미구현으로 명시한다. 화면만 있는 버튼으로 일괄 AI 기능이 있는 것처럼 보이지 않게 한다.
- 외부 상태 의미가 확정되지 않으면 원문 코드·자료 시점을 표시한다. 의료적 해제 기준이나 경사 임계값을 새로 가정하지 않는다.
- 배치 입력/결과 품질이 부족하면 전수 열람은 유지하고 AI 일괄 전송만 보류한다.
- 각 단계 후 [현재 상태](../../../13_현재상태_요구사항_인수인계.md), [진행 기록](../../../prototype/PROGRESS.md), [환자 알림 구현](../../implementation/26-linkone-patient-alerts.md)을 실제 결과로 갱신한다.
