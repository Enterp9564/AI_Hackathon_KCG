# 주요 알림 UX/UI 개선안

2026-09-29 · HAEON(해온) · **검토용 제안 / 미구현**

## 제안 요약

**현재 사건의 중요 정보를 항상 보여주고, 여러 환자를 한 화면에서 비교한 뒤 필요한 항목만 함께 검토한다.** 좁은 알림 팝업을 상시 요약과 넓은 점검 패널로 개선한다. 데이터 수신만으로 AI를 실행하지 않는 기존 결정을 유지한다.

**추가 사용자 결정:** 새 알림을 수신하면 환자 알림 버튼을 붉은 빛으로 은은하게 강조하며, 버튼을 누르기 전까지 유지한다. 상황실장 처리 중 초록색 강조와 같은 방식으로 주의를 끌되 환자 알림 색은 빨간색이다. 클릭은 강조만 멈추며 개별 읽음·검토 완료·AI 실행을 뜻하지 않는다. 이후 새 판본이 오면 다시 강조한다.

문서는 기능별로 나눴다.

- [01 · 화면과 사용자 흐름](main-alerts/01-screen-and-flow.md): 고정 요약, 주요 알림 패널, 8명 비교, 상세, 대형 화면.
- [02 · 정보와 처리 규칙](main-alerts/02-data-and-actions.md): 읽음/검토/원본 상태 구분, 최신성, 일괄 처리와 AI 부하.
- [03 · 구현 순서와 인수 기준](main-alerts/03-delivery-and-acceptance.md): 단계별 변경 파일, 의존성, 검증과 완료 조건.

## 1. 문제와 관측 근거

2026-09-29 직전 화면 비교에서 해온 목록은 최신 판정 8건·미확인 8건이었다. 출처 urgency는 IMMEDIATE 5건, WITHIN_30 2건, OBSERVE 1건이었다. 이 수치는 당시 화면의 표본이며 현재 실시간 집계나 임상 판단이 아니다. 환자 이름·개별 증상·식별자는 이 제안에 기록하지 않는다.

해온의 빨간 숫자는 상세를 열지 않은 최신 판정 수다. 동시에 새로 발생한 응급환자 수가 아니다. 목록에는 오래된 분석과 링크온 화면에서 종결로 표시된 환자의 판정도 포함돼 있었다. 전수 비교·자료 시점·현재 관리 상태를 함께 확인할 수 있어야 한다.

### 링크온에서 가져올 장점

- 환자별 위치, 관리 세력, 이송/종결, 중증도, AI 참고 결과를 같은 목록에서 비교한다.
- 기록과 분석의 경과, 이후 기록 유무를 표시한다.
- 선박 경사 등의 주요 경보가 본문에 보인다.

### 해온에서 개선할 점

- 현재 약 560px 팝업은 긴 카드 목록과 개인 상세를 왕복해야 한다. 8명 전수 점검에 적합한 밀도가 아니다.
- 최신 판정은 긴급도별로 정렬되지만 색상·행 구조가 비슷하고 요약 집계/필터가 없다.
- 읽음에 따라 숫자가 줄어도 검토·대응 여부는 알 수 없다.
- 위치·종결 상태는 알림 API에 없으며, 별도 수동 명부 수신본은 최신성이 다를 수 있다.
- OBSERVE 등 계약 미확정 코드를 오류처럼 보이게 하거나 정상으로 해석하지 않아야 한다.

링크온의 ‘앞 경보를 확인하면 나머지를 표시’하는 구조는 복제하지 않는다. 다른 경보를 보기 위해 먼저 확인 처리할 필요가 없어야 한다.

## 2. 추천 구성

1. **상시 요약:** 현재 사건명, 출처 분류별 건수, 미열람 건수, 마지막 수신 성공 시각.
2. **주요 알림 패널:** 8명을 밀도 높은 목록으로 비교하고 옆에서 상세를 확인. 채팅과 병행 가능.
3. **전체 점검:** 목록을 여는 것만으로 전체를 읽음 처리하지 않는다. 선택한 판본만 명시적으로 처리한다.
4. **함께 AI 검토:** 사용자 요청 시 선택 판정들을 기존 상황실장 흐름의 한 실행으로 전달한다. 환자마다 별도 실행을 자동 생성하지 않는다.
5. **다른 중요 정보:** 환자 기능이 안정화된 뒤 선박/현장 경보와 통신/자료 이상을 같은 영역에 연결한다.

## 3. 먼저 구현할 범위

첫 단계는 **고정 요약 + 전체 비교 목록 + 옆 상세 + 시점/출처 표시**다. 기존 3초 원격 확인·1초 로컬 캐시 조회를 재사용한다. 목록 열기나 필터 변경으로 원격 전체 동기화·AI 호출을 하지 않는다.

그다음 읽음/검토 상태 이력, 선택 일괄 AI 검토, 다른 종류의 알림 순서로 확장한다. 선박 경보의 새 임계값이나 의료 판정 규칙을 이번 UI 개선에서 만들지 않는다.

## 4. 성공 기준

- 담당자는 알림 버튼 한 번으로 8명의 긴급도·요약·기록 시점을 비교할 수 있다.
- 읽은 중요 판정도 계속 보이며, 읽음 숫자 감소를 위험 해소로 오인하지 않는다.
- 해온/링크온 화면 전환과 스크롤 중에도 현재 해온 사건과 중요 알림 요약을 확인한다.
- 새 판정 수신 중에도 선택·초안·상세 포커스를 보존하고, 다른 판본을 몰래 대신 전송하지 않는다.
- 여러 판정을 함께 검토해도 한 번만 접수되고 각 환자별 누락 여부를 확인할 수 있다.

## 5. 현재 상태와의 경계

기존 수신·단건 인용은 [26번 구현 문서](../implementation/26-linkone-patient-alerts.md), 데이터 의미의 미확정 부분은 [DB 계약 조사](../contracts/linkone-patient-alerts.md)를 따른다. 이번 작성은 화면/처리 정책의 개선 제안이다. 코드·DB·서버·로그인 상태를 변경하거나 새 AI 검토를 실행한 기록이 아니다.
