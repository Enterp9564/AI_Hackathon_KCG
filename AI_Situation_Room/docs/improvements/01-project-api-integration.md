# 향후 개선사항 — 여러 프로젝트와 API 정보 교환

> 임시 프로젝트명: **HAEON(해온)** · 해양경찰 멀티에이전트 의사결정 지원 시스템. [명칭·소개 기준](../PROJECT_NAMING.md) (2026-09-27). ‘AI 오케스트라’는 협업 방식의 설명이며 이름에 포함하지 않는다.

> 2026-09-27 갱신. Link-One·RESAID AI의 승인형 MCP 수신은 구현했다. **아래 양방향 교환·운영 확장은 향후 개선 범위다.** 실제 두 프로젝트 앱과의 통합 검증은 아직 하지 않았다.

## 1. 추가할 목표

HAEON(해온)이 여러 프로젝트와 API로 정보를 주고받도록 확장한다. 외부에서 받은 정보를 해당 사건의 근거로 검토하고, 상황실의 상태·요청·보고를 필요한 상대 프로젝트에 전달한다. 연동이 생겨도 원문·정정·세션 격리·실행 모드 구분을 유지한다.

현재 외부 호출은 모델 API와 수동 기상 조회다. 수신은 [MCP 도구](../implementation/17-mcp-transport.md)와 [승인 수신함](../implementation/16-external-inbox.md)을 제공한다. 프로젝트별 토큰·사건 연결·중복 검사·원문/처리 이력이 있다. 결과 송신·웹훅·상대 앱별 어댑터는 없다. `/api/*`는 로컬 UI용이며 외부 서비스용 공개 API가 아니다.

## 2. 대상별로 확정할 항목

대상은 Link-One(현장 구조)·RESAID AI(응급지원)다. 수신 계약 외에 각 프로젝트와 아래 항목을 확정한다. 이름·주소·권한을 추측해서 채우지 않는다.

- 상대 프로젝트명, 담당 기능, 운영/시험 환경.
- 받는 정보: 필드·단위·기준시각·원본 ID·조회 주기.
- 보내는 정보: 어떤 사건·보고·정보요구를 어떤 조건에 전달할지.
- 방향: 조회만 / 수신만 / 송신만 / 양방향.
- 방식: HTTP 요청, 폴링, 웹훅 등 상대가 실제 지원하는 방식.
- 인증·권한 범위·비밀 보관 위치·네트워크 접근 조건.
- 외부 사건 ID와 상황실 session_id의 매핑 책임.
- 누가 어떤 필드의 최신값을 결정하는지, 충돌·정정 처리.
- timeout·재시도·호출량·비용·운영 가능 시간.
- 자료 보존·개인정보 범위·송신 승인 조건·인수 시험 데이터.

기존 무료 기상 중심 초기 API 범위를 이 요청으로 즉시 확대 구현하지 않는다. AIS·MMSI·실제 자원 시스템이 연동 대상으로 확정된 것도 아니다.

## 3. 권장 처리 경계 — 설계 초안

```text
상대 프로젝트 API
  → 프로젝트별 어댑터
  → 인증·스키마·중복·시각 검사
  → 외부 원문/메타데이터 보존
  → 외부 사건 ID ↔ session_id 매핑
  → 세션 근거 또는 상태 갱신 후보
  → 장부·버전 검사 / 필요한 사용자 확인
  → 요원 검토와 최종 보고
  → 전송 대상·필드 선택
  → 송신 대기 기록 → 상대 API → 수신 확인 기록
```

외부 JSON을 session.facts에 바로 덮어쓰지 않는다. 정보의 출처·기준시각·확실성·소속을 검사한다. 수신된 ‘출동 예정’은 ‘출동 완료’로 바꾸지 않는다. 송신 성공도 상대의 현장 조치 완료와 별개다.

어댑터의 책임은 상대 필드를 공통 형식으로 변환하는 것이다. 외부 프로젝트별 예외 로직을 UI와 모델 프롬프트에 흩어 넣지 않는다. 처음에는 프로젝트 한 개·정보 한 종류를 연결하고 독립적으로 늘린다.

## 4. 정보 봉투 예시 — 현재 API 계약 아님

```json
{
  "schema_version":"1",
  "event_id":"external-event-example-001",
  "source_project":"project-placeholder",
  "source_incident_id":"external-incident-example",
  "event_type":"observation.updated",
  "observed_at":"2026-09-27T12:00:00+09:00",
  "sent_at":"2026-09-27T12:00:03+09:00",
  "correlation_id":"exchange-example-001",
  "payload":{"status":"확인 대기"}
}
```

외부가 내부 session_id를 임의 지정하기보다 서버의 등록된 사건 매핑을 사용하도록 설계한다. received_at은 수신 서버가 기록한다. observed_at과 received_at을 구별해 늦은 정보가 최신 사실을 덮어쓰지 않게 한다. schema_version으로 변환 계약을 관리한다. 필드 이름·event_type·경로는 상대 API 확인 후 확정한다.

## 5. 중복·충돌·실패

- `(source_project,event_id)`를 중복 방지 키로 검토한다. 같은 ID·같은 내용은 재반영하지 않고, 다른 내용이면 충돌 기록을 남긴다.
- 역순으로 온 오래된 자료는 원문을 보존하되 최신값 대체를 별도 판단한다.
- 사용자 정정과 외부 값이 다르면 각각 출처를 보존하고 장부 version 기준으로 충돌을 처리한다.
- 재시도는 상대가 지원하는 멱등 키·재시도 가능 오류·최대 횟수를 먼저 정한다. 무제한 재전송하지 않는다.
- 양방향 반사 전송은 event_id·출처·상관 ID로 추적해 루프를 막는다.
- 부분 장애는 상대 프로젝트별로 표시한다. 하나의 연동 장애로 다른 세션·모델·로컬 기록을 중단하지 않는다.
- 중단 후 미전송 항목을 복구하려면 영속 송신 대기 기록이 필요하다. 현재 메모리 run 큐만으로 송신 보장을 주장하지 않는다.

## 6. 보안·사용자 통제

현재 로컬 X-Session-Token을 외부 프로젝트 인증으로 그대로 공유하지 않는다. 상대별 자격증명·최소 권한·TLS·필요 시 웹훅 서명과 재전송 방지를 정한다. 비밀은 서버 설정으로 관리한다.

송신 필드 허용 목록을 두고 대화 원문 전체·다른 세션·키·내부 설정을 무조건 보내지 않는다. 외부 전송과 실제 명령 실행은 구분하며 실제 조치 기능이 추가되면 그 동작별 사용자 승인·확인 정책을 명시한다.

운영 화면에는 연동 이름·최근 성공 시각·자료 기준시각·실패·재시도·미확인 상태를 보여준다. 재시도 전송을 새 현장 보고나 새 AI 완료로 표시하지 않는다.

## 7. 권장 구현 단계와 완료 조건

1. 대상 조사: 위 2의 계약과 샘플 응답 확보. 미정 항목이 남으면 구현 가정을 문서화.
2. 한 프로젝트 읽기 연동: 외부 가상 데이터 → 지정 세션 근거 저장. 출처·시각·단위 확인.
3. 갱신안 연결: 정정·오래된 자료·중복·버전 충돌을 검사하고 장부 오염 방지.
4. 제한된 송신: 전송 필드와 대상 선택, 수신 확인·실패 기록. 실제 조치 완료와 구별.
5. 두 번째 프로젝트: 독립 장애·세션 매핑·역순 이벤트·루프 방지 검증.
6. 운영 확인: 재시작 복구·자격증명 교체·연동 끊기·로그·자료 보존 시험.

수용 사례는 정상 양방향 왕복, 중복 수신, 역순 정정, 인증 실패, timeout, 잘못된 스키마, 다른 사건 접근 거절, 재시작 후 미전송 복구, API 단절 중 기존 앱 유지다. 상대 프로젝트의 성공 응답을 실제 현장 출동 완료로 처리하지 않는지도 확인한다.

## 8. 다른 개선과 우선순위

현재 우선 과제는 빠른 배정의 실행 책임 분리, 의미 기반 핵심 질문·제안 선정, 위험 해소·기출동 중복 제안 방지, 최신 UI/LIVE 회귀다. 프로젝트 API 연동은 이들과 독립된 후속 기능으로 관리한다. 벡터 검색·멀티모델 비교·장기 기억은 미완료다. MCP는 승인형 보고 수신 부분만 구현했으며, 결과 조회·양방향 송신·실제 팀 앱 호환 시험은 후속 범위다.

## 2026-09-28 · 링크온 조회 방식 구체화

사용자가 **링크온이 필요할 때 해온 API를 조회**하는 방식을 선택했다. [사건별 상황 요약 JSON 설계](../superpowers/specs/2026-09-28-linkone-summary-api.md)와 [구현계획](../superpowers/plans/2026-09-28-linkone-summary-api.md), [가상 계약 예제](../contracts/linkone-summary-v1/README.md)가 이 범위의 최신 제안이다.

해온이 제공할 인자는 사건 ID/명칭·LIVE/DEMO·장부 버전·현재 인원/위치·저장된 요약/권고/불확실성/질문·요약 기준 버전/생성 시각·분석 상태·변경 식별자다. 일반 JSON 조회가 1차, 같은 JSON의 MCP 조회는 후속 단계다. 기존 MCP 수신함은 그대로 사용한다.

위 §7의 일반적인 송신 대기열·자동 전달 단계는 이번 조회 구현의 필수 조건이 아니다. 사용자 선택에 따라 webhook/outbox를 이번 범위에서 제외했다. 기존 수신 사건 연결에 사건별 요약 공유 설정을 추가하는 제안이며, 아직 신규 API나 공유 설정을 구현하지 않았다.

사용자가 제공한 링크온 DB 스키마의 [필드 대응 분석](../contracts/linkone-summary-v1/linkone-db-mapping.md)을 추가했다. 사건 연결은 room.id를 사용하고, 실제 집계·취소 규칙을 확인하기 전에는 DB 행 수/이벤트 수를 해온 인원으로 자동 변환하지 않는다.


## 2026-09-28 · 링크온 SSH·DB 접속 준비 회신

사용자가 전달한 링크온 개발자 회신을 기준으로 [외부 전달 문서](../handoff/LINKONE_CONNECTION_REPLY.md)를 작성했다. 현재 제공 범위는 SSH 터널을 통한 링크온 → 해온 읽기 전용 조회다. 기존 해온 요약 조회 API 설계는 보존하되 이번 접속·연동 범위에 포함하지 않으며, 링크온 측과 합의된 양방향 연동으로 표현하지 않는다.

전용 공개키는 아직 생성·전달·등록하지 않았다. 문서에는 접속 조건, 훈련 사건, 초기 조회 대상, 5초 간격 제안·1,000건 제한, 공개키 등록 요청과 sync 응답/인증/변경 범위 확인사항을 담았다. DB 비밀번호·개인키·토큰 값은 기재하지 않았다. 공개키가 포함된 등록 요청 완료본과 구별한다.

이번 작업은 문서 작성과 정적 확인뿐이다. 앱 코드·사용자 runtime·비밀 파일은 변경하지 않았고 도구 설치·SSH/DB/API 접속·단위/HTTP/브라우저/LIVE 시험은 실행하지 않았다.


### 2026-09-28 · 링크온 후속 회신 반영

[접속 준비 문서](../handoff/LINKONE_CONNECTION_REPLY.md)에 인증 없는 GET /api/sync, 최대 20개 rooms, all/rooms 문자열 변경 비교, 재시작 기준 재조회, 5초 주기, 이력 30초 중복 조회·ID 중복 제거, person/transfer 재조회, 종결 후 재개 지원을 반영했다. 회신의 권장 방식과 해온의 보완 검토를 구분하며 30초 중복 조회만으로 무누락을 보장하지 않는다. 공개키 생성·전달·등록은 미완료이고 전달 경로에는 예시 표기가 남아 있다. 이번 변경은 문서만이며 외부 API·SSH·DB 접속과 앱 시험은 미실시다.


## 2026-09-28 · 링크온 로컬 접속 준비 실행

사용자 지시로 [접속 준비와 실행 안내](../handoff/linkone-access/README.md), 공개키 등록 요청·공개키 파일을 준비했다. 개발 전용 Ed25519 키는 사용자 SSH 폴더에 생성했고 개인키 권한은 600이다. 전달받은 DB 비밀번호와 전용 SSH 설정·검증한 known_hosts·psycopg 3.3.6 가상환경은 기존 Git 제외 경로 prototype/.secrets/linkone에 보관했다. 비밀값은 문서에 포함하지 않았다. 암호 없는 키이며 기존 SSH 기본 설정은 변경하지 않았다.

수동 점검 도구 prototype/linkone_access.py는 local/sync/tunnel/db를 제공한다. DB 점검은 읽기 전용 옵션과 권한 메타데이터 확인 후 지정 사건 핵심 5개 테이블에서 최대 20행씩 조회하며 결과 본문은 출력·저장하지 않는다. 자동 수신·장부 변경·모델 호출은 구현하지 않았다.

실행 결과: SSH 서버 지문 일치, 시스템 curl/API 점검 정상, 로컬 검사·구문 검사·도구 보호 검사 5개 통과, Git 비밀 경로 제외 확인. 첫 Python HTTPS는 URLError로 실패 후 인증서 검증을 유지한 시스템 curl로 성공했다. 비밀번호 저장 첫 시도는 빈 표준입력으로 빈 파일이 생겨 바로잡았고 local 검사 통과를 확인했다. SSH 인증 시험은 Permission denied(publickey,password)로 실패했다. 클라이언트는 공개키만 시도했으며 링크온 담당자의 공개키 등록이 남아 있다.

공개키 메시지 발송·원격 등록·실제 DB 접속/권한/데이터 검증·앱 전체 단위/HTTP/브라우저/LIVE는 미실시다. 기존 실행 앱·사용자 runtime 자료는 변경하지 않았다.


### 공개키 전달 완료 후 개발 환경 재확인

사용자가 공개키 송신 완료를 확인했다. [개발 환경 재확인 기록](../handoff/linkone-access/README.md)에 Python 3.11.9·SQLite 3.45.1·Node v24.7.0·의존성 검사·로컬 키/비밀 권한·Git 제외·공개키 ZIP 일치와 모의 보호 시험 5개 재통과를 기록했다. 변경 API는 정상 응답했지만 SSH 재인증은 255 Permission denied로 실패했다. 등록 반영 여부나 서버 설정 원인은 확인하지 못했다. 원격 DB 접속·실데이터 조회와 앱 전체 회귀/HTTP/브라우저/LIVE는 실행하지 않았다. 이번에는 상태 문서만 수정했으며 설치·키 교체·앱 동작 변경은 하지 않았다.


### 공개키 등록 후 SSH·DB 실접속 성공

링크온 등록 완료 회신 후 검증된 서버 지문으로 SSH 터널 및 linkone/linkone_ro 읽기 전용 DB 연결에 성공했다. 제한 컬럼 4개 SELECT 권한 없음, public 일반·파티션 테이블/컬럼 쓰기 권한 메타데이터 확인. 훈련 사건은 room 1행·나머지 핵심 4개 표 0행이며, 추가 제공 퀸메리호 사건의 최대 20행 샘플은 person 20·person_state 6·person_event 20·transfer 0이었다. 전체 건수/인원수로 해석하지 않는다. [담당자 전달 결과](../handoff/linkone-access/CONNECTION_RESULT.md)를 작성했으며 직접 발송하지 않았다. DB 쓰기·행 본문 저장/출력·해온 자동 반영·LIVE 호출은 하지 않았다. 이송·정정 시험 데이터가 필요하며 자동 수신 구현은 후속이다.


### 퀸메리호 침수 시험 수신

사용자 요청으로 실제 링크온 DB를 읽기 전용 REPEATABLE READ로 조회해 [시험 수신 결과](../handoff/linkone-access/QUEENMARY_RECEIVE_RESULT.md)를 작성했다. 선택 컬럼 10개 테이블: room 1, person 100, person_state 6, person_event 44, hull_tilt 2, roster_upload 1, transfer/transport_order/no_accept/room_closure 각 0행. 데이터 쿼리는 5초 간격·최대 1,000행이다. 이전 20행 샘플 결과와 구분한다. runtime/linkone-receive/20260928T093646994891Z에 JSON·무결성 목록·재현 스크립트를 저장했다. 파일 해시/행 수/컬럼/권한/Git 제외 및 참조 검사 8개 통과. 상태 미생성 94명을 미구조로 확정하지 않는다. 사진 등 바이너리·인증 비밀 컬럼은 제외했다. 해온 장부·세션 변경·AI/LIVE 분석은 하지 않았고 SSH 터널은 종료했다.
