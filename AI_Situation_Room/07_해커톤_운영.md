> 2026-09-26 현행화: 현재 구현·검증·남은 과제는 [13번 인수인계 문서](13_현재상태_요구사항_인수인계.md)를 기준으로 한다. 본문의 목표·수용 기준과 날짜별 기록을 구현 완료로 해석하지 않는다.

> 통합 개정본 v2 · 공식 일정과 팀 내부 운영안을 분리한다.

## 2. 담당은 사람 수에 맞춘다

| 팀 규모 | 운영안 |
|---|---|
| 1인 | 한 흐름씩 구현, 고정 입력 버튼과 녹화 준비, 작업 전환 최소화 |
| 2인 | A: 실행·저장·요원·발표 / B: 자료·화면·검증·데모 조작 |
| 3인 이상 | 실행, UI, 자료·검증을 나누고 발표자는 가급적 한 명 |

공통 스키마와 통합 담당을 정하고 동일 파일을 동시에 수정하지 않는다. 인력이 부족해도 모든 역할별 전담자를 가정하지 않는다.

## 3. 현장에서 확인할 사항

- 사전 코드·템플릿·자료 반입과 재사용 범위
- 웍스 AI의 외부 호출, 파일 검색, MCP·이벤트 지원
- 제공 모델·키·호출 한도·네트워크 접근
- 실제 발표 제한시간과 질의응답 포함 여부
- 발표자료 제출 형식·마감·영상 포함 가능 여부
- 발표 준비시간 중 코드 수정 가능 범위
- 공식 심사기준·배점

이 사항을 미리 금지 또는 허용으로 단정하지 않는다. 허용 범위를 확인한 뒤 준비된 구현계획을 적용한다.

## 4. 사전 준비와 당일 개발

자료는 가상 명부·자원표, 검증 가능한 지침, 02의 시나리오를 사용한다. 실행 환경·한국어 임베딩 다운로드·기상 호출·MCP 예제는 허용 범위에서 사전 확인한다.

프로젝트 120분의 구현 배분은 04를 단일 기준으로 사용한다. 첫 60분 안에 작은 접수·지시·재지시 흐름을 확보하고 마지막 25분은 검증·녹화·백업에 남긴다. 교육 제공 예제가 없다면 동일 범위 달성을 보장하지 않는다.

발표 설명·스크린샷은 기능이 작동할 때마다 확보한다. 마지막에 처음 발표자료를 만들지 않는다.

## 6. 장애 대응 큐

| 상황 | 행동 | 발표 멘트 |
|---|---|---|
| 기상 지연·실패 | 미확인 상태 유지, 다른 보고 설명 | “기상 조회가 지연돼 해당 정보는 미확인으로 남깁니다.” |
| 요원 실패 | 실패 영향·나머지 보고 표시 | “이 항목은 추가 확인이 필요합니다.” |
| 라이브 계속 불가 | 명시적인 사전 실행 재생 | “같은 시나리오의 사전 실행 화면으로 이어가겠습니다.” |

## 7. 백업·비밀정보

백업 대상은 소스·의존성 목록, 가상 데이터·지침 출처, 비밀값 없는 설정 예시, 발표본·PDF·녹화·정상 이벤트 기록이다. API 키가 든 env 파일, 원본 비밀정보, 개인자료는 공유 ZIP·화면·로그에 포함하지 않는다.

사용하지 않는 AIS 키를 기상 설정으로 재사용하지 않는다. 이번 문서 묶음에도 키를 넣지 않는다.

## 현재 실행·발표 준비 인수인계 — 2026-09-26

- 기존 일정은 제공 커리큘럼에 대한 당시 기록이다. 이번 문서 작업에서 주최 측 최신 공지를 재확인하지 않았다.
- 실행은 루트 `상황실 실행.command` 더블클릭. 키는 `prototype/.secrets/openai_api_key.txt`에 직접 넣는다. 숨김 폴더 표시는 Command+Shift+.이다.
- 이미 서버가 켜져 있으면 실행 파일은 화면만 연다. 새 코드 적용은 Control+C로 종료 후 다시 실행하고 화면을 새로고침한다.
- 담당자 `/`, 고정 상황판 `/monitor`, 복귀 링크를 사전 점검한다. 입력은 Enter 전송·Shift+Enter 줄바꿈이다.
- `presentation/index.html`은 별도 설명 자료다. 최신 앱 녹화와 구현 상태를 제출 전에 반영한다. 키·runtime·원본 환경설정은 제출물에 넣지 않는다.
- 청해호 가상 시험 원문과 검증 결과를 보존한다. 현재 medium 설정으로 재시험하고 대형 장비·거리·두 화면 리허설을 기록하는 작업이 남아 있다.
