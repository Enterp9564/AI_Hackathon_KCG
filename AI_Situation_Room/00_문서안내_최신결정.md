## 최신 확정 방향

- 상황실장은 요청 범위만 짧게 파악해 전문요원에게 먼저 배정하고, 요원 보고·검증 후 핵심 제안과 확인 질문을 사용자에게 전달한다.
- 요원은 정보·수색구조·자원지원·검증으로 구성한다. 필요한 독립 임무를 실제 병렬로 수행하고 배정 이유·상태·개별 보고·최종 보고를 연결한다.
- 하위 요원도 필요한 정보를 상황실장에게 요구한다. 사용자에게 질문할 때는 필요한 이유를 짧게 설명한다.
- 출동 제안은 사용자 제공 동해 세력과 기본 매뉴얼을 활용한다. 현재 위치·가동·실제 출동은 별도 보고로 확인한다.
- 실제 요청 모델은 `gpt-6-luna`, 모든 역할 추론 수준은 `medium`이다. 화면에는 모델명·추론 수준을 노출하지 않고 LIVE/DEMO 실행 방식만 구분한다.
- 새 세션은 키가 있으면 LIVE 기본이며 여러 세션의 기억은 분리한다. 삭제 확인과 진행 중 삭제 차단을 구현했다.
- 담당자 화면과 고정 대형 상황판을 함께 제공한다. 상단 진행 상태, 전송 직후 피드백, 단계 강조, Enter 전송·Shift+Enter 줄바꿈, 대형화면 복귀를 적용했다.
- 제안·질문은 각각 앞 2건만 기본 표시한다. 실제 생성량 축약·질문 해결 추적은 남은 과제다.
- 시뮬레이션은 가정 기반 조건 비교이며 현재 장부와 분리한다. 물리 예측은 구현하지 않았다.
- 외부 데이터 API는 무료 범위의 기상·해상 정보만 대상으로 한다. AIS·MMSI·실제 자원 위치 시스템은 초기 범위에서 제외한다. LLM 비용은 별도다.

## 실제 구현과 남은 차이

현재는 Python 표준 HTTP 서버·SQLite·HTML/CSS/JavaScript로 실행한다. Streamlit은 과거 후보다. 단어 기반 자료 검색과 수동 기상 코드가 있으며 Chroma·벡터 RAG·MCP·해상 파고·자동 조회·멀티모델 비교는 미구현/미실시다.

빠른 배정 요구는 화면과 프롬프트에 반영됐지만 첫 모델 호출이 아직 장부 갱신과 배정을 함께 수행하고 서버가 출동 후보를 먼저 생성한다. 13번 문서의 우선 과제로 남긴다. 코드와 문구가 있다는 이유로 실제 지연 개선·현장 사용성 검증 완료를 주장하지 않는다.

## 검증과 발표의 기준

청해호 가상 15건은 첫 LIVE 시험에서 수용 실패, 개선 후 중간 1건을 차단·수정·재실행해 최종 저장 검사 PASS였다. 2026-09-26에는 기존 저장 결과 재검사와 핵심 단위 39개, JavaScript 문법 검사를 통과했다. 최신 설정의 새 LIVE 전체 시험·HTTP·브라우저 회귀는 이번에 실행하지 않았다.

발표 HTML의 A호 5→7명 예시와 청해호 7→8명 시험을 혼합하지 않는다. 발표 효과는 설명용이고 실행 증거는 실제 앱 기록으로 제시한다. 공식 커리큘럼의 기존 기록은 팀별 10분 표기이며 5분 압축본도 준비한다. 공식 배점·질의응답 포함 시간·반입 규칙은 현장 확인 사항이다. 이번 현행화는 공식 자료의 재확인이 아니다.
