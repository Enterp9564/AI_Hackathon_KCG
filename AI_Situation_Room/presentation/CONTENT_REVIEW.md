# 발표 내용 점검 및 작성 근거

> 최신 자료는 2026-09-27 두 발표자료이며 마지막 절과 PRESENTATION_BRIEF.md를 참조한다. 아래 기존 10장 분석은 제작 당시 이력으로 보존한다.

> 이 문서의 장면별 인용은 제작 당시 작성 근거다. 2026-09-26 현재 앱에는 실제 API·장부 갱신 등의 후속 구현이 있으나 HTML에 자동 반영되지 않는다. 최신 사실과 남은 증거는 [13번 문서](../13_현재상태_요구사항_인수인계.md)를 따른다.

## 점검 결론

기존 발표는 시각적 화면 안내에는 적합했지만, 시상 전략을 설명하는 순서와 증거의 비중은 보완이 필요했습니다. 기능과 시나리오가 문서에 부합한다는 점과, 실제 구현 성과를 증명했다는 것은 구분해야 합니다. 이번 수정은 **발표 구성과 문구의 전략 정합성**을 높이며 제품 실행 증거를 대신하지 않습니다.

| 기존 문제 | 수정 |
|---|---|
| 요원 지시 설명이 1:45부터 시작 | 0:30부터 요원 지시 장면: 첫 1분 목표 반영 |
| 명부 불일치가 2:45에 등장 | 1:15에 불일치, 1:45에 확인·재지시 배치 |

| 기술스택 소개가 비교·검증을 압도 | 기존 입체 레이어를 규칙 검사·AI 검증·두 모델 비교·실패와 복원으로 재작성 |
| 문서명만 표시해 주장과 근거 연결이 약함 | B 키: 해당 절·직접 인용·구성 이유·추가로 필요한 실증 증거 제공 |
| 업무효과가 추상적으로 반복됨 | 재입력 부담 감소·역할별 조사 가시화·정정 이력 추적이라는 목표로 구체화 |

## 근거의 성격

- **공식 원자료:** 제공된 커리큘럼 이미지에는 RAG, MCP 기반 도구 연동 에이전트, 멀티모델 비교 및 에이전트 신뢰성 검증, 팀별 10분 발표, 과학기술정보통신부장관상이 표기되어 있습니다.
- **공식 평가표:** 제공되지 않았습니다. 임의 배점·수상 확률·경쟁팀 우열은 작성 근거로 사용하지 않았습니다.
- **전략적 해석:** 06번 문서의 “업무 적용과 교육 통합을 실제 증거로 보여준다”는 방향을 채택했습니다. 이는 공식 배점의 대체물이 아닙니다.
- **제품·시나리오 요구사항:** 01·02·03번 문서의 범위와 인원 수치, 사용자 확인 절차를 사용했습니다.
- **계획과 사실의 구분:** 제작 당시 API·RAG·MCP·모델 비교는 계획이었습니다. 현재 API 실호출 기록은 있으며 벡터 RAG·MCP·모델 비교는 미완료입니다. 원문에 남아 있는 과거 AIS 시험은 현재 발표의 제품 성과로 사용하지 않았습니다.
- **외부 기술 참고:** 이번 보완에서 Anthropic의 [다중 에이전트 연구 시스템](https://www.anthropic.com/engineering/multi-agent-research-system)과 [Building effective agents](https://www.anthropic.com/engineering/building-effective-agents)를 확인했습니다. 역할별 맥락·선택 배정·병렬화의 참고이며, 이 프로젝트의 비용 절감이나 정확도 향상을 증명하지 않습니다.

### 3. 왜 여러 AI인가 · 0:30–0:55

**핵심 문구:** 필요한 순간, 필요한 전문성에 추론을 집중한다.

사용자는 하나의 사건 대화를 이어가고, 내부에서는 필요한 전문 역할만 선택해 각자의 자료·지침·도구로 집중 검토한다. 독립 작업은 병렬 처리하고, 새 정보에 영향받는 임무만 재검토하며 상황실장이 최종 보고를 종합한다. 이 구성으로 불필요한 반복을 줄이고 사용자의 선택을 돕는 것이 목표다.

**직접 근거:** [05 발표자료 §3.1](../05_발표자료.md)의 설계 원칙과 사용자 추가 요구. HTML의 B 키에는 동일 문구의 인용과 비교 계획을 제공한다.

**표현 경계:** 전문 역할 구성은 별도 전문가 모델 학습이 아니다. 하나의 사용자 대화는 하나의 공유 LLM 컨텍스트를 의미하지 않는다. 다중 에이전트는 조정 비용이 추가될 수 있으므로 총자원 절감·속도·품질 우위를 측정 전 사실로 쓰지 않는다.

**확보할 실행 증거:** 동일 조건에서 단일 에이전트·전원 호출·선택 호출의 총 토큰·비용·보고 시간·오류·누락을 비교한다. 실제 지시·보고와 실행 구간도 연결한다. 25초 대본은 목표이며 실측 리허설이 필요하다.
