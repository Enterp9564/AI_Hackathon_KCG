# 데이터·API 설계와 검증 기록

> 2026-09-27 문서 연결: 현재 코드의 [기상 계약](docs/implementation/12-weather.md)·[로컬 HTTP 계약](docs/implementation/13-http-api.md)을 분리했다. 여러 프로젝트와 정보 교환은 [향후 API 연동 개선안](docs/improvements/01-project-api-integration.md)이며 대상·주소·인증 미정이다. 아래 무료 기상 중심 범위는 현재 프로토타입에 적용한다.

> 2026-09-26 현행화: 현재 구현·검증·남은 과제는 [13번 인수인계 문서](13_현재상태_요구사항_인수인계.md)를 기준으로 한다. 본문의 목표·수용 기준과 날짜별 기록을 구현 완료로 해석하지 않는다.

> 통합 개정본 v2 · 인증키 값은 기록하지 않는다.
> 상태 기준: 공식 명세 확인 / 실제 응답 검증 / 미검증 / 초기 범위 제외.

## 1. 최신 결정

외부 데이터 API는 **무료 범위의 기상·해상 정보만** 사용한다. 선박·MMSI·AIS는 초기 구현에서 제외한다. 선박정보·사고 위치·명부는 사용자 제공자료, 가용세력 목록은 사용자 제공 동해 운영자료를 로컬 JSON으로 등록하며 실제 위치·가동 상태는 미연동이다.

LLM API 이용료는 별도이며 외부 데이터 API 무료 원칙과 혼동하지 않는다.

## 2. 기상 API 기본 제안

Open-Meteo를 첫 연결 후보로 둔다. 공식 문서는 좌표 기반 기상·해양 조회와 비상업 무료 이용 범위를 안내한다. 일반 기상과 파고는 서로 다른 엔드포인트를 쓰되 요원에게는 get_weather 도구 하나로 제공한다.

| 기능 | 공식 경로 | 우선 항목 |
|---|---|---|
| 기상 | https://api.open-meteo.com/v1/forecast | wind_speed_10m, wind_direction_10m |
| 해상 | https://marine-api.open-meteo.com/v1/marine | wave_height |
| 추가 후보 | 해당 공식 문서 확인 | 기온·시정·수온 |

기상요청은 wind_speed_unit=ms, timezone=Asia/Seoul을 검토하고 해양 요청에도 시간대를 맞춘다. 반환 단위와 시각은 응답으로 재확인한다. Open-Meteo의 current 항목도 모델 기반일 수 있으므로 현장 실측으로 표시하지 않는다.

초기 기록은 공식 문서 확인 단계였다. 이후 수동 Forecast 호출 코드를 앱에 연결했지만 실제 응답 성공 검증은 아직 남아 있다. 이번 현행화에서는 외부 API를 호출하지 않았다. 제공자 확정 전 시연 좌표에서 성공·빈 값·시간·단위를 검증한다.

출처: [기상 문서](https://open-meteo.com/en/docs), [해양 문서](https://open-meteo.com/en/docs/marine-weather-api), [요금·이용 조건](https://open-meteo.com/en/pricing).

무료 API에는 호출 제한과 가용성 보장 부재가 있다. 출처표시와 이용 조건을 지키고, 실제 서비스 배포 단계에서는 용도 적합성을 다시 확인한다.

## 3. 기상 도구의 최소 계약

입력: incident_id, latitude, longitude, 조회 대상시각 또는 현재 조회 명시.

출력:
- status: ok / partial / unavailable
- source, data_kind: forecast 또는 관측임이 확인된 경우 observation
- requested_coordinates, returned_coordinates
- retrieved_at: 실제 조회시각
- 항목별 valid_at, value, unit, source_ref
- cache_used, missing_fields, errors

기상·해양 결과의 격자나 기준시각이 다르면 하나의 동일 관측으로 합치지 않는다. 요청 좌표와 반환 좌표 차이를 보존한다. API가 모델 발행시각을 제공하지 않으면 조회시각으로 대신 채우지 않는다.

조회 시점은 최초 위치 확보, 위치 변경, 사용자 재조회 요청을 우선한다. 매 채팅·화면 갱신마다 자동 호출하지 않는다. 짧은 캐시는 가능하나 자료 기준시각·캐시 여부를 표시한다.

2026-09-25 상시 모니터링 설계: 11 §7은 활성 사건의 서버 단일 스케줄에 의한 정기 재조회를 제안한다. 30분 간격은 초기 후보이며 제공자 한도·자료 시간 해상도·실제 응답 검증 후 활성화한다. 두 화면에서 별도로 실행하지 않고, 사건 종료 시 중단한다. 미구현이면 수동 조회로 표시한다. 현재 화면의 약 1초 상태 조회와 외부 기상 재조회는 별개다.

## 4. 첫 연결 시험과 완료 기준

시연 지점 북위 37.50도·동경 129.50도를 사용한다.

1. 일반 기상과 해상 요청의 HTTP 상태·실제 JSON을 확인한다.
2. 풍속·풍향·파고의 유효 값, 단위, 시각, 반환 좌표를 검사한다.
3. 현재 요청에 오래되거나 다른 시점의 자료가 반환되면 표시·차단 정책을 확인한다.
4. 부분 실패·빈 값·잘못된 좌표를 테스트한다.
5. 도구 결과를 정보요원 보고와 대시보드에 연결한다.
6. 실제 MCP 클라이언트에서 같은 도구를 호출하고 결과를 기록한다.

REST 요청만 성공하면 ‘기상 API 호출 성공’이다. MCP 연결과 앱 통합 완료는 별도 판정한다. 당시 기상이 잔잔해도 시연은 성립한다.

## 5. 저장과 벡터DB

| 저장 대상 | 방식 |
|---|---|
| 사건·대화·임무·계획·기상 결과 | 일반 DB |
| 승선원 명부 | 전체 구조화 데이터, ID 단위 대조 |
| 첨부 원본·추출 텍스트 | 파일과 메타데이터 |
| 지침의 관련 구절 | 벡터DB + 원문 출처 |

빠른 구현 후보는 로컬 Chroma PersistentClient다. 별도 벡터 서버·Docker를 필수로 하지 않는다. 교육 플랫폼에 검증 가능한 검색 기능이 있으면 재사용을 검토한다. [Chroma 공식 문서](https://docs.trychroma.com/docs/run-chroma/clients)

문서 3개부터 절·문단 단위로 나누고 문서명·절·버전·원문을 저장한다. 관련 구절 3개 정도를 검색해 생성에 사용한다. 한국어 임베딩 모델은 로컬 실행 후보를 실제 질문 5개로 확인한 뒤 정한다. 임베딩 다운로드·라이선스·추론시간은 선행 확인사항이다.

벡터 검색은 명부 총원 계산이나 현재 기상값 조회를 대체하지 않는다. 샘플 지침을 실제 기관 매뉴얼처럼 인용하지 않는다. 검색 결과가 없으면 없음으로 보고한다.

## 6. AISStream 실제 시험 기록 — 초기 범위 제외

사용자 제공 키로 서버 연결과 SubscriptionConfirmation을 확인했다.

| 범위 | 수신 시간 | 결과 |
|---|---:|---|
| 북위 37.2부터 38.0, 동경 128.8부터 130.2 | 30초 | 구독 승인 1건, 선박 메시지 0건 |
| 북위 32부터 39, 동경 124부터 132 | 30초 | 구독 승인 1건, 선박 메시지 0건 |

첫 시험은 주요 위치·정적 메시지 유형을 선택했고, 확대 시험은 메시지 유형 필터 없이 진행했다. 짧은 두 번의 시험이며 한국 해역 전체의 미지원이나 원인을 입증하지 못했다. 실시간 국내 시연 자료로 채택할 수 있을 만큼의 수신 검증은 확보하지 못했다.

이후 사용자가 MMSI API 보류, 최종적으로 기상만 연동을 결정했다. 추가 구독은 유지하지 않는다. [AISStream 공식 문서](https://aisstream.io/documentation)

## 7. 공공 AIS API 실제 시험 기록 — 초기 범위 제외

대상: 해양수산부_지능형해양수산재난정보체계_AIS정보

[공식 Swagger](https://infuser.odcloud.kr/oas/docs?namespace=15141997/v1)

경로:
`https://api.odcloud.kr/api/15141997/v1/uddi:e04457d7-7456-462b-aec5-b9c1a14600fe`

| 확인 항목 | 실제 응답 |
|---|---|
| 전체 조회 | 1,000건 + 719건, 합계 1,719건 |
| 선박번호 고유값 | 1,719개 |
| 수신 날짜 | 모두 2024년, 값의 범위 2024-01-01부터 2024-12-31 |
| 위도·경도 | 응답에 없음 |
| 선박명 누락 | 1,006건 |
| IMO 0 | 1,419건 |
| 호출부호 숫자/문자 0 | 1,236건 |
| 선박번호 길이 | 9자리 1,566건, 8자리 139건, 7자리 8건, 6자리 2건, 10자리 4건 |

선박번호 조건 `cond[선박번호::EQ]=414920000`으로 일치 1건, 없는 번호 000000000으로 0건을 확인했다. 예시 선명은 CHANG HANG YUAN HAI, 수신일은 2024-02-20이다.

2,000건 단일 요청에서 502가 발생했고 1,000건씩 페이지를 나눠 전체를 확인했다. 해당 오류를 API 전체 장애나 요청 한도 확정으로 일반화하지 않는다.

일부 0은 결측 표지로 의심되지만 속도 0처럼 유효할 수 있는 값도 있어 일괄 누락 처리하지 않는다. 선수방위·속도 단위와 배율도 문서 확인 없이 변환하지 않는다. 필드명은 선박번호이며 모든 값을 정상 MMSI로 확정하지 않는다.

결론: 현재 선박 위치·기상 자동 연계 목적에 부적합해 채택하지 않는다. 이 과거 자료를 현재 상태처럼 제시하거나 실시간 API라고 설명하지 않는다.

## 8. 자격증명 취급

이번 문서와 배포 묶음에는 인증키와 env 원본을 포함하지 않는다. 기상 도구에는 필요한 설정만 전달한다. 향후 다른 API 재검토 시 제공범위·최신성·국내 수신·비용·조회 성공을 먼저 확인한다.


## 9. 현재 데이터 연결 상태 — 2026-09-26

| 대상 | 코드와 검증 상태 |
|---|---|
| 모델 | Responses 실제 호출 이력 있음. 현재 모든 역할 medium, 최신 설정 전체 LIVE 재시험은 미실시 |

이번 현행화는 외부 API·공개 URL의 재검증이 아니다. 기존 출처는 보존하고 호출 성공·문서 확인·사용자 진술을 구분한다. 키 값은 기록하거나 배포하지 않는다.
