# AI 해커톤 시상 준비 전략

> 2026-09-26 현행화: 현재 구현·검증·남은 과제는 [13번 인수인계 문서](13_현재상태_요구사항_인수인계.md)를 기준으로 한다. 본문의 목표·수용 기준과 날짜별 기록을 구현 완료로 해석하지 않는다.

> 통합 개정본 v2 · 공식 사실과 전략적 해석을 구분한다.

## 1. 확인된 시상·교육 정보

제공된 커리큘럼에는 웍스 AI 기반 에이전트 개발, RAG, MCP 기반 도구 연동, 멀티모델 비교, 에이전트 신뢰성 검증이 포함돼 있다. 10/1 15:30부터 16:00에는 우수 프로젝트 시상과 과학기술정보통신부장관상이 명시돼 있다.

공식 세부 배점·평가표·수상팀 수는 제공자료에서 확인되지 않았다. ‘교육성과를 실제 업무에 통합한 결과와 명확한 시연이 중요할 것’이라는 판단은 우리의 전략적 해석이다. 가상 점수 92점이나 수상 확률처럼 근거 없는 숫자는 사용하지 않는다.

## 2. 심사위원에게 먼저 증명할 것

첫 1분 안에 사용자 입력과 실제 임무 지시를 보여준다. 이어서 검색·조회 결과가 대응안에 쓰이는 장면, 명부 불일치와 사용자 정정, 다시 바뀌는 계획을 보여준다. 기술명은 이 장면을 설명하는 근거로 제시한다.

가장 기억에 남길 장면은 **추가 명부를 받은 상황실장이 불일치를 질문하고, 답변을 받아 관련 요원에게 재지시하는 과정**이다. 인원 변화만 강조하는 자극적 연출보다 기록·판단의 연결을 보여준다.

‘왜 여러 에이전트인가’에는 **필요한 시점의 전문 역할 선택 → 역할별 집중 검토 → 독립 작업 병렬화 → 영향받는 임무만 재검토 → 종합·검증**으로 답한다. 추론 자원 낭비 감소와 더 나은 선택 지원은 목표이며, 실제 절감·품질 향상 주장은 05 §3.1의 동일 조건 비교로 뒷받침한다.

## 3. 교육내용 수용 계획

| 교육내용 | 적용 방식 | 확인 증거 |
|---|---|---|
| 자연어 처리·언어모델 | 신고 이해, 업무지시, 보고 요약 | 입력 원문과 구조화 결과 |
| 텍스트 처리·임베딩 | 지침 분할과 의미 검색 | 분할 단위·검색 질문·결과 |
| Word2Vec·CNN 기초 | 개념과 적합한 문제 이해 | 설계 선택을 설명할 배경지식 |
| Agent | 상황실장·요원 책임 분리 | 실제 지시·보고·재지시 |
| RAG | 벡터 검색 근거를 생성에 반영 | 원문 구절과 조치의 연결 |
| MCP | 기상 조회 도구 호출 | 프로토콜 요청·반환 결과 |
| 멀티모델 비교 | 같은 사례·근거·조건으로 2개 모델 비교 | 조건·모델명·오류·시간표 |
| 신뢰성 검증 | 규칙 검사·검증요원·오류 사례 | 불일치 탐지와 수정 과정 |

배운 내용을 종합적으로 수용하되 모든 알고리즘을 억지로 새로 학습시키지는 않는다. 특히 모델 비교는 역할 이름을 여러 개 붙이는 것으로 대신하지 않는다.

## 4. 증거 중심 준비표

| 전략 관점 | 발표에서 보여줄 것 | 구현·측정 상태 |
|---|---|---|
| 업무 적용 | 상황 정리와 추가 자료 반영 | 청해호 장부·정정 개선 시험 기록 있음 |
| 기술 통합 | Agent·RAG·MCP의 실제 연결 | Agent 실행 확인; 벡터 RAG·MCP 미구현 |
| 신뢰성 | 인원 오류·오래된 보고·기상 실패 처리 | 핵심 단위 39개 및 저장 검사 통과; 실제 기상 실패 동선 확인 필요 |
| 완성도 | 사건 접수부터 수정안까지 한 흐름 | 리허설 미실시 |
| 확장성 | 역할과 도메인 자료의 분리 | 설계 제안 |
| 발표 전달 | 채팅·임무 상세·변경 이유의 가독성 | 앱·HTML 있음; 최신 브라우저·대형 장비 재검증 필요 |

공식 배점표가 확인되면 위 관점을 실제 항목에 대응시킨다. 경쟁팀을 보지 않은 상태에서 수준·약점을 단정하지 않는다.

## 5. 우선 투자와 축소

먼저 완성할 것은 실제 지시·보고, 사용자 자료 반영, 근거 검색과 기상, 검증·수정안이다. 화면은 이 작업이 보이도록 함께 만든다.

시간이 부족하면 장식 효과, 복잡한 도면, 다양한 첨부 형식, 지도, 추가 API부터 줄인다. 기상만 연동하기로 한 범위를 유지한다. 핵심 교육요소가 미완성이면 누락을 공개하고 완료라고 설명하지 않는다.

## 6. 모델 비교와 업무효과

동일 입력·근거·출력 요구로 두 모델을 비교한다. 비교 항목은 인원 오류, 출처 없는 주장, 확인 질문, 지시 적합성, 응답시간이다. 설정·실행일·표본 수를 남기며 작은 시험으로 보편적 우열을 주장하지 않는다.

업무시간 절감률은 별도 기준 작업과 비교하기 전에는 발표하지 않는다. 실측이 없으면 ‘정보를 다시 입력하는 부담을 줄이고 변경 과정을 추적하는 것을 목표로 한다’고 표현한다.

## 7. 발표 기준

공식 팀별 10분 표기를 기록하고 5분 압축본을 함께 준비한다. 실제 운영시간을 미리 확정하지 않는다. 05의 공통 슬라이드를 활용하고 시간이 줄어도 명부 확인과 재지시를 남긴다.

발표 종료 시 심사위원이 확인해야 할 것은 ‘AI가 여러 개다’보다 **누가 무엇을 조사했고, 어떤 근거로 계획이 바뀌었는지 알 수 있다**는 점이다.


## 현재 확보한 증거와 시상 준비의 남은 간격 — 2026-09-26

실제 Agent 병렬 호출·개별 보고·최종 종합과 세션 저장, 청해호 장부·이름 정정의 개선 시험 기록이 있다. 매뉴얼과 세력 후보를 제공하고 질문의 이유를 붙이는 코드, 즉시 접수 피드백과 진행 화면도 있다. 반면 빠른 배정의 실제 지연, 최우선 질문·출동안 축약, 최신 브라우저 전체 동선은 추가 검증 대상이다.

교육요소 가운데 벡터 RAG·MCP·동일 조건 멀티모델 비교는 아직 비어 있다. 공통 문서 주입·단어 검색·다섯 역할을 각각 이 기능의 완료로 표현하지 않는다. 시상 전략은 남은 교육 증거를 실제 업무 장면과 연결하고, 완료하지 못한 범위는 명시하는 것이다.

발표의 핵심 순서는 짧은 신고 → 전문요원 배정·실행 → 필요한 정보와 이유 → 정정 반영 → 근거 있는 핵심 제안이다. 성능 수치는 날짜·시험 조건·실패와 재실행 여부를 함께 제시한다. 공식 배점과 수상 결과는 예측해 쓰지 않는다.
