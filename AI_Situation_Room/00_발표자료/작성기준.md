## 최신 인원과 과제

최신 인원은 사용자 지정 4번 이미지 기준이다. 2팀은 신진섭·채민주·김대성·송민주, 총 4명이다. 1~3번 이미지는 과제 내용의 근거로 사용하며 이전 인원표를 최신으로 취급하지 않는다.

과제 신청 기준 역할은 Link-One(신진섭), RESAID AI(채민주), HAEON(해온)(김대성·송민주)이다. 상세 개발 분담은 팀 협의 사항이다. 다른 팀의 구현 수준과 수상 가능성은 제공 자료로 알 수 없다.

## 사용자 요청 반영

각 프로젝트의 화면·기능·개발 자율성을 유지하고, 결과와 확인 요청을 API로 주고받아 현장 협업을 완성한다. 마지막 API 연결 작업과 개발 중 문제 해결을 제안자가 최대한 지원한다는 문구를 팀원용 14장에 넣었다. 발표자는 자신의 약속으로 읽을 수 있다.

최종 연결 이전에 사건·대상자·이벤트 식별과 예제 요청·응답만 작게 합의하는 순서를 제안했다. 현재 API 주소·인증·교환 계약은 확정되지 않았다. 이번 작업은 발표자료 제작이며 앱 API를 새로 구현하지 않았다.

## 기술 스토리의 편집

사용자 제공 `AI_situation_room_RAG_story.md`를 다음 순서로 반영했다.

1. 접수부터 판단·대응안까지 이어지는 HAEON(해온)
2. 근거 없는 판단·누락·충돌을 어떻게 확인할 것인가
3. RAG로 관련 지침 구절을 검색해 근거 공급
4. 현실의 복합 사고에 여러 매뉴얼을 함께 적용
5. 현장 상태와 적용 조건을 대조해 대응안 구성
6. 세 프로젝트가 API로 상태·확인 요청·결과를 주고받으며 갱신

End-to-End는 업무 흐름의 연결을 뜻하며 단일 모델 종단간 학습의 구현 주장으로 쓰지 않았다. AI는 대응안을 제안하고 최종 운영 판단은 사람이 한다. 매뉴얼을 근거로 해석하되 법령·필수 절차는 제약으로 존중한다. 검색 유사도와 조치 우선순위, RAG 사용과 정확성 보장을 구분한다.

기술 참고: Lewis et al., *Retrieval-Augmented Generation for Knowledge-Intensive NLP Tasks*, NeurIPS 2020. <https://arxiv.org/abs/2005.11401>. 검색 자료를 생성 과정에 결합하는 개념을 참고했으며 연구의 성능 수치를 우리 프로젝트에 적용하지 않았다.

## 주장과 증거

- 현재 앱: 실제 모델 호출·요원 실행·병렬 처리·저장·정정 관련 기존 기록이 있다.
- 현재 검색은 단어 기반이며 벡터 RAG·다중 매뉴얼 의미 검색·MCP·두 모델 비교·세 프로젝트 API는 미완료/목표다.
- 공식 평가 배점과 수상 가능성은 미확인이다. 기술적 강점은 실제 업무 기여와 실행 증거로 제시한다.
- A호 5→7명 발표 예시와 청해호 7→8명 기존 시험을 구분한다.
- HTML 도식은 설명과 설계 제안이다. 실제 앱·API가 작동하는 화면이나 증거 영상으로 소개하지 않는다.
- 속도·비용·정확도·시너지의 정량 개선치는 만들지 않았다. 발표 시간도 실측 전 목표다.

## 디자인 선택

팀원용: Taste 기준을 발표 목적에 맞춰 적용. 레이아웃 변화 6, 움직임 3, 정보 밀도 3. 실버 배경·녹색 단일 포인트·같은 계열 한글 산세리프, 표지·관계도·넓은 비교·수평 순서·지원 약속 장면으로 구성했다. 웹 프레임워크를 추가하지 않고 오프라인 HTML을 유지했다. 작은 세로 화면에는 읽기용 단일 열 배치를 적용했다.

최종 발표용: 기존 짙은 배경·시안 포인트·입체 상황실 장면과 조작법을 유지했다. 새 장면에는 동일한 시각 언어로 관계도와 근거 레이어를 추가했다.

## 수상 경쟁력 중심 개정

2026-09-27 사용자 피드백을 반영해 팀원용 15장·8분 목표로 재구성했다. 위의 최초 제작 기록보다 이 절의 편집 방향이 우선한다. 최종 발표용은 이번에 변경하지 않았다.

- 1~6장: 수상 목표, 평가에서 인정받을 이유, 각자의 이익, 팀 구성의 장점, 현장의 정보 불일치, 심사위원에게 보여줄 결과. API 해법을 먼저 공개하지 않는다.
- 7장: 각자 자유롭게 개발하고 API로 결과를 교환하는 해법을 공개한다.
- 8~9장: 스토리 MD를 두 개념도로 요약한다. ① 상황 해석 AI ↔ 다중 매뉴얼 RAG → 근거 있는 제안 ② 현장·응급·지침 → 해온의 자연어 처리·검색·에이전트·검증 → 대응안·질문·변경 이유. 중앙의 기술 통합 책임과 각 프로젝트의 전문성을 함께 보여준다.
- 10~11장: 정확성 향상의 경로와 평가 이점을 실제로 보여줄 증거로 연결한다.
- 12~15장: 부담을 줄이는 범위, 공동 시연, API 연결·개발 지원 약속, 참여 제안.

### 평가 이점을 설명하는 근거

제공 커리큘럼에는 RAG 기반 생성, MCP 기반 도구 연동, 멀티모델 비교, 에이전트 신뢰성 검증과 우수 프로젝트 시상이 있다. 공식 심사표·가산점·항목별 배점은 제공되지 않았다. 따라서 교육 활용·기술 완성도·협업·현장 가치는 팀이 제안하는 평가 전략이며 공식 평가 기준으로 단정하지 않는다. 원자료는 `참고자료/curriculum.png`에 보존했다.

협업은 서로의 결과가 다음 판단에 쓰이는 것으로, API 기술은 실제 요청·응답과 상태 반영으로, 현장 정확성은 불일치 발견·확인·정정 반영으로, 교육 활용은 검색 근거와 요원 보고가 대응안에 쓰이는 과정으로 증명한다. 각자에게는 개발 자율성 유지, 자신의 결과물 활용 범위 확대, 통합 개발 지원이라는 실질적인 이점을 제시한다.

정확성은 현재 측정한 개선치가 아니다. 같은 사건에서 연동 전후의 정보 누락, 정정 반영, 근거 오류를 비교할 계획이다. 벡터 RAG·프로젝트 간 연동 등 미완료 부분을 완료 성과로 소개하지 않는다. 전환 애니메이션은 실행 증거가 아니다.

개정 전 팀 HTML·대본·데이터는 `*-before-merit-revision.*`에 보존했다.


## MCP 중심 문구와 현장 대응 흐름 개정

2026-09-27 최신 사용자 요청에 따라 팀원용과 최종 발표의 프로젝트 간 연결 기술을 MCP로 변경했다. 일반 외부 API와 실제 AI API 호출의 의미는 구분해 유지했다. MCP 서버 구현은 이번 발표 수정 범위에 포함하지 않으며, 두 발표 모두 MCP 적용 계획으로 표시한다.

상황실을 중앙 MCP 서버로 두고 Link-One·RESAID AI가 보고 제출과 최신 결과 조회를 수행한다. 수신 정보는 알림함에 보관하고 담당자가 선택하여 인용·전송한 뒤 AI 요원 검토에 사용한다. 공유와 AI 판단 반영을 구분하며 MCP 자체가 자동 동기화나 정확성을 보장한다고 설명하지 않는다.

팀원용 표지의 큰 수상 문구는 ‘함께 만드는 현장 대응’으로 바꿨다. 4장은 신청 과제 기준으로 세 프로젝트의 고유 역할과 기여를 상세화했다. 5~6장은 급박한 현장 변화, 정보 공유, 대응 계획 검토, 현장 결과의 재보고가 반복되는 흐름이다. 7장은 MCP를 강조하고 9장은 MCP 도구 연동을 명시한다. 전체 문구와 대본은 익숙한 한국어로 다듬었다. 팀원용 목표 시간은 8분 20초, 최종은 10분이다.

최종 발표 12장은 보고 제출·담당자 선택·요원 검토·결과 조회의 MCP 연동 계획으로 변경했다. 표지부터 마무리까지 제목과 본문, 대본을 다듬었으며 기존 입체 디자인은 유지한다. 개정 전 파일은 `*-before-mcp-revision.*`로 보존했다.


## 2026-09-27 · End-to-End 스토리와 개별 프로젝트 소개

사용자 제공 `AI_situation_room_RAG_story.md`를 다시 읽고 최종 발표를 22장으로 재구성했다. 2~4장은 Link-One·RESAID AI·해온의 개별 소개다. 6장 End-to-End 강조, 7장 오답·할루시네이션 질문, 8장 RAG 근거 보완, 9장 매뉴얼과 AI 판단의 관계, 10~11장 복합 사고와 다중 매뉴얼로 이어진다. RAG가 공개되기 전 6~7장의 표시 문구와 대본에서는 RAG 해법을 먼저 설명하지 않는다.

End-to-End는 상황 이해부터 대응 제안까지의 업무 구조로 정의하고 단일 모델 종단간 학습 주장은 피했다. 최종 현장 판단은 담당자에게 있으며, RAG의 오류 감소는 검증할 목표다. 개별 프로젝트 소개는 기존 신청 과제와 팀의 개발 방향을 바탕으로 작성했다. 전체 10분 목표로 시간 배분과 대본을 갱신했고 실측 리허설은 남아 있다.

검증: 핵심 7장(2·3·4·6·7·8·9)의 1280×720 브라우저 화면 확인, 22장 데이터·대본 일치, 시간 합계 600초, JavaScript 문법, 한글 배포본 동기화, 로컬 근거 링크 대상 존재 확인. 수집된 JavaScript 오류 0건. 초기 미리보기는 종료된 서버로 연결 실패했고, 발표 폴더만 제공하는 루프백 서버를 허용된 실행으로 재시작한 뒤 확인했다. 앱 기능·LIVE·MCP 실행·모바일 시험은 이번 범위에 포함하지 않았다.
