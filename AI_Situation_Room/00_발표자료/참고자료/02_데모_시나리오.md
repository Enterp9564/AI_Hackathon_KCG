# AI 종합상황실 데모 시나리오

> 2026-09-26 현행화: 현재 구현·검증·남은 과제는 [13번 인수인계 문서](13_현재상태_요구사항_인수인계.md)를 기준으로 한다. 본문의 목표·수용 기준과 날짜별 기록을 구현 완료로 해석하지 않는다.

> A호 설명 시나리오의 입력 수치 기준. 별도 청해호 15단계는 아래 §10을 따른다.
> 사건·인물·자원은 가상. 기상은 실제 조회 또는 명시적인 저장 결과 재생.

## 1. 시연의 중심

사용자가 상황실장에게 정보를 보완하면 요원들의 임무와 공통 상황·대응안이 바뀌는 것을 보여준다. 첫 분석과 추가 정보 반영을 모두 포함한다. 긴급성은 충돌·침수·소재 미확인에서 드러내고, 실제 기상이 악화됐다고 미리 정해두지 않는다.

## 2. 공통 사건과 위치

- 사건 ID 예시: DEMO-001
- 대상: 가상 어선 A호. 실제 선박명·MMSI를 사고와 결부하지 않는다.
- 위치: 시연용 동해 해상 좌표 북위 37.50도, 동경 129.50도.
- 해당 좌표는 기상 호출용 가상 지점이며 ‘동해항 동방 8해리’라는 기존 문구와 동일 위치라고 주장하지 않는다.
- 실제 API 시연은 실행일 현재 기상을 조회한다. 고정 사고시각은 두지 않고 최초 입력 T0, 추가 입력 T1로 구분한다.
- 신고 위치가 텍스트뿐이면 좌표를 확인한다. AI가 임의로 정확한 좌표를 만들어 조회하지 않는다.

## 3. 첫 입력 S0

> 훈련 상황이야. 북위 37.50도, 동경 129.50도에서 어선 A호와 화물선의 충돌 신고가 들어왔어. 최초 신고로는 A호 승선원 5명, 4명은 구조됐다는 보고가 있고 1명은 소재 미확인이야. 선체가 파손됐고 침수 여부는 아직 확인되지 않았어. 필요한 정보를 조사하고 대응안을 정리해줘.

현재 표시는 ‘최초 신고 총원 5명 / 구조 보고 4명 / 소재 미확인 1명’이다. 모두 신고 출처이며 현장 확인이 끝난 사실처럼 표시하지 않는다. ‘소재 미확인’을 임의로 ‘실종 확정’으로 바꾸지 않는다.

## 4. 자료와 추가 입력 S1·S2

### S1: 명부 제출과 불일치

> 승선원 명부를 올렸어. 명부에는 7명이 적혀 있어. 구조 보고 명단은 P01, P02, P03, P04야. 최초 신고의 5명과 다르니 확인해줘. 현장에서 침수가 진행 중이라는 추가 보고도 들어왔어.

첨부용 CSV 내용 기준:

| person_id | display_name |
|---|---|
| P01 | 가상승선원01 |
| P02 | 가상승선원02 |
| P03 | 가상승선원03 |
| P04 | 가상승선원04 |
| P05 | 가상승선원05 |
| P06 | 가상승선원06 |
| P07 | 가상승선원07 |

예상 처리:
- CSV 전체를 읽고 중복 ID와 구조자 ID 포함 여부를 검사한다.
- ‘명부 7명 / 최초 신고 5명 불일치’를 표시한다.
- 명부가 이번 출항의 실제 탑승자 명부인지 사용자에게 묻는다.
- ‘명부 기준 구조 보고 4명, 소재 미확인 3명’이라는 잠정 집계와 출처를 표시한다.
- 실제 승선원 총원을 조용히 7명으로 확정하지 않는다.
- 침수는 ‘현장 추가 보고’로 기록하며 독립 확인 여부를 함께 둔다.

### S2: 사용자 확인

> 이번 출항에 실제 승선한 7명의 명부가 맞아. 최초 신고의 5명은 잘못 전달됐어. P01부터 P04까지 4명 구조 보고는 유지하고, 나머지 3명은 아직 소재를 확인하지 못했어.

예상 처리:
- 사용자 정정 근거로 현재 집계를 총원 7명, 구조 보고 4명, 소재 미확인 3명으로 갱신한다.
- 최초 신고와 S1의 불일치 이력을 보존한다.
- 상황실장이 영향받는 요원에게 보완 지시하고 수정 대응안을 만든다.
- 명부를 다시 올리거나 같은 이벤트가 재처리돼도 인원을 더하지 않는다.

| 단계 | 총원 취급 | 구조 보고 | 소재 미확인 | 확인 상태 |
|---|---|---:|---:|---|
| S0 | 신고상 5명 | 4명 | 1명 | 신고 기준 |
| S1 | 신고 5명과 명부 7명 병기 | 4명 | 명부 기준 3명 | 실제 탑승 확인 대기 |
| S2 | 사용자 정정 7명 | 4명 | 3명 | 정정 근거 기록 |

## 5. 가상 자원표

| 자원 ID | 종류 | 시연상 상태 | 비고 |
|---|---|---|---|
| UNIT-A | 구조지원 함정 | 가용으로 설정 | 실제 기관 자원 아님 |
| UNIT-B | 지원 함정 | 다른 임무로 불가 설정 | 가용 추천 목록에서 제외 |
| TEAM-A | 구조팀 | 가용으로 설정 | 실제 인력 조회 아님 |

초기 시연에서는 임의 ETA를 만들지 않는다. 거리·속력·가용성 검증 없이 도착시간이나 실제 투입 가능성을 단정하지 않는다. 자원지원요원은 이 가상 표를 근거로 지원 검토안을 낸다.

## 6. 실제 실행 순서

| 장면 | 조작과 실행 | 화면 증거 |
|---|---|---|
| 접수 | 채팅에 S0 입력 | 원문·접수 상태·현재 상황 |
| 지시 | 상황실장이 필요한 임무 생성 | 담당 요원·자연어 지시·방향 화살표 |
| 조사 | 정보요원 기상, 수색구조요원 지침, 자원지원요원 로컬 표 | 실제 호출 상태·출처·자료 종류 |
| 종합 | 도착한 보고를 종합하고 검증 | 조치·근거·확인 질문 |
| 불일치 | S1과 명부 제출 | 5명/7명 불일치·개인 ID 대조·질문 |
| 정정 | S2 전송 | 7=4+3, 새 상황 버전 |
| 재지시 | 필요한 요원만 다시 실행 | 변경된 임무와 이전 보고 연결 |
| 수정안 | 검증 의견 반영 | 변경 이유·최신안·이전안 |

수색구조요원의 기초 지침 검색과 정보요원의 기상 조회는 독립 실행할 수 있다. 기상에 의존하는 최종 검토는 실제 결과 도착 후 수행한다.

## 7. 기상 표시 원칙

풍속·풍향·유의파고 등 실제 반환값과 단위를 그대로 연결한다. 조회 성공 여부와 별개로 자료 기준시각, 조회시각, 요청/반환 좌표, 예측자료 여부를 표시한다.

- 기상이 잔잔해도 시나리오는 성립한다. 파고 상승을 연출하지 않는다.
- 조회 실패는 ‘기상 미확인’으로 남기고 나머지 업무를 진행한다.
- 저장 결과 재생은 라이브 사건과 분리한 재생 모드로 표시한다.
- 실제 API 값과 가상의 악천후 값을 하나의 조회 결과처럼 섞지 않는다.
- 특정 파고만으로 항공·구조 가능 여부를 확정하지 않는다.

## 8. 리허설 시간 목표

5분 압축 발표에서는 데모에 2분 40초, 10분 구성에서는 4분 20초를 배정한다. 이는 발표 구성 목표이며 API 응답시간 보장이 아니다. 02의 같은 입력을 사용하고 설명량만 바꾼다.

핵심 큐: S0 접수 → 실제 조사·보고 → S1 첨부 → 불일치 질문 → S2 정정 → 새 계획. 기다리는 동안 이미 도착한 근거를 설명하고, 실패 시 [07_해커톤_운영.md](07_해커톤_운영.md)의 재생 전환 멘트를 쓴다.

## 9. 별도 검증 사례

| 사례 | 기대 결과 |
|---|---|
| P04 중복 행 추가 | 중복 탐지, 단순 행 수를 총원으로 사용하지 않음 |
| 구조자 P99 입력 | 명부에 없는 ID 확인 요청 |
| 기상 요청 실패 | 수치 생성 금지, 미확인 표시 |
| 이전 상황 보고 늦게 도착 | 최신 상황 자동 덮어쓰기 차단 |
| 지침 검색 결과 없음 | 근거 없음과 추가 확인 표시 |
| 신뢰성 시험용 잘못된 초안 | 검증요원이 모순을 찾아 경고·수정 제안 |

검증용 결함 삽입은 테스트임을 표시한다. 라이브 결과에 경고를 강제로 넣지 않는다. 리허설 후 실제 소요시간·성공 여부는 04에 기록한다.


## 10. 현재 앱에 적용하는 방법과 청해호 시험

위 A호 5→7명 예시는 발표 HTML의 설명 시나리오다. 현재 CSV 파서는 `id,rescued` 열을 사용하며 `rescued`는 true/false 또는 1/0이다. 위 person_id/display_name 표는 설계 예시로, 그대로 올리는 파일 형식이 아니다. P01~P04는 true, P05~P07은 false로 구성한다.

UNIT-A 등은 과거 가상 설명용 표다. 현재 출동 지시안의 카탈로그는 [동해 세력 목록](prototype/manuals/donghae_assets.json)을 사용한다. 실제 기상 호출 성공·MCP·벡터 검색·자동 보완 지시는 이 시나리오 표만으로 완료했다고 볼 수 없다.

사용자가 후속 제공한 실사용 수용 시험은 [청해호 화재 15건 원문](prototype/scenarios/cheonghae-fire.md)이다. 총원 7→8명, 구조 0→3→6→8명, 잔류 8→5→2→0명, 기관장 이기란→이기관, 최종 301함 5명·묵호항 3명과 환자 인계를 확인한다. 301함은 이 가상 사건의 자산이고 카탈로그의 306함과 별개다.

[최초 실패 기록](prototype/scenarios/cheonghae-test-results.md)과 [개선 후 검사](prototype/scenarios/cheonghae-improvement-results.md)를 모두 보존한다. 개선 시험은 중간 오류 수정·재실행을 포함하며, 최신 medium 설정·UI 변경 후의 새 무중단 시험은 남아 있다.
