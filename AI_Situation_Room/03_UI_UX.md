## 1. 화면 원칙

사용자는 상황실장과 대화하며 정보를 보완한다. 화면의 중심은 채팅, 요원 소통, 현재 상황이다. 실행 결과는 읽기 쉬운 요약으로 보여주고 근거와 대화 원문은 선택해서 연다. 내부 추론 원문은 표시하지 않는다.

현재 화면은 HTML·CSS·JavaScript다. 화살표는 흐름을 설명하고 실제 지시·보고는 요원 상세 버튼에서 확인한다. Streamlit은 초기 후보였으며 사용하지 않는다.

## 2. 화면 구성

아래 표는 기존 단일 화면의 기본안이다. 최신 운영안은 11 §4–6의 **읽기 전용 상시 상황판 / 담당자 작업 화면**으로 구분하며, 동일 사건·임무·상황 버전을 공유한다. 단순 확대 복제나 화면별 AI 실행으로 만들지 않는다.

| 영역 | 기본 표시 | 사용자 조작 |
|---|---|---|
| 상단 | 사건 ID, 상황 버전, 자료 갱신 상태, 라이브/재생 배지 | 사건 초기화는 별도 확인 동작 |
| 좌측 채팅 약 30% | 사용자와 상황실장 대화, 첨부 접수·분석 상태 | 메시지·정정·파일 제출 |
| 중앙 소통 약 40% | 상황실장과 요원, 지시·보고 화살표, 현재 임무 | 요원·메시지 선택 |
| 우측 상황 약 30% | 출처별 인원·위치·위험·기상·확인 질문 | 근거 상세 열기 |
| 하단 접이식 | 대응안·검증·변경 이력·상황일지 | 이전 버전 비교 |

1920×1080을 우선 검토하고 발표 장비에서 핵심 영역이 읽히는지 확인한다. 화면에 맞추려고 본문을 지나치게 줄이지 않는다. 작은 화면에서는 상세 일지부터 접는다.

세션은 여러 개 생성·전환할 수 있다. 각 세션의 대화·기억·자료·조언은 분리하며, 대형 상황판은 별도 표시 세션을 고정한다. 질문에 대한 가정 기반 시뮬레이션과 조언은 채팅 안에서 표시한다. 상세는 [12_모델배정_시뮬레이션조언_세션기억.md](12_모델배정_시뮬레이션조언_세션기억.md)를 따른다.

## 3. 상황실장 채팅

- 최초 신고 전용 입력과 추가 신고 입력을 별개 시스템처럼 만들지 않는다. 같은 대화에서 이어간다.
- 첨부 상태를 접수 → 분석 중 → 분석 완료/지원하지 않는 형식/확인 필요로 구분한다.
- 분석 중 들어온 새 입력은 접수하고 ‘현재 작업 이후 반영 예정’을 표시한다.
- 상황실장 질문에 대한 사용자의 답변이 어느 불일치를 해소했는지 연결한다.
- 시연 입력 불러오기는 타이핑 보조 기능이며 자동 완료 결과를 만드는 버튼이 아니다.

## 4. 방향과 대화 상세

상황실장 → 요원은 지시, 요원 → 상황실장은 보고다. 실제 메시지 이벤트가 생길 때만 화살표를 강조한다. 상세 패널에는 다음을 보여준다.

| 정보 | 표시 내용 |
|---|---|
| 발신·수신 | 상황실장 / 정보요원 등 한글 명칭 |
| 임무 | 지시문, 임무 ID, 기준 상황 버전 |
| 결과 | 보고 요약, 근거, 불확실성 |
| 시간 | 실제 시작·완료·수신시각 |
| 자료 | 첨부 문서 위치·검색 구절·기상 출처 |
| 현재 유효성 | 최신 상황 기준 / 이전 버전 보고 |

상황실장의 배정 이유, 요원의 작업 단계·개별 보고, 상황실장의 수신·종합·검증과 사용자 최종 보고를 같은 요청으로 연결한다. 대형 화면에는 짧은 공개 설명과 핵심 근거를 표시하고 원문은 담당자 상세에서 연다. 독립 임무의 실제 실행 시간축을 나란히 표시하며, 먼저 도착한 보고는 전체 완료 전에 보여준다. 구체 배치는 11 §5.3–5.4를 따른다.

요원끼리 직접 자유 대화하는 화살표는 만들지 않는다. 상황실장을 통해 필요한 자료를 전달한다.

## 5. 상태 표시

| 내부 상태 | 화면 문구 |
|---|---|
| idle | 대기 |
| assigned | 임무 수신 |
| running | 조사 중 / 검토 중 |
| waiting_dependency | 선행 결과 대기 |
| tool_running | 기상 조회 중 / 문서 검색 중 |
| completed | 보고 완료 |
| failed | 조회 실패 / 분석 실패 |
| stale | 이전 상황 기준 |
| needs_confirmation | 확인 필요 |

재지시는 새 임무로 기록하고 ‘보완 지시’ 표시를 붙인다. 위험도, 실행 상태, 정보 확인 상태는 별개 속성이다. 검증 경고가 있다고 사건 위험도를 자동으로 올리지 않는다.

## 6. 상황판과 변경 표시

시나리오는 [02_데모_시나리오.md](02_데모_시나리오.md)를 따른다.

- S0: ‘신고상 5명 / 구조 보고 4명 / 소재 미확인 1명’.
- S1: ‘최초 신고 5명 ↔ 명부 7명, 실제 탑승 확인 필요’.
- S2: ‘사용자 정정 7명 / 구조 보고 4명 / 소재 미확인 3명’.
- 각 값에 출처·접수시각·확인 상태를 붙인다.
- 이전 값은 이력에 남기고 최신 화면에서는 변경 이유를 바로 열 수 있게 한다.

‘확인된 사실’이라는 단일 배지 대신 신고 기재·문서 기재·사용자 정정·API 예측·AI 추정을 구분한다.

## 7. 기상 카드

풍속(m/s), 풍향(도), 유의파고(m)를 우선 표시한다. 여유가 있으면 시정·기온·수온을 더하되 실제 제공 여부를 확인한다. 개별 항목이 비어 있으면 ‘미제공’으로 표시한다.

필수 보조정보는 출처, 예측/관측 구분, 자료 기준시각, 조회시각, 요청 지점과 반환 지점이다. 기상·해양 API의 시각과 격자가 다르면 이를 보존한다. 기상 카드 제목을 ‘실측 현장기상’으로 고정하지 않는다.

## 8. 대응안·검증

대응안과 정보요구는 각각 핵심 1~2개를 기본 표시하고 추가 내용은 펼쳐본다. 현재 구현은 앞 2개를 표시하며 의미 기반 최우선 선정은 남은 과제다. 각 항목에 근거 ID, 필요한 확인사항, 권고임을 표시한다. 검증요원은 발견한 모순과 수정 요청을 보고하며 실패·미검증 상태를 숨기지 않는다.

새 정보 도착 시 기존 계획에 ‘재검토 필요’를 표시하고, 새 계획을 만들면 이전안과 달라진 이유를 보여준다. 매번 모든 항목이 달라져야 한다고 강제하지 않는다.

## 9. 디자인과 실제 실행의 일치

- 배경 #08111F, 패널 #0F1B2D, 본문 #E5EEF8, 강조 #38BDF8을 후보로 사용한다.
- 대기는 회색, 진행은 청록, 확인 필요는 주황, 실패는 빨강으로 텍스트·아이콘과 병기한다.
- 카드 본문은 핵심 3개 항목, 상세는 접이식으로 둔다.
- 화살표 전환·약한 강조 효과로 흐름을 표현한다.
- 실제 완료를 늦추거나 거짓 실행 상태를 유지하지 않는다.
- 순차 실행이면 순차로 표시한다. 병렬이라는 설명은 실제 실행 구간이 겹칠 때만 쓴다.
- 재생 모드는 화면 상단과 기상·도구 결과에 식별 가능하게 표시한다.
- API 키·원본 예외·프롬프트·개인정보는 화면에 노출하지 않는다.

## 10. 검토 기준

채팅에서 신고·첨부·정정이 이어지는가, 선택한 화살표가 실제 메시지와 일치하는가, 불일치가 묻히지 않는가, 기상 출처·시각이 보이는가, 변경 이유와 이전 계획을 확인할 수 있는가를 실제 화면에서 검토한다. 미구현 화면은 목업으로 표시한다.


## 11. 최신 입력·피드백·관리 동작

- Enter 전송, Shift+Enter 줄바꿈. 한글 조합 중 Enter는 전송하지 않는다.
- 전송 즉시 접수 표시와 글로우, 상단 ‘지시 수행 중’을 보여준다. 이후 저장된 배정·요원 상태·보고·최종 종합을 표시한다.
- 전체 응답을 기다리다 갑자기 결과만 나타나는 경험을 줄인다. 실제 API 단계 이상의 생각·완료율은 만들어 표시하지 않는다.
- 질문은 요원 → 상황실장 → 사용자 순서로 이유와 함께 전달한다. 정보가 거의 없을 때 확인 질문만 하는 경로도 있다.
- 운영 화면에서 모델명·추론 수준을 숨긴다. LIVE/DEMO는 실제 AI 호출 여부를 설명하므로 남긴다.
- 세션 목록 ×는 확인 후 삭제한다. queued/running이 있으면 거절하고, 삭제한 세션이 고정돼 있으면 고정도 해제한다.
- 대형 화면에는 ‘상황실로 돌아가기 ↩’ 링크를 제공한다.

질문 해결 상태·알림 읽음·자동 재지시·최신 브라우저 회귀와 실제 거리 가독성 시험은 미완료다. 제안·질문 각각 2건과 접기만으로 모든 화면에서 요원 카드가 항상 보인다고 보장하지 않는다.

## 2026-09-27 · 외부 보고의 담당자 승인

Link-One·RESAID AI 알림은 수신함의 미처리 건수와 미열람 강조를 표시한다. 보고 수신만으로 AI나 현재 상황판을 갱신하지 않는다. 플로팅 패널에서 출처·사건·보고/수신 시각·원문을 확인하고 **인용하여 전송 / 나중에 / 반영 안 함**을 선택한다. 인용은 검토 요청이며 사실 확정이 아니다. 기존 채팅 전송을 재사용하고 작성 중 초안·가정을 보존한다. 다른 사건의 보고는 연결 사건으로 이동하기 전에는 전송할 수 없다. 상태·이력·키보드·중복 방지 상세는 [수신함 구현](docs/implementation/16-external-inbox.md)을 따른다.
