# 내부 매뉴얼을 추가할 때

> 준비 규칙. 내부 자료는 아직 추가하지 않았으며 아래 경계는 현재 앱에 구현된 기능이 아니다.

## 자료 등록

1. 사용 권한과 공개·내부 구분을 확인하고 원본을 보존한다. 내부 파일은 공개 Git 저장소·발표 ZIP과 분리된 저장 위치를 사용한다.
2. 발행기관, 제목, 문서번호, 버전·시행일, 적용 지역·업무, 원본 해시를 기록한다.
3. 페이지·절 단위 텍스트를 추출하고 조건·예외·금지사항이 본문과 떨어지지 않게 구절을 나눈다. OCR·표 추출 결과는 원본과 대조한다.
4. 각 구절에 `source_id`, `version`, `pdf_pages`, `locator`, `content`, `limitations`, `review_status`, `scope`, `external_use`를 넣는다.
5. 담당 전문가가 번역·해석·국내 적용 범위를 검토한다. 원문 개정판을 추가해도 이전 실행이 참조한 구절은 보존한다.

## 검색과 외부 전송

내부 자료의 기본값은 `scope=internal`, `external_use=deny`다. 이 메타데이터만 적는 것으로 보호가 구현되지는 않는다. 검색 단계의 접근 범위와 모델 호출 직전의 외부 전송 검사를 함께 구현해야 한다.

현재 LIVE는 외부 API 경로다. 내부 매뉴얼을 현재 첨부 기능에 넣으면 해당 세션의 모델 입력으로 전달될 수 있으므로, 로컬 전용 모델 경로와 전송 차단이 준비된 뒤 연결한다. 공개 자료와 내부 자료의 혼합 검색 시에도 내부 내용이 웹 검색 질의·원격 임베딩·오류 로그로 넘어가지 않게 한다.

## 교체와 우선순위

‘국내 문서’라는 이유만으로 항상 우선하거나 ‘최신 날짜’만으로 선택하지 않는다. 관할·적용 업무·유효 판본·승인 수준을 확인한다. 공개 국제 자료와 내부 지침이 충돌하면 충돌을 표시하고 적용할 지침의 판단을 담당자에게 맡긴다.
